# DEC-001：Bake 即定稿（形状对象在 Bake 后只读）

- **状态**：生效（2026-11-11）
- **决策者**：产品负责人
- **关联卡**：DEBT-14（#265）、DEBT-15（#266）、DEBT-16（#267）
- **影响范围**：所有 `DRAW-*` 与后续形状相关任务

## 背景

形状（ShapeDrawing / ShapeModel）在落地时存在两套状态：

1. **形状对象**：参数化配方（几何 + 样式 + 区域点 + 算子链），可重生成音符；
2. **音符**：Bake（✓）后写入文档的最终数据，用户可自由编辑。

在 Bake 之后同时保留这两套可写状态，会产生两个硬冲突：

- **数据冲突**：用户改过形状内音符的长度/属性后，形状回写按"音符值"定位旧音符会失败或误删；
- **协作歧义**：形状对象与音符分别同步时，任一端都可能"重生成"覆盖另一端的结果，无法判定权威。

## 决策

**Bake（✓）是唯一且不可逆的定稿动作。Bake 之后：**

1. **音符是唯一权威**；形状对象降级为**只读配方**（可展示、可追溯来源，不可回写）；
2. **禁止任何"改形状参数 → 重生成音符"的入口**，包括但不限于：
   - 编辑图形（角点/单边/旋转/倾斜/锚点手柄）
   - 填充设置（fill / align / ends / union / apart / borders）
   - 区域着色（AreaSpot 写入）
   - 遮罩参数
   - 对称 / 扶正 / Join / Merge / Slice / Between / CopyAlong 等对形状本体的操作
3. **形状列表（ShapeStore 视图）只读**：可列出名称、来源、参数快照，不提供写入；
4. **Bake 的 undo 只撤销这次 Bake**，不提供 un-bake；
5. **协作只同步音符**，不同步形状对象（或仅作为只读元数据且施加端强制忽略写入）。

## 插入语义（与 DEBT-14 配套）

**不允许"一次性 Bake"**。形状从抽屉进入工程必须经过待确认态：

```
抽屉调整参数 → Insert（生成 pending + 预览音符）→ 用户确认效果
    ├─ 不满意：右键「退回抽屉」→ 回填空格参数 → 重新调整 → 再 Insert
    └─ 满意：✓ → Bake（定稿，形状对象从此只读）
```

## 理由

| 维度 | 说明 |
|---|---|
| 正确性 | 避免重生成覆盖用户已编辑的音符（不可恢复的事故） |
| 协作 | 单一权威源，杜绝"两端各自重生成"的分叉 |
| 可预期 | 用户在 Bake 前能看到最终音符，不需要摸奖 |
| 可维护 | 去掉"形状 ↔ 音符"双向同步，减少一整类状态机 |

## 后果（Consequences）

- 已合并但违反本决策的实现需要在 DEBT-15 中关闭入口（#204 的 baked 手柄、#216 的区域着色回写、#177 的主窗口填充设置等）；
- 旧工程中的形状对象仍可正常读取与展示，只是不可回写；
- 后续所有 `DRAW-*` 卡必须在验收标准中显式声明"符合 DEC-001"，否则不予验收。

## 例外

无。任何"Bake 后仍可编辑形状"的需求，都必须先修订本决策文档并说明如何解决上述两个硬冲突。
