## 1. 交付内容

关于页顶部新增 Lumino logo（复用 `Icon::LogoInApp`，未新建面板/窗口），并实现其彩蛋交互：

- 单击 logo → **原地晃动一次**（0.30s、衰减收正弦、±7px）；
- 连点累计满 **15** 次触发彩蛋序列；相邻点击间隔超过 **2s** 则计数清零重新累计（惰性判定，无定时器）；
- 序列：**快速转动（2 圈 / 0.5s）→ 脱离原位（0.22s ease-out）→ 飞向窗口中轴 Y 以上随机位置 → 匀加速砸向窗口底部（0.55s）→ 落地（播放「钢管落地」音效）→ 渐隐消失（0.35s）**；
- 消失状态**仅进程内保持**：重开设置面板/关于页不再出现，重启 APP 恢复，不写任何配置。

## 3. 关键设计决策

1. **消失标志放进程级 static，而非面板状态**：设置面板是独立窗口，`close_dialog` 会 drop `DialogWindow`，每次打开都 `Host::new_settings_dialog` → 全新 `RootState`（`dialog/src/manager/lifecycle.rs:157`、`ui/src/host/builder.rs:181`）。面板内任何字段都会被重置，承载不了"重开不再出现"。静态标志同时天然满足"不持久化、重启恢复"。
2. **几何全部在像素域解算**：`window::Window` 无尺寸字段、视图层拿不到 viewport，故由 Host 每帧 `set_viewport()` 注入、点击时 `set_click_point()` 注入光标；状态机负责钳制（落点仅取中轴 Y 以上、落地钳在窗口底部内），视图只做"位置 → 布局"无损换算。
3. **悬浮层挂 `view_dialog`（整窗）而非设置内容区**：使悬浮层坐标系与 Host 视口坐标系逐像素一致，消除自有标题栏 30px 的坐标错位；logo 可越过标题栏但仍严格限制在窗口可见区内。
4. **飞行层的点击穿透**：该层只由容器/占位器/Svg 组成，**不套 `mouse_area`**，iced 对未捕获事件的层向下穿透 → 底层设置内容照常可点（对比 `settings_dialog.rs` 的 BPM 遮罩是**故意**用 `mouse_area` 捕获点击的）。
5. **动画状态只在 `update` 推进**：`Root::view(&self)` 只读，故推进点在 `handle_animation_tick`；视图纯函数化，便于测试。
6. **不引入 `rand`**：xorshift64（种子取系统时间）完成一次随机落点采样，避免为单点需求加依赖。

## 4. 落地陷阱（研究阶段未预判）

- **F4｜`SettingsPanel::update` 是穷尽匹配、无 catch-all**：新增 `Event` 变体必须在 `ui-settings/src/panel.rs` 同步补 arm，否则直接编译失败（已补，含说明注释）。
- iced `Svg` 以**旋转后包围盒**参与 `ContentFit::Contain` 缩放：不做补偿时非正方形 logo 在转动中会周期性缩到约 77%。已用 `spin_fit_scale()`（AABB 长边比）补偿，使绘制尺寸恒定；控件放进固定方盒居中，吸收布局盒呼吸。
- 对话框的 `ui_dirty` 只在"消息产生状态变更"或 iced 返回 `State::Updated` 时被置位（`host/event/window/events.rs::update_ui_state`）；事件队列清空后 `render_iced_ui` 会走"仅 present 缓存帧"的早退路径（`host/render/ui.rs:30-39`），**只喂 tick 不置脏 = 动画冻结**。已在 `frame.rs` 动画期显式置脏（先例：同文件播放分支）。

### 8.2 为什么用 MP3 而不是转 WAV

仓库已有 **symphonia 0.5.5**（`lumino-gpu-synth` 引入，`midi-io` 经其传递依赖），其 `default` 特性集**不含 mp3**。故在 `midi-io` 上按同一版本追加 `features = ["mp3"]`：cargo 特性合并后仍是**单份 symphonia 构建**，只多出同族的 `symphonia-bundle-mp3`（MPL-2.0，与既有 symphonia 同源，无新增许可风险）。

对比方案（转 WAV + `hound`）：素材体积 2.7s 立体声 16-bit ≈ **509 KB**（单声道亦 255 KB），是 MP3 的 2~5 倍，且引入「派生资产 + 转换步骤」需长期留档。**MP3 原样内置同时赢了体积与可追溯性**，故采用之。

### 8.3 播放架构（`crates/audio/midi-io/src/ui_sfx.rs`，新增）

- **专属工作线程**：首次 `prewarm`/`play` 时懒启动，独占 cpal 流；UI 线程只发一条命令即返回，**绝不阻塞**；
- **音频回调零锁零分配**：`Arc<Vec<f32>>`（不可变样本）+ `AtomicUsize`（游标）+ `AtomicBool`（playing），回调只做原子读写与样本搬运 —— 沿用仓库「音频回调不持互斥量」的既定纪律；
- **懒开流 + 播完暂停**：初始化后流保持暂停（不留常驻静音回调），每次播放 `play()`、尾部播完 `pause()`；
- **失败静默降级**：无设备 / 设备被独占 / 解码失败 → 只告警一次并放弃，彩蛋其余流程不受影响；
- **设备跟随设置**：复用 `audio_devices::resolve_audio_output_device`，取设置面板当前选择的输出设备（`None` = 系统默认）；设备解析必须在工作线程内完成（`cpal::Device` 不跨线程移动）；
- **预热门控**：彩蛋序列触发瞬间（`AboutLogoClicked` 判定为起飞）即 `prewarm`，序列约 1.27s 后才落地，足以覆盖「解码 + 开流」，落地瞬间只剩一次 `play`。

### 8.4 落地触发链路（消费式一次性信号）

```
Fall 相位触及窗口底部
  └─ enter(Impact) + impact_signal = true            （ui-core 状态机，零音频依赖）
       └─ handle_animation_tick 调 take_impact_signal()（消费式，整段序列只返回一次 true）
            └─ ui_sfx::play_pipe_impact(当前输出设备名)  （no-op 于失败，立即返回）
```

`ui-core` 不引入任何音频依赖：状态机只置位，播放动作由 `lumino-ui` 消费信号完成 —— 保持「UI 基础层不含业务设施」的分层。

### 8.5 抓到的真实缺陷：symphonia 不跳过 MP3 编码器延迟

**现象**：内嵌素材解码后开头带一段近静音（阈值 −60 dBFS），未处理时「落地后不即响」。归因（同素材对比 ffmpeg，ffmpeg 会按 LAME 头跳过延迟、symphonia 不会）：

| 素材 | ffmpeg 侧前导 | symphonia 侧前导 | 差值 = 未跳过的编码器延迟 |
|---|---|---|---|
| 旧 `gang-guan-luo-di.mp3` | 34.8 ms（素材自身 preroll） | 59.7 ms | **24.9 ms ≈ LAME 1105 样本** |
| 新 `钢管 (1).mp3`（当前） | **0 ms**（素材无 preroll） | ≈ 25 ms | 探针实测裁掉 **1102 帧 = 23.0 ms**（1105 − 保留的 4 帧 preroll） |

两次独立素材互相印证同一结论：**差值恒为 ~23 ms 的编码器延迟**，属解码器行为而非素材问题。

**修复**：解码后按能量阈值裁掉前导静音（`trim_leading_silence`，保留 4 帧 ≈0.08 ms 软起振余量，最多扫 200 ms），与素材解耦、换素材无需改代码。

**判据与「测试有没有牙」**：起振判据取「**达到峰值 90% 的时间 ≤ 30 ms**」而非固定窗口的绝对能量——实录冲击常自带 ~20 ms 起振爬升（当前素材峰值落在 25.3 ms），固定 10 ms 窗口对实录过严。该判据经**反证**确认有效：临时摘掉 `trim_leading_silence` 后实测起振 **47.5 ms**（= 23 ms 编码器延迟 + 24 ms 素材爬升），断言如期变红；恢复裁剪后回绿。前提特征化由 `test_embedded_asset_carries_mp3_encoder_delay` 承担。

### 8.6 播放增益

素材峰值 0.0 dBFS（满刻度）、均值 −4.1 dB，而彩蛋属**非预期触发**的隐藏交互，满刻度直接回放易惊吓用户、且下游任何增益都会削波。故施加 `SFX_GAIN = 0.6`（约 −4.4 dB）；**如需完全忠实原文件，把该常量改为 `1.0` 即可**（单点可调）。

> 换素材提示：旧素材均值 −10.5 dB、新素材 −4.1 dB（响度感知更"实"），但峰值同为满刻度，故保持同一增益不变（峰值余量口径一致）。
