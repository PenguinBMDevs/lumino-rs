即缺口收缩 **80.0%**；277 条残余**全部经过逐条判定**，分类见 §5，没有一条是「漏做」。

## 2. 为什么不能沿用旧方案

改造前 i18n 只有**编译期结构体表**（`lumino-extras::i18n` 的 `MainTranslations` 144 字段 +
`SettingsTranslations` 133 字段），适合界面骨架。但长尾文案有三个硬约束让它撑不住：

1. **低层 crate 拿不到 `Language`**。缺口里 102 条在 `crates/network/cloud`、52 条在 `crates/audio/midi-io`、
   103 条在 `crates/editor/gfx`……这些 crate 要么不依赖 `lumino-extras`，要么在生产错误的**后台线程**里，
   把 `Language` 一路透传过去等于重写调用链。
2. **量级不可维护**。再往结构体里加 1200 个字段 + 2400 行翻译表，且每加一条要动 4 个文件、到处解决并行冲突。
3. **大量文案带插值**（`format!("正在上传协作工程 {}（{:.0}%）", …)`），结构体字段只能存整句，拼不出来。

## 3. 方案：`lumino_core::i18n` 运行时文案目录

新增 `crates/core/core/src/i18n.rs` + `i18n/catalog/*.rs`（**在 `lumino-core` 里**，因为它是所有 crate 的公共底座，
加进去不会形成环；`lumino-extras::i18n` 原样转出，UI 侧仍可只 `use lumino_extras::i18n::…`）。

### 3.1 gettext 风格：原文即 key

```rust
use lumino_core::{tr, trf};

text(tr!("云存储提醒"));                                   // 无占位符 → &'static str
text(trf!("连接失败：{e}", e = err));                      // 有占位符 → String
text(trf!("正在上传 {name}（{pct}%）", name = n, pct = 42));
```

- **中文侧不查表**，直接返回原文（零成本）；英文侧查目录，缺失回退中文。
- 模板用 `{名字}` 命名占位（不是 `format!` 的 `{}`/`{:?}`），`render()` 做替换；
  **未提供实参的 `{...}` 原样保留**——所以「支持 {nc} {bpm} 占位符」这类文案用 `tr!` 就不会被吃掉。
- 占位符顺序可跨语言重排，不存在 `format!` 的位置耦合。

### 3.2 语言来源：进程级当前语言

`lumino_core::i18n::set_current_language()`，只有两个同步点：

| 位置 | 时机 |
|---|---|
| `src/runner/inner.rs`（紧随 `storage.config.get()`） | 启动按配置落一次 |
| `crates/editor/ui/src/root/handlers/settings.rs` 的 `LanguageChanged` | 设置面板切语言 |

**这是整件事能一次落地的前提**：调用点不需要手里的 `Language`，后台线程、错误构造点、`Display` impl 都能取词。

### 3.3 目录按「谁的字面量」分域

`i18n/catalog/` 下每个文件导出 `fn lookup(zh: &str) -> Option<&'static str>`，内部是**一个 `match`**：

| 分域 | 负责范围 | 条目 |
|---|---|---:|
| `ui_view` | `crates/editor/ui/src/view/**` | 266 |
| `ui_shell` | `crates/editor/ui/src/{root,toolbar,titlebar,sidebar,right_sidebar,host,mixer_panel}**` | 132 |
| `project_core` | `crates/core/{core,project,message,diagnostics}/**` | 88 |
| `runner_menu` | `src/runner/menu/**` | 80 |
| `audio` | `crates/audio/**` | 79 |
| `cloud_collab` | `crates/network/**` | 71 |
| `error_display` | `#[error(...)]` / 手写 `Display` 的错误短句 | 66 |
| `export` | `crates/tools/{export,extras}/**` | 64 |
| `runner_host` | 其余 `src/**` | 64 |
| `ui_kit` | `crates/editor/{ui-core,ui-editor,ui-settings,editor-state}/**` | 54 |
| `gfx_dialog` | `crates/editor/{gfx,dialog}/**` | 31 |
| — | **合计** | **995** |

用 `match` 而不是排序数组：rustc 对字符串字面量 `match` 会做跳转/哈希分派，
**同域内重复 key 直接是编译错误**（unreachable pattern），不需要人工查重；每个文件一个函数，多域可并行维护。

### 3.4 三道测试门禁（`i18n/catalog.rs::tests`）

| 测试 | 挡什么 |
|---|---|
| `test_every_call_site_key_is_translated` | **扫全工作区**每一个 `tr!` / `trf!` / `i18n::tr(` 的字面量 key，缺英文登记即红 —— 「改了文案忘了翻译」的唯一防线 |
| `test_catalog_placeholders_match` | 同一 key 的中英模板 `{name}` 集合必须完全一致 |
| `test_catalog_keys_unique_across_sections` | 跨域重复登记时**译文必须逐字一致**（否则同一条中文在不同界面显示成不同英文） |
| `test_catalog_english_non_empty` | 英文非空、且不得与中文相同（防「忘了翻」直接复制） |
| `test_call_site_scanner_recognizes_macros` | 扫描器自检（防「扫描器坏了 → 门禁静默放行」） |

### 3.5 数据值 ≠ 显示值：`tr_dyn` + `LocalizedChoice`

有一批取值**同时是界面状态里的规范数据值**，且被 `match` / `==` 当 key 用，例如
`VideoExportDialogState::render_mode == "计数器"`、`counter_font_mode` 在
`root/handlers/dialog/video_export/helpers.rs` 的分派。**把它们翻成英文 = 逻辑静默失效**。

处理方式：数据值保持中文，只在**显示层**取词。

```rust
// crates/editor/ui/src/view/video_export_dialog/localized_choice.rs
#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) struct LocalizedChoice(pub String);   // 内部始终是中文数据值，参与 PartialEq

impl std::fmt::Display for LocalizedChoice {
    fn fmt(&self, f: &mut Formatter<'_>) -> fmt::Result { f.write_str(&tr_dyn(&self.0)) }
}
```

`pick_list` 的菜单文案走 `ToString`、选中匹配走 `PartialEq`（已核对 iced 0.14.2 源码），
正好满足「显示随语言、比较看数据值」；选中回调一律回发 `v.0`。
覆盖：渲染风格、质量、对齐、字体来源（计数器 / 数据曲线）、数据来源共 6 个下拉。

### 3.6 `#[error(...)]`：两段式

thiserror 属性宏里用不了宏，但**允许把任意表达式放进格式参数位置**：

```rust
#[error("{}: {}", lumino_core::i18n::tr("IO 错误"), .0)]
Io(#[from] std::io::Error),
```

已对照 vendored `thiserror-impl-2.0.20/src/{attr,fmt,expand}.rs` 确认 `.0` / `.字段名` 会被重写成
匹配臂局部变量，借用作 `&T: Display` 成立。共改造 72 条 thiserror + 4 条手写 `impl Display`。

> ⚠️ **一处刻意不翻**：`ExportError::Aborted` 的 `#[error("已中止")]`。它的 `Display` 输出被
> 3 处 `error == "已中止"` 直接比较，本地化会让「用户主动中止」被误报成「导出失败」。
> 正确修法是改成错误码/枚举比较，属独立议题；本次只把**展示分支**接了 i18n。

## 5. 277 条残余：逐类交代

`scripts/i18n_audit.py` 把「含中文字符串字面量」分成 8 类，残余全在下面的类里，
**没有一条是「应该翻但漏了」**：

| 类别 | 条数 | 为什么不算缺口 |
|---|---:|---|
| 已经是双语常量池 | 39 | `ui-core/src/button_descs.rs` 的 `DESC_ZH`/`DESC_EN`（29）、`sidebar_event/{group,route}.rs` 的 `match lang`（8）、`ui-settings/pages/audio/types.rs` 的 `match lang`（2）——本来就是双份 |
| 字体族名 / WGSL / 图片资源名 | 26 | `微软雅黑`/`宋体`/`MSYH`、`shaders.rs` 的 WGSL 源码、PNG 调色板名——**是数据，翻了就坏** |
| 规范数据值（`match`/`==` 的 key） | ~55 | 渲染模式 / 质量预设 / 字体来源 / 数据来源 / `AutoScroll` 模式等。**显示层已经双语**（`LocalizedChoice` / `tr_dyn`），存的那份必须保持中文 |
| 内部诊断 / 缓存完整性校验 / 构建期输出 | ~97 | `clipboard.rs` / `domino.rs` / `gfx` 的 cull 资源名 / `cache/io.rs` / `extras/build.rs` / `palette/png.rs` / `midi_manager` 的 `map_err`——唯一消费点是 `tracing::*!`，不上屏 |
| 日志入参 / 对话框日志标签 | ~40 | `src/runner/menu/window/dialog.rs` 的 `open_dialog_traced(_, "视频导出")` → 只进 `tracing::info!("请求打开{label}对话框")` |
| 终端 CLI 进度条 | 11 | `CliProgressBar` 纯 stdout；release 版 `windows_subsystem = "windows"` 下终端不可见 |
| 显式声明不本地化 | 5 | `ui-core/src/state/echo_cave.rs` 的彩蛋文案（模块文档写明不本地化，且打字机整形护栏测试要求首字符非 ASCII） |
| 属性宏 / 协议数据 | 2 | `src/cli.rs` 的 clap `#[command(about = …)]`、协作默认房间名（随协议发给服务端） |

## 6. 复现与回归

```powershell
# 审计（控制台汇总 / 明细 JSON / 分域清单 / markdown 报告）
python scripts/i18n_audit.py
python scripts/i18n_audit.py --json target/i18n-scan/after.json
python scripts/i18n_audit.py --buckets target/i18n-scan/buckets
python scripts/i18n_audit.py --report docs/i18n-audit.md

# 门禁
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p lumino-core i18n      # i18n 目录 + 覆盖率门禁
```

**新增文案的正确姿势**：

1. 代码里写 `tr!("中文原文")` / `trf!("模板 {x}", x = v)`；
2. 在对应分域的 `catalog/<域>.rs` 里加 `"中文原文" => Some("English"),`；
3. 忘了第 2 步 → `cargo test -p lumino-core i18n` 直接红，并打印缺哪几条。

## 7. 已知限制 / 后续

| # | 项 | 说明 |
|---|---|---|
| 1 | `ExportError::Aborted` 的 `"已中止"` | 见 §3.6 的 ⚠️；建议改成错误码比较（独立小任务） |
| 2 | 「关闭」一词多义 | `AutoScrollMode::Off` / `ThreadingOption::None` 的中文原文都是「关闭」，与按钮「关闭」共用一条 key，英文只能是 `Close`（下拉里更贴切的是 `Off`）。要修正需给这两处换独立中文 key |
| 3 | 根目录 `mw_*` / `dsh_*` 之外的 `scripts/` 无 CI 挂钩 | `scripts/i18n_audit.py` 目前靠手动跑；建议并入 CI 作为「缺口数量不回涨」的门槛 |
| 4 | 英文文案未经母语者审校 | 995 条译文按统一术语表产出（取消=Cancel、确定=OK、导出=Export、重置=Reset…），建议产品侧过一遍 |
| 5 | `lumino_core::i18n` 的位置 | 放在 `lumino-core` 是为了让低层 crate 能用；若日后拆分，可整体挪到独立 `lumino-i18n` crate，调用点无需改 |
