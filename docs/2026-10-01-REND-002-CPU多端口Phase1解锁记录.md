# REND-002-CPU 多端口 Phase 1：映射原语与“写死”解锁记录

> 关联 Issue：#86（CPU 子卡）、父卡 #68、GPU 姊妹卡 #87
> 分支：`fix/rend-002-cpu-multi-port`｜日期：2026-10-01
> 阶段口径：**零行为变化**——单端口（port=0）恒等映射；多端口映射代码全部由
> `midi_max_port == 0` 门控，P2 才由渲染入口填入真实端口值。

## 一、已拍板决策

| 项 | 决定 |
|---|---|
| A1 | Phase 1 单独合入 `dev` |
| A2 | `max_port==0` 严格保持 `SynthFormat::Midi`（零行为变化基线） |
| B1 | 上限 16 端口 / 256 通道；`port>15` 折叠到端口 15 块 + 显式告警计数；文档写明 |
| B2 | 先仓库内自动 fixture，再 Night Voyager 人工终验 |
| B3 | `AudioRenderConfig` 加字段（`midi_max_port`），不改 `build_group_config` 签名 |
| C1 | 选 a：`OutputConnection` 参数扩宽 u16；默认实现保持 4bit 折叠（外部设备不投入） |
| C2 | 只要 `max_port` 变化（增/减）就重建实时合成管线；播放中先停播 |
| C3 | 端口 UI 不动，另立 issue |
| D1 | 听感验收由用户自验 |
| D2 | 性能用户自验，不做硬门禁；不得改动 CPU 离线导出算法 |
| D3/#87 | PREF-003 语义改动留给 #67；GPU #87 远期，CPU 跑通后再开工 |

## 二、Phase 1 交付

### 1. 共享映射原语（`lumino-midi-model`）

`crates/audio/midi-model/src/multi_port.rs`（新增）：

- `CHANNELS_PER_PORT = 16`；
- `global_channel(port, ch) -> u16`（`port*16 + ch`，u16 防 16 端口溢出 u8）；
- `split_global_channel(global) -> (port, ch)`（逆映射，往返有测试）；
- `channels_for_max_port(max_port) -> u32`（`(max_port+1)*16`）；
- `MAX_PORTS = 16`（产品上限，B1）；
- `effective_port(port) = port.min(15)`（超限折叠，告警由调用方负责）。

`crates/audio/midi-model/src/document_query.rs`：`MidiDocument::max_port()`。

### 2. “写死”解锁清单（零行为变化）

| 位置 | 原写死 | 解锁方式 | 门控/兼容 |
|---|---|---|---|
| `export/src/audio/config.rs` | `format: SynthFormat::Midi` | 新增 `midi_max_port` 字段 + `synth_format()`（0→Midi，否则 `Custom{channels}`） | 默认 0，路径与历史完全一致 |
| `export/src/audio/event/processor.rs` | `channel.as_int() as u32` | `dispatch_event(&kind, port)`，多端口时 `global_channel(effective_port(port), ch)` | `midi_max_port==0` 走原表达式 |
| `export/src/audio/event_stream.rs` | `MergedEvent` 无端口 | 增 `port: u8`（填补原 padding，体积不变），音符按轨、控制事件按 `ctrl.track` 填 `doc.track_port()` | 单端口全 0，映射恒等 |
| `midi-loader/src/streaming_player.rs` | 流式路径无端口来源 | `scan_tempos` 顺带提取每轨 FF 21，暴露 `track_ports()/track_port()/max_port()` | 纯增量 |
| `midi-io/src/lib.rs` | `OutputConnection` 通道参数 `u8` + 默认实现 `&0x0F` | 参数扩宽 `u16`（全局通道）；默认实现仍折叠低 4 位 | 现有调用方全部 ≤15，行为不变 |
| `midi-io/src/api/xsynth_output.rs` | `ch & 0x0F` 截断 | 直接消费全局通道 `u32::from(ch)` | 当前值 ≤15，行为不变 |
| `midi-io/src/api/lgs.rs` | `ch & 0x0F` | 接口 u16，内部继续 4bit 折叠 | LGS 属 GPU 范围（#87），暂不解锁 |
| `midi-io/src/playback/manager/commands.rs` | 传 `u8` | `u16::from(*channel)` 透传 | 端口 0 语义，数值不变 |

**明确未动**：块式调度器、`TickToTime`、k 路归并、`render_frames`、limiter/sink/codec、
进度回调、GPU 后端与混音台 16 通道语义——CPU 离线导出的算法实现零改动，仅新增
端口维度与通道开通条件（P2 生效）。

### 3. 留给后续阶段

- **P2（导出接线）**：`render_audio` 用 `player.max_port()`、`render_audio_from_document`
  用 `doc.max_port()` 写回 `midi_max_port`；每端口 `p*16+9` 显式
  `SetPercussionMode(true)`（`Custom` 不自动开打击乐）；B1 折叠告警与事件计数；
  仓库内多端口 fixture + 单端口零回归测试。
- **P3（实时接线）**：`XSynthRealtimeConfig.format` 按文档端口数配置 + 文档切换
  重建（含缩小）；播放通道空间 u8→u16；`chase` 状态空间按 `max_port` 伸缩、去掉
  `.min(15)`。

## 三、零行为变化证据

1. 门控单测：`test_synth_format_single_port_stays_midi`（默认 config → `Midi`）；
   多端口 `midi_max_port=6 → Custom{112}`、`127 → Custom{256}`（B1 折叠）；
2. 默认输出折叠单测：`default_output_folds_global_channel_to_low_nibble`
   （`note_on(25,..)` → 线上 `0x99`；`program_change(17,..)` → `0xC1`）；
3. 端口载体单测：`test_track_ports_extracted`（流式 FF 21 提取 + 越界回退）、
   `test_merged_event_carries_track_port` / `test_control_event_carries_track_port`
   （内存事件流按轨携带端口）；
4. 回归命令（全绿）：
   - `cargo test -p lumino-midi-model -p lumino-midi-loader -p lumino-export -p lumino-midi-io`
   - `cargo check --workspace --all-targets`
   - `cargo clippy --workspace --all-targets`、`cargo fmt`。

## 四、风险与关注点

- 超限端口折叠（>15）会与端口 15 块共享通道状态，属 B1 有意降级；P2 必须补
  “显式告警计数”，否则违反“不静默串台”口径；
- 多端口映射激活后，跨端口同 `(channel,key)` 音符不再合流，活跃声部数上升，
  负载形态变化需按 D2 重定基线（PREF-002 文末已预告）；
- `OutputConnection` 扩宽后，非 XSynth 后端（System/KDMAPI/LGS）仍折叠 16 通道，
  多端口独立语义仅对软件合成后端生效（C1 决策 a）。
