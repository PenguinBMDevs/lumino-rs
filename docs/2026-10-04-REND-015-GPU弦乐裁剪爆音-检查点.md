## 二、问题与证据链

**现象**：CC73（Attack Time）+ 高频音符模拟弦乐 → poly 快速上涨 → 触发裁剪 →
弦乐后半段**连续爆音（噼啪）**。**后端：GPU（LGS）实时**（用户确认）。

| 事实 | 位置 |
|---|---|
| GPU 裁剪被裁组统一 `fade_out`，但淡出时长 **1ms** | `gpu-synth/src/synth/engine/pool.rs` fade stage `duration: (sr / 1000).max(1)` |
| fork 在 REND-009 已确认 **1ms 太短**（连续淡出叠加 = "电锯音"），CPU 侧改 **5ms** | `xsynth-nanfix/realtime/src/realtime_synth.rs:1033` 注释；`core/src/voice.rs:65 KILL_FADE_SECS = 0.005` |
| GPU 裁剪**无每块数量上限**，每块把超限组全部裁掉 | `gpu-synth/src/synth/engine/trim.rs::trim_port_key_voices`（由 `trim_voice_pool_for_block` 每块调用） |

## 三、修法（已与用户对齐，双保险）

1. **淡出 5ms**：`pool.rs` fade stage `(sr / 1000)` → `(sr / 200)`（5ms）；
   同步核对 fade 相关常量（`FADE_SLOTS_FRACTION`）与"已淡出一块后 ended"的假设。
2. **每块裁剪限流**：`trim_port_key_voices` 增加**每块最多裁剪组数**（建议 64–128，待定），
   超出部分留待后续块，避免"每块小批量持续抢"的密集淡出叠加。
3. **迟滞（hysteresis）**：仅当超过上限一定幅度（如 `cap + slack` 或 `> cap × 1.25`）才触发裁剪，
   避免边界抖动导致每块都抢。
4. 回归：弦乐素材（CC73+高频）听感 + 频谱；单端口/多端口；**#105 语义不回退**
   （释放优先、无硬杀）。
5. 可选评估：5ms 淡出与 attack 相位叠加的输出电平（必要时加淡出起始电平保护）。
