# GPU 离线导出进度回调与实时倍速显示（2026-09-19）

- 分支：`fix/35-export-progress`（两个提交：#35 进度修复 + 倍速新增功能）
- 关联：#35（EXP-003，LGS/GPU 音频渲染导出无进度指示）

## 1. 背景

#35 的问题是 LGS/GPU 离线导出期间进度条停在 20% 不动。根因：

- `GpuSynth` 渲染循环没有进度回调（只有暂停/中止用的 checkpoint）；
- 导出侧只在固定节点报进度（0.05 初始化 / 0.10 加载音色库 / 0.20 渲染中 → 0.85 写盘），
  渲染阶段没有任何更新。

同时在导出体验上新增需求：进度文案显示"当前导出速度 = 实时播放的多少倍"。
明确不做瞬时值（黑 MIDI 单块耗时波动大，瞬时值会剧烈跳变），采用短窗口平均。

## 2. 实现

### 2.1 引擎进度回调（#35）

`crates/audio/gpu-synth/src/synth/engine.rs`：

- 新增 `RenderProgress`（`Prewarm { done, total }` / `Render { done, total }`）与 `RenderProgressFn`；
- `GpuSynth::set_render_progress(Option<RenderProgressFn>)`：回调必须轻量、不可阻塞；
- 预载（音色重采样/上传）按分片回报；主渲染（内存 `render_midi_inner` 与
  流式 `render_midi_file_to_wav_streaming`）按块回报；
- 与暂停/中止 checkpoint 相互独立，原有语义不变。

### 2.2 导出接线（#35）

`crates/tools/export/src/audio/gpu_backend.rs`：

- 预载映射 0.10→0.20、渲染映射 0.20→0.85；
- 进度每前进 0.1% 才转发一次（黑 MIDI 每块刷新会拖 UI）；
- 文案对齐 CPU 路径：`进度: xx.x% | 帧 n/N | 耗时 x.xs`。

### 2.3 实时倍速显示（新增功能）

`crates/tools/export/src/audio/speed.rs`（新文件）：

- `ExportSpeedMeter`：3 秒滑动窗口平均（音频秒/墙钟秒）；
- 时间跨度 < 0.5s 时返回 `None`——启动阶段不显示夸张数字；
- 异常回退输入不会显示负数。

接入范围：

- GPU：渲染阶段以 `done / sample_rate` 作为音频时长，文案追加 `N.NN× 实时`；
- CPU（流式/文档两条路径）：由 tempo 表计算音频总时长，按 `tick 占比 × 总时长`
  近似音频时长（tempo 变化时略有偏差，已在代码注释说明）。

## 3. 验证

- `cargo fmt --check` 通过；`cargo clippy --all-targets -- -D warnings` 通过；
- `cargo test -p lumino-export`：50 通过（含进度映射 1 个、倍速 3 个单测）；
- `cargo test -p lumino-gpu-synth`：30 通过 + 7 doctests；
- 用户本地实测（debug exe）：
  - CPU、GPU 导出都能看到倍速；
  - 倍速数字随导出稳定变化（非瞬时抖动）；
  - 进度条 / 倍速 / 耗时三者同步刷新。

## 4. #35 验收对照

| 验收标准 | 结果 |
|---|---|
| LGS 导出显示真实进度，样式与 CPU 一致 | 引擎按分片/块回报真实进度；文案与进度条样式对齐 CPU |

| 固定尺寸下显示完整、无裁剪 | 固定宽度面板 + 文字自动换行；本地实测无裁剪 |

## 5. 说明

- 倍速显示为本次**新增功能**，不属于 #35 验收范围；已在 PR 描述中单独标注，
  便于负责人把"修复"与"新功能"分开评审。
- CPU 路径的音频时长是 tick 占比近似，展示用途足够；若后续要求精确，
  可在 `MidiEventProcessor` 内直接回报已渲染样本数。
