## 3. 修改规则

1. **文档只走命令**：`Root` / `Host` 不得直接写 `editor.editor_state.data`；新增编辑行为必须落到
   `Editor` 的 `apply_*` / `commit_*` 方法（现有直接写点视为债，逐条迁移）。
2. **窗口态不回流文档**：布局、焦点、悬浮面板状态不得出现在工程文件或撤销栈。
3. **设备态不进 Root**：wgpu / surface / 线程句柄只能出现在 `Host`；`Root` 需要渲染结果时拿纹理 id。
4. **配置写回单通道**：`Root.settings` 只读，修改经 `Host` 落盘并回填。
5. **跨层调用只经枚举**：UI → 编辑用 `Message` / `EditorAction`；编辑 → UI 用返回值或事件，
   不允许反向持有 `&mut Root`。

## 4. 迁移顺序

1. 用 `rg` 列出 `editor_state.data` 的直接写点，按模块建清单（先只统计，不改）。
2. 每个模块把直接写点替换为 `Editor` 方法；每步跑该模块测试 + 文档撤销回归。
3. 方法数目标：`Editor` 555 → ≤200、`Root` 345 → ≤150、`Host` 271 → ≤150。
   拆分按「状态分组」而不是按调用方：同一组状态的方法集中在同一 `impl` 文件。
4. 每完成一组，在 `scripts/debt_metrics.py` 的周报里记录方法数变化。

## 5. 非目标

- 不重写 `Root`/`Host` 的渲染模型；
- 不把 `Editor` 拆成多个 crate；
- 不在本卡内改 DSP 或导出管线。
