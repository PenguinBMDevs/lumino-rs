# UI-013：重绘定时器 spawn 失败回滚 + 重绘请求收进 Updated 分支（Issue #54）

> 记录日期：2026-09-22 ｜ 分支：`fix/ui-013-tooltip-redraw-timer` ｜ PR：#57

## 背景

UI-011/012（PR #51）引入的 tooltip 延迟重绘机制有两处遗留问题（复审发现，均不致命）：

1. **重绘定时器线程 spawn 失败未回滚**（`crates/editor/ui/src/host.rs::schedule_redraw_at`）：
   `redraw_timer_active.swap(true)` 先于 `thread::Builder::spawn` 执行，且 spawn 返回值被
   `let _ =` 丢弃。若线程创建失败（线程资源耗尽等极端场景），active 已置 true 而线程不存在，
   之后所有 `schedule_redraw_at` 都会在 swap 处提前返回 → tooltip 延迟唤醒永久失效。
2. **重绘请求双路径冗余**：`render/ui.rs`（每帧渲染路径）无条件调用
   `handle_redraw_request`，而 `State::Outdated` 时本就只能传 `Wait` 空操作，
   属结构冗余（每帧多一次锁获取）。

## 改动（2 文件 +17/−13）

- `crates/editor/ui/src/host.rs::schedule_redraw_at`：
  - `spawn` 改用 `Result` 匹配，不再 `let _ =` 丢弃；
  - 线程创建失败时回滚 `redraw_timer_active=false`，保证「活跃标志 ↔ 线程存在性」一致，
    后续调度可重试起线程；
  - 失败路径记 `tracing::warn!` 日志。
- `crates/editor/ui/src/host/render/ui.rs`：
  - `handle_redraw_request` 调用收进 `State::Updated` 分支（`Outdated` 无请求可处理），
    删除每帧无条件调用。
- 行为零变化：tooltip 500ms 延迟唤醒与光标幂等应用语义均未改。
