## 1. 验收定义（Working Backwards：先把"做到什么样算完"钉死）

「所有最边缘的控件都显示出来」不是"内容不裁剪"这种模糊说法，它拆成三条可判定条件：

| # | 条件 | 判定方式 |
|---|---|---|
| 1 | 任何**内容驱动**的控件都不得小于其自然尺寸 | 与宽松基准布局逐节点比对（横向被压窄 / 纵向被压扁） |
| 2 | 任何子节点都不得越出**内容驱动**容器的边界 | 子节点右/下边界不得超过容器（相对坐标） |
| 3 | 流体容器（`Fill`）本身不参与判定 | 它的尺寸是自由参数——**这正是需求说的"流体就流体"** |

两条**合法例外**（不是放水，是语义纠正）：

- **滚动视口**：流体容器装不下内容 = `scrollable` 的视口，内容是能滚出来的，不算"没显示"；
- **换行重排**：文本在窄窗口里折行后宽度变小、**高度变大**——那是重排不是被压。判据取
  「宽度变小 **且** 高度没长」才算被压窄。

> 反例证明这把尺子会红：`ruler_detects_squeeze_caused_by_narrow_window`
> （两个 `Fixed(300)` 并排、窗口只给 300 ⇒ 必须报违规）。没有反向对照的"全绿"没有意义。

## 2. 尺子（已落地）

`crates/editor/ui/src/host/measure/edge.rs`（判据核心）+ `edge/corners`（角落清单）+
`edge/report`（报告与门槛）+ `edge/tests`（反向对照）：

```text
基准：按轴两套宽松布局 ⇒ 逐节点判定流体 / 内容驱动 + 自然尺寸
      宽度轴：(10000, 实测高) 与 (9840, 实测高)   ← 高度固定，滚动条状态与实测一致
      高度轴：(实测宽, 实测高+4000) 与 (…+3840)   ← 宽度固定，同理
实测：按**真实渲染口径**（Limits::new(ZERO, 最终窗口尺寸)，与 UserInterface::build 同源）
      跑一次布局，逐节点比对 ⇒ Squeezed / OutOfBounds
```

**口径同源**：窗口尺寸直接调用生产入口
`host::measure::decide_dialog_window_size`（本轮从 `Host` 方法中抽出），
测试与生产不可能漂移；`dialog_sizes` 另有断言把内联配方与它逐位比对。

**遍历维度是「类型 × 视图状态」**，不是「类型」。只测默认状态漏过两次：

| 漏检 | 后果 |

| 视频导出 `overlay = None`（默认） | 渲染的是「准备中…」占位——真正的四种覆盖层内容一次都没被量过 |

## 4. 剩余处置（按优先级）

### E1（✅ 已完成）resizable 对话框的**最小尺寸**没有约束 —— 用户能把控件压扁

- **现状**（证据）：`with_min_inner_size` 全仓库只有**主窗口**一处
  （`src/runner/window_manager.rs:296`）；对话框构造的窗口属性里没有任何最小尺寸
  （`crates/editor/dialog/src/window.rs` 只设了 `inner_size` / `title` / `visible` /
  `resizable` / `enabled_buttons`），运行时的 `set_min_inner_size` 全仓库 0 命中。
  因此下面 5 类可缩放对话框，用户拖小窗口时系统不会拦，控件会被压到不可用 ——
  尺子在"决策尺寸"下是干净的，但**用户可以把窗口拖到比决策尺寸更小**，
  这是当前真实存在的缺口。
- **受影响**：Settings / ProjectSettings / BatchEdit / RecoverTrack / CloudBrowser
  （`dialog/src/window.rs` 中 `resizable = true` 的 5 类）。
- **已实施**：`window/size.rs::apply_measured_size` 在测量完成后，对**可缩放**窗口调用
  `window.set_min_inner_size(Some(决策尺寸))`；下限按工作区夹取
  （防御：下限不得超过可见区域）。取值逻辑抽成纯函数
  `minimum_inner_size(decided, work_area, resizable)`——不可缩放 / 尺寸非法 / 工作区
  非法时都不设下限（错的 min 会让窗口永远显示不出来）。**未新增任何尺寸数字**。
  API 已核实：`winit-0.30.13/src/window.rs:845`。
- **验证**：6 条单测覆盖（可缩放=决策尺寸 / 不可缩放=None / 夹到工作区 / 无工作区退回 /
  非法决策尺寸拒绝 / 工作区数据损坏退回）；`cargo test -p lumino-dialog` = 26 passed。
- **待人工确认**：实机把 5 类拖到最小 ⇒ 每个控件仍完整可见。

### E4（✅ 已完成）多状态覆盖：设置 10 页 + 其余对话框的关键状态

**验收返工（2026-10-16）**：首轮"17/17 干净"是**假绿**——尺子只跑了设置面板的
**第 0 页**，而真实问题在第 1 / 2 / 5 页。现已覆盖全部 10 页，并据此修完视图。

尺子随之升级（每条都有实测依据，不是为了让结果变绿）：

| 升级 | 为什么 |
|---|---|
| 宽度基准用「宽松宽 × **实测高**」、高度基准用「实测宽 × 宽松高」 | 基准若不带滚动条状态，会出现 14px 假阳性（基准里没有滚动条、实测里有） |
| 换行豁免与**同一宽度布局**的高度比较 | 折行后宽度变小、高度变大是重排，不是被压（否则 300 宽窗口下的长说明句会被误报） |
| 收窄 ≤10% 视为重排 | 交互区块容器 393.5→379.5（−3.6%，尾部文字折行、控件完好）与音频页输入框 80→36（−55%，真被压）必须区分开 |
| 越界豁免追加「**只有一个子节点**」 | 只判「流体容器 + 子节点越界」会把普通 `row` 也当滚动视口：云浏览工具行 216 宽时行宽 184、四个按钮合计逾 300 全被放过（见下方"覆盖自检"） |
| 覆盖自检：每个声明状态必须真的改变布局 | 防止"清单里写着一个角落、实际渲染同一份内容"的假绿（`every_declared_state_actually_changes_the_layout`） |
| 反向对照加一组**真实视图**收窄 | 探针只能证明判据会算；`ruler_sees_squeeze_inside_real_dialog_views` 证明判据看得见产品视图树 |

**实修清单**（`cargo test -p lumino-ui --lib report_edge_visibility -- --ignored` 验证）：

| 位置 | 症状 | 处置 |
|---|---|---|
| `audio/xsynth.rs` 每键最大同音数行 | 输入框 80 → **36** | 标签 180 → `Fill`（让位） |

## 5. 视图作者检查清单（新增对话框时照做）

1. 在 `view/dialog_preferred_size.rs` 里声明尺寸（不声明**编译不过**，这是刻意的）。
   **并且**把新类型加进 `host/measure/dialog_sizes.rs` 的 `ALL_DIALOGS`——
   那个数组长度是手写的常量，漏加**编译器不会提醒**，尺子与尺寸验证会一起静默漏检。
2. 内容全部 `Fixed` 驱动 ⇒ 用 `auto()`（宽度自动）；含 `Fill` 输入框 / 长文本 ⇒ 用
   `boxed(原值)` 或 `at_least_width(下限)`（流体内容的宽度是自由参数，必须给下限）。
3. 含**无界滚动区** ⇒ 必须 `pinned(宽, 高)` 或声明 `max_height`：压缩测量会把滚动区
   外层压成 0（实测设置面板的菜单内容 524 被压成 0）。
4. 不许用 `space().height(Length::Fill)` 把按钮推到底部 —— 测量期它会吃掉整个上限；
   窗口贴合内容后本来就到底了，用固定间距即可。
5. 一行里的**控件不许靠文字让位**：标签/说明文字用 `Length::Fill`（让位），
   控件保持自然宽度或显式 `Fixed`。反例是 `label(Fixed 200) + control(Fixed 200)`
   在 392 宽的内容区里必然压窄控件。
6. 有**多套视图状态**的对话框，在 `host/measure/edge/corners.rs` 的 `dialog_states`
   里登记状态并注入贴近真实的数据（长文件名、多条列表），否则尺子只量开局态。
7. 提交前跑 `cargo test -p lumino-ui --lib measure`：尺子会告诉你有没有控件被压窄/被裁。

## 6. 覆盖自检（防"假绿"的两道闸）

| 闸 | 抓什么 | 用例 |
|---|---|---|
| 状态活性 | 登记了角落但状态字段没生效 / 视图忽略该字段 / 两状态渲染等价 | `every_declared_state_actually_changes_the_layout`：逐节点尺寸指纹必须与默认状态不同 |
| 尺子灵敏度 | 尺子对产品视图树瞎了（只在探针上灵） | `ruler_sees_squeeze_inside_real_dialog_views`：真实视图逐级收窄到 60%/45%/30%，必须至少一档报红 |

第二条闸本轮真的抓到问题：云浏览工具行在 216 宽时四个按钮越界却被"流体容器 = 滚动视口"
豁免，据此把越界豁免收紧为「流体 **且** 只有一个子节点」。

## 7. 仍未覆盖（原理性盲区，保持诚实）

| 盲区 | 为什么没覆盖 |
|---|---|
| **DPI 切换 / 多显示器** | 逻辑尺寸不随 DPI 变化（物理像素才变）⇒ 尺子结论不变，但实际观感需人工确认 |
| 视图**自身**用 Fixed 容器装不下子节点 | iced 在任意窗口下都会夹（基准同样被夹）⇒ 尺子原理上抓不到，只能靠 §5 的视图作者清单 |
| 宽度收窄 ≤10% | 按「正常重排」放行（依据见 E4 表）；更小的收窄不会被拦 |
| 单个子节点的流体容器越界 | 与滚动视口同形（`scrollable` 的布局节点就是"padding 包裹层 + 唯一内容"），无法再细分；这类容器通常是容器自身 `padding` 内缩，越界概率低 |
