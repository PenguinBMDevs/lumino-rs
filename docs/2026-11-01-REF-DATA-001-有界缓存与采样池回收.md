# REF-DATA-001 · 采样内存度量拆分 + 重采样缓存有界 + GPU 采样池回收

> 日期：2026-11-01 ｜ 分支：`ref-data-001` ｜ 状态：**已完成（阶段 0/1/2）**
> 结论：同率零额外字节保持不变；异率/ SFZ 重采样缓存加 **256 MiB 上限 + LRU**；
> 换音源/卸载时 **采样池回落 382 MB → 4 MiB**（Jasmine 3.4 GB 实测）。
> 音频逐位一致：`rich.sf2` filtered/unfiltered 与 Jasmine 的 golden 全部不变。

---

## 1. 背景与剩余范围

`#225` 指出采样数据存在三处驻留：CPU 原生、CPU 重采样缓存、GPU chunk。经
REF-LGS-007/013/014 后：

- CPU 跨实例单份（014）✅
- GPU chunk 减半（007）✅
- 度量（013）🟡 只有 CPU 合计 + GPU，未拆分
- 重采样缓存无上限 ❌
- GPU 采样池只增不减（换音源不回收）❌

本卡补齐后三项。

## 2. 度量拆分（阶段 0）

- `SoundFont::memory_bytes_split() -> (原生, 重采样)`：按 `Arc` 指针去重；
  同率缓存与原生共享同一 `Arc`，重采样计 0。
- `GpuSynth::sample_memory_breakdown() -> (GPU, CPU 合计, 重采样)`。
- `GpuBufferStats.sample_resample_bytes`（新增）+ `hash_render` 输出/JSON。

实测（Jasmine 3.4 GB，同率）：`sample_resample_bytes = 0`，
`sample_cpu_bytes = 7 448 359 248`——与 CPU 合计相等，证明同率没有第二份。

## 3. 重采样缓存有界 + LRU（阶段 1）

`soundfont/types.rs`：

```rust
struct ResampleEntry { data: Arc<[f32]>, last_used: u64 }
struct ResampleCache { map: HashMap<(usize, u32), ResampleEntry>, bytes: u64, tick: u64 }
```

- 上限 `RESAMPLE_CACHE_MAX_BYTES = 256 MiB`（测试用 1 MiB 以触发淘汰）；
- `bytes` **只计非别名条目**：`Arc::ptr_eq(entry, core.samples[id])` 的条目
  与原生共享内存，不计费也不作为淘汰候选；
- 淘汰：`while bytes > cap` 选 `last_used` 最小的非别名条目移除；
- 锁只覆盖 map 查找/插入，重采样计算仍在锁外（rayon 并行路径不受影响）。

测试：

| 用例 | 断言 |
|---|---|
| `same_rate_resample_aliases_native_and_is_free` | 同率缓存 `resample == 0`、原生字节不变 |
| `resample_cache_evicts_when_over_budget` | 3×512 KiB 在 1 MiB 上限下只剩 2 份，`resample <= cap` |

## 4. GPU 采样池回收（阶段 2）

问题：`load_soundfont` 只替换 `self.sf`，`sample_offsets`/`samples_next_offset`
与 chunk 都不重置——换音源时显存只增不减；且新旧音源同 `sample_id` 时旧偏移
会被当成命中（潜在错音，App 目前靠“换音源即重建 synth”规避）。

改动（`synth/engine/init.rs` + `diag.rs`）：

```rust
// load_soundfont（成功解析后、挂新句柄前）
if self.sf.is_some() || !self.sample_offsets.is_empty() {
    self.reset_channel_state();   // 清声部/事件/limiter（旧 offset 作废）
    self.reset_sample_pool();     // 清 sample_offsets、next=0、chunk 重建为 1 MiB
}
self.sf = Some(sf);

// unload_soundfont 同样 reset
```

`reset_sample_pool` 把 4 个 chunk 重建为初始容量（1 MiB），`render_bg_dirty = true`
触发 bind group 重建；旧缓冲由 wgpu 在在途提交完成后回收。

实测（`hash_render --load-twice`，Jasmine 3.4 GB，先预热上传再重载）：

```
gpu_before_reload=382663168  gpu_after_reload=4194304
cpu_before_reload=7448359248 cpu_after_reload=7448359248
resample_before_reload=0     resample_after_reload=0
```

即采样池 **382 MB → 4 MiB**，CPU 因共享核心保持不变；重载仍是缓存命中。

## 5. 行为边界

- 换音源会**清空声部**（旧声部引用旧采样，必须作废）；App 的换音源路径本来就
  重建 `GpuSynth`，此语义只在直接调用 `load_soundfont` 时可见。
- 卸载/重载只回收 GPU 采样池，CPU 侧 `SoundFontCore` 仍由进程级缓存/句柄持有
  （014 的边界：同进程单份，不跨进程）。
- 异率路径仍保留双份，但受 256 MiB 上限约束；真正的“只留引擎率”取舍依赖
  AUD-003（内部渲染率可调），不在本卡。
- 不动混音算法/采样精度/磁盘格式；golden 全部不变。
