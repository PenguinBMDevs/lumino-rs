## 一、本阶段交付

### 1. 实时合成管线的端口布局

- `XSynthOptions` 新增 `midi_max_port: u8`（0 = 单端口）；`XSynth` 单独保存当前布局
  字段（`options` 允许为 `None`，且布局只在重建成功后提交，失败保持旧布局）。
- `init_synth` 按 `rt_format(max_port)` 设置 `XSynthRealtimeConfig.format`：
  0 → `Midi`（16 通道，零行为变化）；否则 `Custom{(min(max_port,15)+1)*16}`。
- `Custom` 不自动开 ch9 打击乐（fork 仅 `Midi` 自动，`realtime_synth.rs:698-702`），
  初始化时对每端口 `p*16+9` 显式下发 `SetPercussionMode(true)`（含 port 0）。
- `Api::set_midi_port_layout(max_port)` 默认 no-op；XSynth 实现为**总是全量**
  `rebuild_with_layout`（文档装载时清上一文档遗留 bank/模态），重建成功才提交布局。

### 2. 文档切换与异步初始化对齐

- `MidiManager` 新增 `desired_midi_max_port`：
  - 装载 MIDI/LMPJ/素材：`import_midi_to_editor` **先导入（内部先
    `reset_playback_manager` 停播、再设置文档）→ 应用端口布局强制重建 →
    创建播放输出连接**，保证重建时已停播且连接指向正确通道空间；
  - 新建/关闭工程：`close.rs` 应用 0，释放多端口通道空间；
  - 导出自动重载：`export.rs` 按文档布局强制重建。
- XSynth 异步初始化中/System 回退：desired 暂存，`finish_xsynth_init` 成功后
  再 `set_midi_port_layout` 对齐，之后才重连播放输出。

### 3. 播放通道空间与运行时打击乐模态（方案 B）

- `NoteEvent / EventType / MidiMessage.channel` u8 → **u16 全局通道**
  （`port*16+channel`；单端口恒等）。
- 生产侧映射：
  - 当前轨队列（`core.rs`）用 `doc.track_port(current_track)`；
  - 其他轨音符与控制事件（`state.rs`）用 `track_idx` / `ctrl_event.track` 的端口；
  - 当前轨 automation/PC（UI `playback.rs`）按当前轨端口映射；
    `track_midi_events`（HashMap<轨道, _>）按键逐轨映射。
- 共享纯逻辑 `multi_port::PercussionTracker`（midi-model，导出/实时共用）：
  - 默认模态 = `channel % 16 == 9`（每端口 ch9）；
  - GS `CC0=120/121`、XG `CC0=127 && CC32=0` → 打击乐；
    明确非鼓 Bank Select → 旋律；仅 CC32 不单独判定（避免误关默认 ch9）；
  - 切换消息必须**先于**触发 CC 下发（fork 在打击乐模态下忽略 CC0）。
- 实时链路：`state.rs` 在其他轨控制事件与当前轨 automation 中推导模态，
  产生 `MidiMessage::PercussionMode`；`flush` 转为
  `OutputConnection::set_percussion_mode`（默认 no-op，XSynth 发 Channel Config）。
- chase：状态空间按文档 `max_port` 伸缩、删除 `.min(15)`；`PercussionTracker`
  一并追齐，`emit_chase` 先发模态再发 Bank/PC；seek/回绕用追齐快照同步引擎
  内部跟踪器（否则后续 Bank Select 会与旧状态比较而漏切换）。
- 导出链路：`MidiEventProcessor` 用同一 tracker，在 CC0/CC32 触发时先发
  `SetPercussionMode` 再转发 CC（导出/实时同源语义）。
- 暂停清理：新增 `OutputConnection::release_all_dampers`（默认 16 通道 CC64；
  XSynth override 为 `AllChannels`），修复多端口下端口 >0 的踏板持音残留。

### 4. 明确未改动

- 混音台/电平表仍为 16 通道语义（端口 0；`track.channel` 颗粒度）；
- 外部 MIDI 设备仍 4bit 折叠（C1=a）；LGS/GPU 留 #87；
- SysEx（GS/XG Reset、Rhythm Part 重指派）见独立卡 #90（REND-007）。

## 五、接口演进 B：能力扩展 trait（基础 trait 冻结）

> 背景：REND-002 的三项能力（端口布局 / 打击乐模态 / 踏板释放）原先直接加在
> `Api`、`OutputConnection` 上，违反 agent 模板「禁止新增 pub fn 到已有 trait」。
> 评估 A（维持）/ B（能力 trait）/ C（A+治理）后，选定 **B 落地 + 保留治理纪律**。

### 落地形态（Rust 关键点：单对象所有权不变）

- `Api`、`OutputConnection` **冻结**：本次新增的 3 个方法全部移出；
- 新增扩展 trait（`crates/audio/midi-io/src/lib.rs`）：
  - `pub trait SynthControl: Api`：`set_midi_port_layout` 默认 no-op（不支持多端口）；
  - `pub trait PlaybackOutput: OutputConnection`：`set_percussion_mode`（默认 no-op）、
    `release_all_dampers`（默认 16 线通道 CC64）；
- 存储直接持有扩展 trait 对象（**无 upcast/downcast、无 Arc/Mutex 拆句柄**）：
  `Box<dyn SynthControl>` / `Box<dyn PlaybackOutput>`；supertrait 的基础方法照常可调；
- 每个后端**显式声明**加入（空 impl = 接受默认行为）：System / KDMAPI / LGS 空 impl，
  XSynth 覆写三项能力；测试替身（RawRecorder / CountingOutput / MockOutput / RecordingOutput）
  同样补空 impl；
- 构造/流转签名同步：`new_api*` → `Box<dyn SynthControl>`、`Api::open_output` →
  `Box<dyn PlaybackOutput>`、`PlaybackManager::set_midi_output` / UI `set_playback_midi_output`
  / `pending_midi_output` / `flush_midi_messages` / `handle_audio_action` 等。

### 配套纪律（C 的治理条款）

1. 能力方法只进扩展 trait；基础 trait 仅在「所有后端都必须具备」的语义下变更；
2. 每个扩展 trait 方法必须带默认实现 + 默认/覆写行为测试；
3. 后端支持矩阵以「是否实现扩展 trait」显式可见，新增后端需显式选择；
4. #88（每端口音色库）、#87（LGS 多端口）的新能力直接落扩展 trait，不再动基础 trait。

## 七、验收发现：导出限幅器失效 + NaN 污染（独立缺陷）

**现象**：用户导出 `Parallel Universe Shifter Clean.mid`（8 端口，CPU/48k/每键32/限幅开）
→ WAV 峰值异常、3:02–3:09 与 6:45 后出现“被切断”。

**诊断证据**（对用户 WAV `PUS CPU MTPT Test.wav` 扫描）：
- float32 立体声 48k、433.18s；**t=2s 起有限峰值即 1.5–3.9**（此时无 NaN）→ 限幅器从未真正生效；
- **82.522s 出现首个 NaN**，之后 envelope 被污染 → `target_gain` 恒 1.0 → **限幅器永久旁路**，峰值飙至 9–30；
- NaN 每段恰为**一个 256 帧渲染块**（≈5.33ms），共 220 段，集中于 1:22、2:34、**3:02–3:09**、**6:45–6:53**（与用户听感完全吻合）；
- NaN 区间的 MIDI 特征：海量 `CC6/CC38`（Data Entry）洪峰 + 全幅 `Pitch Bend 0..16383`，无 ch9/鼓 bank 事件；
- 该文件 `(port,ch,key)` 复音峰值仅 4（无偷声）、`PercussionTracker` 切换 0 次 → 排除多端口映射与打击乐模态。

**根因 A（已修）**：`limiter.rs`
1. 包络 attack(10ms) 与 lookahead(10ms) 相等 → 每个瞬态原样通过；
2. 非有限输入令 envelope 永久 NaN → `target_gain` 走 else 恒 1.0 → 限幅器永久失效。
修复：`ATTACK_MS=0`（瞬时包络，coeff 语义修正为 0.0）、非有限样本按静音处理、
envelope/gain 有限性防御、`non_finite_samples` 计数并在导出结束告警；新增 3 例回归
（密集瞬态 ≤1.0、NaN 后仍限幅、既有用例保持）。

**根因 B（未修，待归因）**：NaN 源在上游（fork voice/控制 DSP 或音色库），
需要用户音色库复现后定位；修复 A 只能保证 WAV 有限且限幅器不再被旁路，
上游 NaN 仍会产生 5ms 级 dropout（听感“切断”）。

### B-1 复现与隔离实验（用户音色库 TWGMD Remake VI.sf2）

- 78–95s 切片复现 **19890 个非有限样本**；去掉 **PB / CC6+38 / RPN 选择**任意一项 →
  **归零**（三者组合为必要条件）；
- 端口二分：ports 0–1 复现（19890），ports 2–7 在该时段无内容；port 0 单独 8638，
  ch0–7 与 ch8–15 两半均有 → 触发面跨多通道；
- 微切片（`carry` 模式：窗口前 CC/PC/PB 折叠到 t=0 + 窗口内平移）成功把复现压到
  **0.22s 窗口**；探针现场：首个非有限样本前 27ms 内为
  **PB 斜坡（+0.1..+0.2，非极值）+ CC38 DataEntry 递增（16→32→…→112）+ 5ms 级同 tick
  Off/On 重触发**；
- 最小 MIDI（灵敏度 127 / 粗调 / PB 极值 / 长音）**不能复现** → 需要“具体事件序列 +
  音色库采样区”组合；
- 结论：触发源在 **fork 合成侧**（RPN/PB 控制状态 × 采样器时间推进 × 具体音色区），
  Lumino 侧事件域值与应用顺序无异常证据（PB 均为小幅、CC38 为正常 DataEntry）。
