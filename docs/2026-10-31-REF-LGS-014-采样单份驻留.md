# REF-LGS-014 · SF2 采样数据单份驻留（进程级缓存 + 共享核心）

> 日期：2026-10-31 ｜ 分支：`ref-lgs` ｜ 状态：**已完成**
> 目标：同进程内同一 SF2 的采样数据只有一份；端口布局重建不再重复解析。
> 实测：`F2 Jasmine 2.1.sf2`（3.4 GB）二次加载 **7 876 ms → 0.094 ms**；
> CPU 采样统计 7.86 GB → **7.45 GB**（去掉同率缓存的重复计数）；
> 音频逐位一致（Jasmine 96000 帧 `4ae7ab3cb5ceb311` 不变）。

---

## 1. 现状

`docs/2026-10-17-数据源冗余审计.md:255-257,341` 记录：LGS 播放 + 同时导出时，
进程内出现两份同 SF2 的完整采样数据。本轮复核确认两条路径都走
`GpuSynth::load_soundfont` → `SoundFont::load`：

- 实时：`Lgs::build_synth`（`crates/audio/midi-io/src/api/lgs/init.rs:34`）；
- 导出：`crates/tools/export/src/audio/gpu_backend/render.rs:93,241`；
- 端口布局重建：`Lgs::rebuild_with_options` → `build_synth`（`api/lgs.rs:395`）。

`SoundFont::load` 每次都完整解析 SF2（`xsynth-soundfonts` 在加载时把每份采样
重采样到引擎率），因此每个 `GpuSynth` 各持一份：rich.sf2 约 17 MB 无所谓，
`F2 Jasmine 2.1` 是 **7.45 GB/份**，两份即 15 GB 量级。

## 2. 设计

### 2.1 拆出不可变核心

```
SoundFontCore   // 采样/zone/矩阵/去重表，解析后不再变化
SoundFont       // { core: Arc<SoundFontCore> }
```

- `SoundFontCore` 还持有**重采样缓存**（`Mutex<HashMap<(id, rate), Arc<[f32]>>>`）：
  缓存按核心共享，同一文件的两个引擎不会各缓存一份；锁只在 map 读写时持有，
  **不包住重采样计算**（rayon 并行路径不被串行化）。
- `SoundFont` 只持 `Arc`，克隆/共享零拷贝。

### 2.2 进程级缓存（`soundfont/cache.rs`）

键：**（路径, mtime, 大小, 采样率, bank, preset, use_effects）**，值是
`Weak<SoundFontCore>`：

| 性质 | 说明 |
|---|---|
| 命中条件 | 同文件 + 同参数 + 至少一个引擎还持有该核心 |
| 失效 | 路径/mtime/大小任一变化自然 miss（改文件后不会读到旧解析） |
| 生命周期 | `Weak` —— 所有持有者释放后核心回收，缓存**不会**把 GB 级音源长期钉住 |
| 并发 | `OnceLock<Mutex<...>>`；命中/插入是短临界区，解析在锁外 |
| SFZ | 跳过缓存：采样分散在多个文件，单个 `.sfz` 的 mtime 不能代表内容 |

`GpuSynth::load_soundfont` 改用 `SoundFont::load_cached`，并**先取新句柄再替换
`self.sf`**：替换前旧核心仍存活，所以端口重建（先建新、成功才停旧）必命中。

## 3. 实测

### 3.1 二次加载耗时（`hash_render --load-twice`）

| 音源 | 首次解析 | 命中缓存 | 倍数 |
|---|---|---|---|
| `rich.sf2`（30 KB） | 2.4 ms | 0.088 ms | 27× |
| `F2 Jasmine 2.1.sf2`（3.4 GB，3168 采样 / 18.6 亿帧） | **7 876.0 ms** | **0.094 ms** | **≈8.4 万×** |

命中时只做一次 `Arc::clone` + 元数据读取，不触碰采样数据。

### 3.2 内存

| 指标 | 改前 | 改后 |
|---|---|---|
| 同一 SF2 的采样份数（CPU） | 2（播放 + 导出 / 重建前后） | **1**（`Arc::ptr_eq` 单测保证） |
| `sample_cpu_bytes`（Jasmine，单引擎） | 7 859 213 048 | **7 448 359 248** |

> 后者不是数据变少，而是统计口径修正：`memory_bytes()` 现在按 `Arc` 指针去重。
> 目标率 == 原生率时（SF2 加载即引擎率），重采样缓存项与原生采样是**同一个
> Arc**，旧实现把它算了两遍（约 411 MB 的虚高）。

### 3.3 逐位一致

- `F2 Jasmine` 96000 帧 @512：`4ae7ab3cb5ceb311`（改前/改后一致）；
- `rich.sf2` 512 filtered / unfiltered：`ea209e1f675b4d03` / `ba3ce4034c7b5298`；
- 114 单测 + 7 doctest 全过。

## 5. 绑定与边界

- **进程内**单份：跨进程（播放器 + 独立导出进程）不共享，这是本卡明确边界；
- 缓存键不做 `canonicalize`（避免额外 IO 与 Windows 长路径差异），同一路径
  字符串 + mtime + size 足以识别内容；
- 不改 `SoundFont` 磁盘格式、不改 zone/矩阵语义；
- `SoundFont::load` 保留为**不走缓存**的构造（测试/工具需要全新解析时使用）。
