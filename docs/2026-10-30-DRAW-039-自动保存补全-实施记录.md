# DRAW-039 自动保存补全 + 崩溃日志可见化 · 实施记录

## 背景

`#223` 要求把现有“重连失败兜底保存”扩展为完整的保命链：

- 周期自动保存（仅 dirty、后台、默认关闭）
- 手动保存/云上传期间不并发写
- `autosave-backup`、损坏文件改名保留、backup 回退
- 每次会话只提示一次
- 崩溃日志用户可见、归档
- 保留 REND-019 的 `auto_save_before_failed`

旧 PR `#239` 实现了配置/定时器骨架，但恢复后会把 autosave 当普通源文件加载，
且组包仍在 UI 线程；已关闭不合并，本实现以其骨架为参考重做。

## 关键决策

| 项目 | 决策 |
|---|---|
| 默认状态 | 关闭；间隔默认 5 分钟，收敛 1..=120 |
| 文件位置 | `config_dir()/autosave/autosave.lmpj` 与 `autosave-backup.lmpj` |
| 组包线程 | 主线程只克隆 `MidiDocument`/形状/元数据，`LuminoProject` 组包与写盘进 `spawn_blocking` |
| 恢复语义 | 恢复后清空 `current_midi_source`/云端来源，标记 `modified = true`，Ctrl+S 走另存为 |
| 损坏处理 | 改名 `autosave-lost-*`，永不覆盖；主文件失败退用 backup |
| 用户拒绝 | 改名 `autosave-declined-*` 保留，不删除 |
| 正常退出 | 统一在 `Runner::exiting` 清理 main + backup；在飞任务延迟删除 |
| 崩溃日志 | 扫描 `logs/crash_*.log`，归档 `logs/crash-archive/`，每会话提示一次 |
| 启动提示 | 延迟到首帧后，避免原生模态框阻塞导致白屏 |
| Windows 原生按钮 | 嵌入 Common Controls v6 manifest，`TaskDialogIndirect` 可用；崩溃日志按钮为“打开目录/关闭窗口” |

## 实现落点

- `src/runner/menu/file/save/lmpj.rs`
  - `LmpjSnapshot`、快照化组包、后台保存
  - `spawn_autosave_lmpj`（独立 autosave 写入）
- `src/runner/menu/file/auto_save.rs`
  - `autosave_due`、timer、串行守卫、退出清理、失败提示
- `src/runner/menu/file/auto_save/recovery.rs`
  - 启动恢复、backup/lost/declined、恢复为未保存工程
- `src/runner/inner/crash_log.rs`
  - 启动提示、归档、打开目录、首帧后调度
- `src/logging.rs`
  - crash 扫描/归档、打开目录、panic backtrace
- `src/runner/inner.rs` / `lifecycle/*`
  - 状态字段、`ControlFlow` 唤醒、退出清理
- 配置/设置/i18n
  - `autosave_enabled`、`autosave_interval_mins`、编辑页 section、持久化

## 验收 smoke

已通过：

- 默认关闭、间隔持久化
- dirty 后周期写盘；clean 后不写
- 杀进程后恢复；恢复后 Ctrl+S 弹另存为
- 主文件损坏 → `lost` + backup 回退
- main/backup 双损坏 → 不卡死，状态栏/日志告知
- 用户拒绝 → `declined`
- 正常退出（菜单/X）清理 main + backup
- 崩溃日志提示一次、归档、打开目录、二次启动不提示

## 已知边界 / 后续

- 恢复提示仍使用平台原生 `MessageDialog`，尚未接应用内 `AutosaveRecover`。
- 崩溃日志提示在极端回退后端下仍可能只有普通按钮；已通过 Common Controls v6 manifest 改善。
- 工程持续 dirty 时每周期重写同内容，后续可按编辑代次优化。
- `#240` 的 1 亿音符 UI 同步段证据仍需单独性能 smoke。
