## 一、问题1：LGS 无声色库静默降级 → 可见提示

| 触发 | 提示内容（写入底部状态栏，取走即清） |
|---|---|
| `start_lgs_async_init` 音色库路径为空 | `LGS 未生效：未设置音色库，当前使用 System 后端；请在设置中加载音色库（.sf2/.sfz）` |
| 音色库文件不存在 | `LGS 未生效：音色库文件不存在（{path}），当前使用 System 后端` |
| `finish_lgs_init` 初始化失败 | `LGS 初始化失败，已回退 System 后端：{原因}` |
| 初始化线程异常断开 | `LGS 初始化线程异常断开，已回退 System 后端` |

机制：`MidiManager.pending_backend_notice`（取走即清）→ `RunnerInner::handle_midi_reinit`
每帧取走并 `set_status_message` 到状态栏。异步失败不再静默留在 System 后端。

## 二、问题2：换设备重初始化后输出创建失败（永久无声）

现场机制（issue 原文）：启动时策略3把 System 主输出交给播放引擎；reinit 时 `self.output`
已为 `None`，但播放引擎仍持有旧 WinMM 连接未释放 → `init_system_output` 重开同端口失败 →
`create_additional_output` 三策略连锁失败 →「无法创建任何输出连接，播放将无声」。

修复链路（四层）：

1. **重初始化前同步释放旧连接**（根因修复）：
   新增 `PlaybackManager::clear_midi_output_sync`——`ClearMidiOutputAck` 命令在旧连接 drop
   **之后**回执，500ms 超时；经 `Root::clear_midi_output_sync` /
   `Host::clear_playback_midi_output_sync` 暴露；`handle_midi_reinit` 在 `reinit_if_needed`
   前调用。此前异步 clear 存在「命令尚未处理就重开端口」的竞争窗口，必然失败。
2. **端口逐个回退**：新增纯函数 `ordered_output_ids`（指定设备优先 + 其余按枚举顺序；
   指定设备不存在时纯枚举）；`init_system_output`、策略1、`try_open_new_api` 全部改为
   逐端口尝试，不再"只试一个就放弃"。
3. **异步初始化失败也重连播放输出**：`check_async_init_complete` 返回
   `AsyncInitOutcome::{Pending, Switched, Failed}`（原 `bool` 语义）；`Failed` 分支同样
   `reconnect_playback_output`——此前失败分支不重连，播放引擎停留在已被释放的旧连接上。
4. **自愈重试 + 可见失败**：`MidiOutputRetry`（3 次 × 750ms，启动创建失败即武装；
   运行期重连失败武装）；重试成功清除失败提示；次数耗尽后状态栏提示
   「MIDI 播放输出创建失败，播放将无声：请检查输出设备（设置 → MIDI）后重试」。
