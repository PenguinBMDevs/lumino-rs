## 3. 实施中新发现的坑（调研阶段未预见）

### 3.1 真剪贴板测试会互相抢剪贴板 → 必须进程内互斥

初版把「开关开」「开关关」拆成两个 `#[test]`，默认并行执行（同一进程多线程），
两者交替 `EmptyClipboard` 导致**互相把对方写入的格式清掉**，表现为随机失败：

```
test_copy_writes_domino_format_only_when_enabled ... FAILED
test_paste_ignores_domino_format_when_disabled ... FAILED   # left: 8, right: 16
```

处置：`static CLIPBOARD_LOCK: Mutex<()>` 串行化本模块用例（锁毒化用
`unwrap_or_else(|e| e.into_inner())` 兜底，避免一个失败连锁毒化其余用例）。

### 3.2 系统剪贴板是**进程外**共享资源 → 单次读取会假阴性

`OpenClipboard` 可能被其他进程短暂占用，此时 `get_clipboard_domino()` 返回 `None`。
若负向断言（"关闭时不得写 Domino"）只读一次，会因读失败而**假通过**；正向断言只读一次
则会**假失败**（实测 3 次并行运行中出现 1 次，报 `left: None`）。

处置（本卡采用的统一语义）：

- **正向**断言：退避重试直到观测成立（`copy_until` / `copy_until_both`，5 次）；
- **负向**断言：先重试到正向前置成立（证明确实写进去了），再**多次探测**该格式始终不存在
  （`absent_over_probes`），并额外断言剪贴板仍可读（排除"读不到所以没粘贴"的假阴性）。

### 3.3 「绿色测试」不等于「有效测试」→ 蓝军自攻击

把两处闸门临时还原成改动前的无条件行为（`build_clipboard_domino()` / 去掉
`domino_clipboard_enabled &&`），测试必须变红，实测结果：

```
test_copy_writes_domino_format_only_when_enabled ... FAILED
  panicked: 关闭时不得写入 Domino(MidiPortalSequence) 格式
test_paste_ignores_domino_format_when_disabled ... FAILED
  assertion `left == right` failed: 关闭时不得消费 MidiPortalSequence（不应粘贴出新音符）
```

证明两条闸门测试具备真实检出能力（非空断言），随后已还原并复测全绿。

## 4. 与调研结论的偏差

| 项 | 调研建议 | 实施取舍 | 理由 |
|---|---|---|---|
| 闸门形态 | 「复制闸门块内先判开关」 | 抽为 `Editor::domino_payload()`（`#[cfg(windows)]`），复制点调用 | 「关闭时不进入编码」从"看代码"变成**可单测契约**；也避免以后有人在别处复制粘贴这段判断而漏掉闸门 |
| Editor 侧读取 | 「加读取方法」 | 同时加 `pub fn domino_clipboard_enabled()` 只读 getter | 无 getter 时 `ui` crate 的 `apply_settings` 测试只能断言 settings 镜像，**恰好覆盖不到 P0-2 的漏跳风险** |
| 非 Windows 字段处置 | 建议 `#[cfg_attr(not(windows), allow(dead_code))]` | **未加**该属性 | 字段被跨平台 getter 读取 + getter 是 lib 的 `pub` API，本就不会触发 `dead_code`；不加属性比加更干净 |
| 非 Windows 机器验证手段 | — | 交叉 check 受限于无 Linux/macOS C 工具链（`zstd-sys` 需 `cc`）。改用**翻转 cfg 到宿主机**真编译非 Windows 分支 | 设置页已用此法验证 `clippy -D warnings` 全绿；`ui-editor` 的结构性论证见 §5 |
