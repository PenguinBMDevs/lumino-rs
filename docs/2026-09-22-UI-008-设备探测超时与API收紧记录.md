> 记录日期：2026-09-22 ｜ 分支：`fix/ui-008-probe-timeout` ｜ PR：待创建

## 一、背景：无限冻结的事故路径

修复前，启动门控在**主线程**（`resumed()`，窗口创建之前）直接同步调用廉价探测：

```rust
// ❌ 修复前（src/runner/lifecycle/device_gate.rs）
let cache_hit = device_check_policy::cache_hit(
    within_ttl,
    device_check::debug_force_fail_requested(),
    cached_passed,
    cached_fp.as_deref(),
    device_check::probe_adapter_fingerprints,   // ← 主线程同步执行，无超时、无日志
);
```

`probe_adapter_fingerprints()` 内部新建 wgpu `Instance` 并 `enumerate_adapters()`
（加载 Vulkan ICD、dlopen 各驱动）。这条路径是**绝大多数老用户每次启动的默认路径**
（TTL 7 天内 + 上次通过 + 指纹一致即命中）；驱动异常挂起时进程冻结在窗口创建之前，
用户表现为「双击无反应」。开销更大的全量检测反而有独立线程 + 3 秒超时。

## 二、修复原则

| 原则 | 落实 |
|---|---|
| 超时语义 | **探测超时 ≠ 检测失败**：只说明缓存无法快速校验 → 按 cache miss 落回全量检测，不弹警告窗、不误判失败 |
| 线程模型 | 复用既有「独立线程 + `mpsc::recv_timeout`」模式，不引入 async 运行时 |
| 防回归 | 原始探测函数**收紧为 `pub(crate)`**，外部唯一入口是带超时的包装（编译期保证） |
| 最坏耗时 | 探测超时 1.5s + 全量超时 3s ≈ 4.5s，取代「无限冻结」 |

## 三、API 收紧（编译期防回归）

`probe_adapter_fingerprints` 由 `pub` 收紧为 `pub(crate)`，并从 `device_check.rs`
与 `lib.rs` 的再导出中移除；crate 外只能调用带超时的包装：

```rust
// ❌ 禁止（收紧前唯一可用的写法；同 crate 内新增调用点同样禁止）
//    调用线程（主线程/事件循环）被阻塞，驱动挂起即无限冻结
let fingerprints = probe_adapter_fingerprints();

// ✅ 正确（crate 外唯一入口；内部独立线程 + 超时）
match probe_adapter_fingerprints_with_timeout(PROBE_TIMEOUT) {
    Some(fingerprints) => { /* 与缓存指纹比对 */ }
    None => { /* 超时/异常：按 cache miss 落回全量检测 */ }
}
```

原始函数保留了长文档说明事故与约束（`crates/editor/gfx/src/device_check/check.rs`），
包含上述 ❌/✅ 示例，避免后来者「看见 pub(crate) 就顺手直呼」。

## 四、超时包装实现

```rust
// crates/editor/gfx/src/device_check/check.rs
pub fn probe_adapter_fingerprints_with_timeout(timeout: Duration) -> Option<Vec<String>> {
    probe_with_timeout(timeout, probe_adapter_fingerprints)
}

pub(crate) fn probe_with_timeout<F>(timeout: Duration, probe: F) -> Option<Vec<String>>
where
    F: FnOnce() -> Vec<String> + Send + 'static,
{
    tracing::info!("GPU 适配器廉价探测：开始（超时 {timeout:?}）");
    let started = Instant::now();

    let (tx, rx) = std::sync::mpsc::channel();
    let spawn_result = std::thread::Builder::new()
        .name("lumino-gpu-probe".to_string())
        .spawn(move || {
            let fingerprints = probe();
            let _ = tx.send(fingerprints);
        });
    if let Err(e) = spawn_result {
        tracing::warn!("GPU 适配器廉价探测：探测线程创建失败（{e}），按 cache miss 落回全量检测");
        return None;
    }

    match rx.recv_timeout(timeout) {
        Ok(fingerprints) => Some(fingerprints),          // 完成（含耗时日志）
        Err(RecvTimeoutError::Timeout) => None,           // 超时 → cache miss
        Err(RecvTimeoutError::Disconnected) => None,      // 线程 panic → cache miss
    }
}
```

- 超时常量：`device_check::PROBE_TIMEOUT = 1.5s`（与 `DEFAULT_TIMEOUT = 3s` 并列，含语义文档）；
- 日志口径：开始（info）/ 完成含耗时与适配器数（info）/ 超时或异常落回（warn）。

## 五、`device_gate` 接入

```rust
// src/runner/lifecycle/device_gate.rs
// 廉价探测也走独立线程 + 超时；超时/异常折算为空指纹列表 → cache miss → 全量检测
let cache_hit = device_check_policy::cache_hit(
    within_ttl,
    device_check::debug_force_fail_requested(),
    cached_passed,
    cached_fp.as_deref(),
    || {
        device_check::probe_adapter_fingerprints_with_timeout(device_check::PROBE_TIMEOUT)
            .unwrap_or_default()
    },
);
...
} else {
    tracing::info!("GPU 适配器指纹缓存未命中，执行全量兼容性检测");
    device_check::run_check_with_timeout(device_check::DEFAULT_TIMEOUT)
};
```

策略层（`device_check_policy::cache_hit`，纯函数）**零改动**：
TTL 过期 / 上次未通过 / 强制失败时依旧**连探测都不发起**（既有 17 个单测语义保持）。

## 六、调试开关与手动验收

仅 debug 构建生效：

```bat
:: 1) 先正常启动一次（让指纹缓存写入 passed、TTL 内），退出
:: 2) 模拟探测挂起后再次启动
set LUMINO_DEBUG_PROBE_HANG=1
target\debug\lumino-rs.exe
```

预期日志序列（stderr 与日志文件均可见）：

```
WARN LUMINO_DEBUG_PROBE_HANG 已设置：模拟适配器探测挂起 30 秒
INFO GPU 适配器廉价探测：开始（超时 1.5s）
WARN GPU 适配器廉价探测：超时（1500ms / 上限 1.5s），按 cache miss 落回全量检测
INFO GPU 适配器指纹缓存未命中，执行全量兼容性检测
```

预期时间线：窗口在 **≈4.5 秒内出现**（1.5s 探测超时 + 最多 3s 全量检测），
**不再出现「双击无反应」**；且不弹 GPU 警告窗（探测超时不是检测失败）。

## 八、风险与遗留

- **已知遗留（Issue 注明本卡不处理）**：超时后探测线程 detach、无法终止（Rust 无线程取消）；
  极端情况下可能与随后的全量检测线程并存创建 wgpu `Instance`，另开任务评估。
- 最坏启动阻塞 4.5s（探测 1.5s + 全量 3s），Issue 设计表已认可；正常机器探测仅几十 ms。
- `gfx::device_check` 公共面整体审计（哪些真需要 `pub`）记为后续任务，不在本卡做。
