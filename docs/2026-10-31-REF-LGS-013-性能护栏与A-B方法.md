# REF-LGS-013 性能护栏与 A/B 方法（2026-10-31）

> 目标：把"环境漂移会吞噬 3–5% 结论"的教训固化成**可复现、机器可读、可回归**的基准流程。
> 机器：RTX 5080 / 驱动 610.88 / 9950X3D / 48 kHz（与 `2026-10-31-LGS-5080基线.md` 同一环境）。
> 原则：**先有度量，再做优化**；没有对照表的性能改动不进入验收。

---

## 1. 交付物

| 组件 | 路径 | 作用 |
|---|---|---|
| 单次基准 | `crates/audio/gpu-synth/examples/hash_render.rs` | 渲染 N 帧，输出倍实时、分相（配合 `LUMINO_PROFILE=1`）、峰值声部、声部帧率、FNV 哈希、JSON |
| 夹具生成器 | `scripts/gen_lgs_bench_fixtures.py` | 标准库 SMF 写入器；生成 16/32/64/128/256 通道（1/2/4/8/16 端口）持续音夹具 + 2 端口门控夹具 + manifest |
| A/B 工具 | `scripts/lgs_ab.py` | 双二进制、交替顺序、≥6 对、中位、GPU 时钟/温度、JSON/CSV、哈希一致性、负向门控 |
| 用例清单 | `scripts/lgs_bench_cases.json` | 8 个用例（sustained 512/2048 + 多端口 5 档 + 256ch@2048）+ 门控参数 |

夹具落在 `test-file/bench/`（`.gitignore` 排除，**不入库**）；manifest 记录尺寸与 SHA256，A/B 工具在开跑前自动校验。

### 1.1 `hash_render` 用法

```bash
cargo build --release -p lumino-gpu-synth --example hash_render

# 默认 16 通道（历史行为）
./target/release/examples/hash_render.exe <midi> <sf2> <frames> <block>

# 按文件端口上界推导通道数（1 端口→16，16 端口→256）
./target/release/examples/hash_render.exe <midi> <sf2> 1440000 512 --auto-channels

# 显式通道 + 机器可读输出
./target/release/examples/hash_render.exe <midi> <sf2> 1440000 512 \
  --channels 64 --json out.json --raw out.f32 --wav out.wav

# 覆盖实时预热路径（warm_voice_templates）
./target/release/examples/hash_render.exe <midi> <sf2> 192000 512 --channels 16 --prewarm
```

输出新增字段：

```
midi_max_port=1 midi_channels=32 auto_channels=true
voices_peak=256 voice_frames=227147776 voice_frames_per_s=137608299
sample_gpu_bytes=4194304 sample_cpu_bytes=157168
```

- `voices_peak`：实际提交给 GPU 的声部数峰值；
- `voice_frames = Σ(每块提交声部数 × 块帧数)`；除以墙钟 = **声部帧率**，跨块长/通道数可比；
- `sample_gpu_bytes` / `sample_cpu_bytes`：采样显存（chunk 分配）/ CPU 采样数据字节；
- `--json` 写 `midi_channels`（配置值）与 `out_channels`（输出声道，立体声=2），两者不混用。

### 1.2 `lgs_ab.py` 用法

```bash
# 保存 baseline / after 两个可执行文件后：
python scripts/lgs_ab.py \
  --baseline test-file/bench/hash_render_baseline.exe \
  --after    test-file/bench/hash_render_after.exe \
  --label 003-negative --pairs 6 --gate-pct 2 \
  --json test-file/bench/ab_003.json \
  --csv  test-file/bench/ab_003.csv
```

纪律（工具强制）：

1. **不重新编译**：baseline/after 都是独立 exe；
2. **顺序交替**：奇数对 baseline 先跑，偶数对 after 先跑；
3. **默认 6 对**，取中位；同时输出每对 delta 与符号一致性；
4. 每次运行前抓 `nvidia-smi` 的 SM/显存时钟、温度、功耗；无 nvidia-smi 时降级；
5. 先做每侧 1 次**丢弃预热**（驱动管线缓存/页缓存）；
6. 默认要求两侧样本哈希**逐位一致**；`--allow-hash-diff` 仅用于 007 量化等有界差异场景；
7. 退出码：`--fail-on none|regression|any`（本地默认 `none`，CI 建议 `any`）。

> 旧版 `hash_render` 不支持 `--json`；工具通过二进制内参数串探测能力并退回 stdout 解析，
> 因此 003 时期保存的双二进制仍可直接参与 A/B。

## 2. 指标口径

| 指标 | 来源 | 说明 |
|---|---|---|
| 倍实时 | `hash_render` | `音频秒数 / 渲染墙钟`；不含 `GpuSynth::new`、SF2 解析、预热 |
| 分相 | `LUMINO_PROFILE=1` 的 `[profile] block` 行 | `apply/collect/sync/upload/samples/mix/dispatch/readback/total`，工具取中位 |
| 峰值声部 | `GpuSynth::peak_voice_count` | dispatch 后累加，统计口径 = 实际提交声部数 |
| 声部帧率 | `GpuSynth::voice_frames / wall` | 与块长无关的工作量指标，适合横向比较 |
| 输出哈希 | `hash_render` | FNV-1a 64，覆盖所有样本 `to_bits()` 小端字节 |

> 注意：分相中位数与墙钟中位数可能不同向（例如 003 的 after 在 512 档 `collect` 更低但墙钟更慢）。
> **判定只看墙钟中位数**；分相只用于定位，不作为通过/失败的依据。

## 4. 5080 多端口基线（30 s 音频，block 512）

`hash_render --auto-channels`，2 次取较低值（差异 <2%）：

| 端口 | 通道 | 墙钟 | 倍实时 | 峰值声部 | 声部帧率（M/s） | FNV |
|---:|---:|---:|---:|---:|---:|---|
| 1 | 16 | 1.744 s | 17.20× | 128 | 65.1 | `cf24e3f5bcb6016d` |
| 2 | 32 | 1.878 s | 15.98× | 256 | 117.1 | `f35a61c7c23a7c22` |
| 4 | 64 | 2.083 s | 14.41× | 505 | 214.7 | `4e1deaba5f8d3165` |
| 8 | 128 | 2.410 s | 12.45× | 744 | 259.6 | `35c11caa48f01704` |
| 16 | 256 | 2.807 s | 10.69× | 872 | 222.2 | `006f09825e48d474` |

256ch @2048：1.563 s = **19.22×**，峰值 872，FNV `601789a4f77d1123`。

> 观察：通道数从 16 → 256 时倍实时下降约 1.6×（17.2 → 10.7），主要来自 mix 的通道循环与
> `MixParams` 体积；块长从 512 → 2048 在同一素材上回升到 19.2×，说明**每块固定/宿主成本**仍是
> 小块的主要成本。这两条正是 001/002/010 的靶点。

## 5. 负向门控验收（已纳入 `lgs_ab.py`）

`gate_2p_32ch.mid`（端口 0 低音区 / 端口 1 高音区）：

| 检查 | 结果 |
|---|---|
| 窄配置（16ch）渲染成功 | ✅ rc=0 |
| 宽配置（32ch）渲染成功 | ✅ rc=0 |
| 自动配置（`--auto-channels`）渲染成功 | ✅ rc=0 |
| 窄 ≠ 宽（端口 1 确实被丢弃） | ✅ `f0c27bce11404040` vs `afce309c2dc5e77d` |
| 自动 == 宽（推导正确） | ✅ `afce309c2dc5e77d` |
| 窄配置告警 `event dropped` | ✅ 每进程一次 |
| 窄配置 + `--prewarm` 不 panic | ✅ rc=0 |
| 所有运行无 panic | ✅ |

**修复的缺陷**：`warm_voice_templates` 按 `channel*128*128` 索引 `seen`，但未做通道门控；
当多端口 MIDI 喂给窄通道引擎时（如 16ch 配置 + 端口 1 事件），会**越界 panic**。
现在渲染路径（`handle_event`）、预热路径（`prewarm_midi_file` / `warm_voice_templates`）
共用 `midi::port::channel_in_range`，并有单测
`channel_gate_rejects_events_outside_the_configured_space`。

### 7.1 采样内存口径（`GMEM` / `CMEM`）

| 指标 | 含义 | 来源 |
|---|---|---|
| `sample_gpu_bytes`（GMEM） | `samples_chunks` 的**实际分配字节**（已加载/重采样的采样数据） | `GpuSynth::sample_memory_bytes()` |
| `sample_cpu_bytes`（CMEM） | 原生样本 + 重采样缓存（f32 采样本体，不含 zone/矩阵/哈希表） | `SoundFont::memory_bytes()` |

- 发布频率：渲染线程每 25 块发布一次（约 0.25–0.5 s），避免每块遍历样本表；
- 状态栏仅在 `GMEM`/`CMEM` 非 0 时显示（未加载音源不占位）；
- **GMEM 是 `samples_chunks` 的分配容量**（每 chunk 最小 4 MiB），不是"当前活跃采样字节"；
  CMEM 是采样数据本身；两者趋势用于发现回归，不做精确 allocator 计量；
- `PlaybackControl::ResetStats` 只清累计量（欠载/丢弃），不清采样内存（瞬时量）；
- 单测：`test_snapshot_exports_sample_memory`、`memory_bytes_counts_native_and_resampled_cache`
  （后者在缺失 `rich.sf2` 时跳过，CI 不会红）。

## 8. 运行前置与已知边界

| 项 | 说明 |
|---|---|
| CI runner | `.github/workflows/lgs-bench.yml` 需要自托管 runner，标签 `self-hosted, windows, x64, gpu`，并安装 Rust stable / Python 3 / nvidia-smi；没有该 runner 时 workflow 只是不可调度，不影响现有 CI |
| 夹具存储 | 仍不入库（`test-file/` gitignored）；CI 每次用 `gen_lgs_bench_fixtures.py` 确定性重建，靠 manifest 校验 |
| 007 量化 | `lgs_ab.py --allow-hash-diff` 预留；默认逐位一致 |
| CMEM 精度 | 只统计 f32 采样数据（原生 + 重采样缓存），不含元数据；趋势展示用，不是精确 allocator 计量 |
| 采样内存刷新 | 每 25 块一次；音源刚加载后的前 ~0.5 s 可能显示 0，属预期 |
| PR 模板 | 新增 `.github/pull_request_template.md`；DRAW 并行工作流的下一次 PR 会看到该模板 |

## 9. 复现命令汇总

```bash
# 1) 生成夹具（gitignored）
python scripts/gen_lgs_bench_fixtures.py

# 2) 构建候选二进制并保存
cargo build --release -p lumino-gpu-synth --example hash_render
cp target/release/examples/hash_render.exe test-file/bench/hash_render_after.exe
# baseline 用改动前的构建产物（或上一次发布的 exe）

# 3) A/B（精测用 2%，CI 用 10%）
python scripts/lgs_ab.py \
  --baseline test-file/bench/hash_render_baseline.exe \
  --after    test-file/bench/hash_render_after.exe \
  --pairs 6 --gate-pct 2 --label my-card \
  --json test-file/bench/ab_my_card.json --csv test-file/bench/ab_my_card.csv

# 4) 单次分相
LUMINO_PROFILE=1 ./target/release/examples/hash_render.exe \
  test-file/bench/sustained65536.mid test-file/bench/rich.sf2 480000 512
```
