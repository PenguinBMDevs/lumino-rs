# UI-001：统一 UI 字体绑定 + 自定义字体文件加载 + CJK 平滑回退（Issue #23）

> 记录日期：2026-09-26 ｜ 分支：`feat/ui-001-font-binding` ｜ PR：#78

## 背景

UI 字体此前已支持在设置面板指定（系统字体名 / 自定义字体文件路径），但存在三类问题：

1. **组件级字体硬编码**：11 处对话框标题硬编码 `Font::with_name("Microsoft YaHei")`、
   2 处轨道列表 `..Default::default()` 重置 family、21 处 canvas 绘制用
   `Font::DEFAULT`/`Text::default()` → 界面字体不统一；
2. **自定义字体文件路径是空实现**（只打日志不加载）；
3. **无 CJK 覆盖的字体出现豆腐块**（Issue 报告）。

## 探针实测（先证据后方案）

`examples/font_probe.rs`（不入库）用 iced 字体系统直接整形 `"中文测试 ABC 123"`：

| 场景 | 结果 |
|---|---|
| 无 CJK 字体（Arial）+ `Shaping::Advanced`（iced 段落对非 ASCII 的实际路径） | ✅ 逐字形回退：中文→系统 CJK 字体（Windows 实测 Microsoft YaHei UI）、西文/数字→Arial、无 `.notdef` |
| 无 CJK 字体 + `Shaping::Basic`（canvas 旧站点） | ✗ 中文 4 个 `.notdef` 豆腐块（Basic 不启用回退） |
| 有 CJK 字体（YaHei）+ Advanced | ✅ 全部来自该字体、不触发回退 |
| 字体名解析不到 + Advanced | ✅ 回退、不崩溃 |
| 字体文件路径加载（simsun.ttc） | ✅ `load_font(bytes)` 注册成功（db +2 faces），`Font::with_name("SimSun")` 可用 |

结论：CJK 回退走 **cosmic-text `Advanced` 逐字形回退**（按平台字体链匹配，不写死字体名）；
canvas 的 Basic 站点必须显式切 Advanced 才能启用回退。

## 改动（32 文件）

| 层 | 内容 |
|---|---|
| 全局入口 | 新增 `lumino-ui-core::font`：`resolve_font`（path 有效优先 → name → 默认；失败仅告警降级）、`init`（启动解析一次）、`ui_font`/`ui_font_bold` |
| 自定义字体文件 | 实装：读文件 → 注册进 iced 字体库 → 按文件家族名引用；失败回退下一优先级，不崩溃 |
| 统一绑定 | 34 处字体覆盖 → 全走全局入口（11 硬编码 + 2 轨道列表 + 21 canvas） |

| CJK 回退 | `grid/remote_cursors.rs`（协作者用户名）Basic→Advanced |
| 字体工具 | `note-core`：`resolve_font_family`/`font_supports_cjk`/`pick_cjk_font`（按系统字体链匹配） |
| 设置面板 | 系统字体与文件路径**二选一互斥**（选下拉清路径 / 浏览文件清字体名）+ 提示文案（中英） |
| 交互修复 | 字体变更**不再重建窗口**（消除主窗口闪烁；iced 0.14 `Renderer.default_font` 私有不可热更）+ 设置面板显式提示「字体修改将在重启程序后生效」 |

## 已知边界

- 字体切换**需重启程序生效**（iced 渲染器默认字体不可热更；实时切换需重建 Renderer/Engine，
  成本高且仍会闪，未纳入本卡）
- 配置默认字体 `Microsoft YaHei` 为 Windows 专属（macOS/Linux 解析不到时按平台回退链渲染，
  不崩溃）——跨平台默认值可另开小卡
