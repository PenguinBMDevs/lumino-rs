## 3. 性能实证（本卡核心动机）

### 3.1 方法

临时 example（`crates/audio/midi-model/examples/domino_probe_tmp.rs`，**已删除**，复现见 §8）：
自定义 `#[global_allocator]` 精确统计**堆峰值增量**（比 RSS 干净，不含加载态噪声），对同规模音符分别跑：

- A：`encode_domino_clipboard(notes)`（Domino 格式，zlib level 1）——即开关开启时每次都付的钱；
- B：`encode_clipboard(...)`（Lumino 私有紧凑二进制，即现网主格式）——开关关闭后的真实代价。

音符分布：相邻 tick 间隔 1（密集排布），时值 1..480，力度 100，通道 0..15。`--release`（opt-level=3）3 次采样 + `--profile fast-release` 1 次。

### 3.2 实测数据

| 选中数 N | 原始体（40 B/音符） | **Domino 耗时** | **Domino 堆峰值增量** | Domino 输出 | Lumino 耗时 | Lumino 堆峰值增量 | 耗时倍数 |
|---|---|---|---|---|---|---|---|
| 200,000（= 保护闸上限） | 7.6 MB | 62 – 148 ms | **26.2 MB** | 1.3 MB | 2.3 – 6.7 ms | 1.5 MB | ~22–40× |
| 500,000 | 19.1 MB | 246 – 352 ms | **64.4 MB** | 3.2 MB | 7.2 – 9.1 ms | 3.8 MB | ~34–47× |
| 1,000,000 | 38.1 MB | 662 – 933 ms | **128.8 MB** | 6.3 MB | 21.6 – 55.7 ms | 7.6 MB | ~14–37× |
| 2,000,000 | 76.3 MB | 1011 – 1761 ms | **257.5 MB** | 12.6 MB | 30.7 – 61.8 ms | 15.3 MB | ~27–36× |

堆峰值数字**四次运行完全一致**（确定性）；耗时受本机负载影响波动较大（同档位最大差 2.4×），故给区间。

### 3.3 从数据得出的三条硬结论

1. **堆代价 ≈ 3.4 × 原始体，是 Lumino 二进制路径的 ~17 倍**（1M 音符：128.8 MB vs 7.6 MB）。这个 3.4× 是**实现引入的、可避免的**冗余（见 §4-P2-1）。
2. **每一次复制（Ctrl+C）在 200k 选中档位上额外阻塞 UI 线程 60–150 ms**，基线只有 2.3–6.7 ms。这是用户能明确感知的卡顿（>50 ms 即体感掉帧），也是本卡最站得住的动机。
3. **「秒级成本」在生产上不可达**：>200k 时保护闸先返回 `None`，编码根本不发生（`encode.rs:170-177`）。秒级只在「手动绕过保护闸」时出现。

### 3.4 对卡面量化描述的三处修正

| 卡面原文 | 实测 | 修正建议 |
|---|---|---|
| 「百万级选中约 100MB 原始体」 | 1M = **38.1 MB**；100 MB 原始体对应 **~2.6M** 音符 | 改为「每音符 40 B，100 万选中 ≈ 38 MB 原始体、**129 MB 堆峰值**」 |
| 「复制路径的秒级成本」 | 保护闸内实测 **60–150 ms**（200k）；秒级只出现在保护闸之外 | 改为「**每次复制额外阻塞 UI 线程 60–150 ms、堆峰值 26 MB**」 |
| 「现网日志特征：不再出现 Domino 编码相关 **debug** 记录」 | `encode.rs:171-175` 的 debug 日志**只在超限时**打印；开关关闭时"不打印"与"超限跳过"无法区分，**不构成有效信号** | 用 `clipboard.rs:120-125` 的 **info** 记录做信号：开启且成功 = 「已复制 N 字节 Lumino 二进制 + M 字节 Domino 二进制」；关闭/跳过 = 退化为 `:130-134` 的「已复制 N 字节二进制音符」 |

同时 `domino.rs:113-115` 的代码注释「level 6 对百万级音符的 ~100MB 原始体需 1s+」同样失真（实际是 level 1、38 MB、0.66–0.93 s），建议一并订正，否则后来人继续被误导。

## 4. 必须修正的缺陷清单

### 🔴 P0-1：非 Windows 会因 `dead_code` 直接卡 CI

`.github/workflows/ci.yml:33` 矩阵 `[ubuntu-latest, windows-latest, macos-latest]`，`:78` 门禁为
`cargo clippy --workspace --all-targets -- -D warnings`。

若把 `domino_clipboard_enabled` 加为 `Editor` 字段、且**只在 `#[cfg(windows)]` 块内读取**，则非 Windows 编译时该字段「written but never read」→ `dead_code` → `-D warnings` 变红（ubuntu/macos 两个 job）。**这是硬失败，不是理论风险。**

本仓已有 4 处同款解法先例，逐一照抄即可零告警：

- `crates/editor/ui-editor/src/clipboard.rs:33`（`ARRANGEMENT_BINARY_MARK`）
- `crates/editor/ui-editor/src/clipboard/paste_interop.rs:67`
- `crates/editor/ui-editor/src/arrangement_ops/clipboard/encode.rs:19`
- `crates/editor/ui-editor/src/arrangement_ops/clipboard/paste.rs:101`

统一写法：`#[cfg_attr(not(windows), allow(dead_code))]` 挂在字段/方法上。
（卡面 step 6 只说了「闸门判断放在 cfg 块内」，**没说字段侧的 dead_code 处置**。）

### 🔴 P0-2：step 3 的先例引用错误 → 照卡实施会「设置改了不生效」

- `crates/editor/ui-editor/Cargo.toml:45-69` **不依赖** `lumino-ui-settings`；`Editor`（`lib.rs:128-258`）**没有任何 settings / UiConfig 字段**（全 crate grep `ui_config|UiConfig|settings` 零命中）。
- 所以 `build_clipboard_domino` / `try_paste_from_domino` 所在的 `impl Editor` **读不到 `SettingsPanel`**。
- `intercept_notification_enabled()` 之所以可行，是因为它在 `Root` 上、消费点也在 `Root`（`editor_action.rs:29`），属于「Root 层决策」，不是「Editor 内部决策」。

**正确先例**是同类「UiConfig bool → Editor 内部字段」通路 `playback_key_colors_enabled`，共 **5 跳**：

| 跳 | 位置 | Domino 开关对应物 |
|---|---|---|
| a. 字段 | `crates/editor/ui-editor/src/lib.rs:151` | `pub(crate) domino_clipboard_enabled: bool` + `#[cfg_attr(not(windows), allow(dead_code))]` |
| b. 初始化 | `crates/editor/ui-editor/src/impls/editor_impl.rs:39` | `domino_clipboard_enabled: false`（**与 UiConfig 默认值一致**） |
| c. setter | `crates/editor/ui-editor/src/impls/config.rs:122-129` | `pub fn set_domino_clipboard_enabled(&mut self, bool)` |
| d. 启动注入 | `crates/editor/ui/src/root.rs:201-202` | `root.editor.set_domino_clipboard_enabled(ui_config.domino_clipboard_enabled);` |
| e. 变更同步 | `crates/editor/ui/src/root/editor_ops/dialog/settings.rs:81-89`（在 `sync_editor_interaction_settings` 内，由 `apply_settings`:17 调用） | 同款 `old != new` 判断 + `tracing::info!` + 调 setter |
| f. 持久化 | `src/runner/inner/persist.rs:271`（写回）+ `:67`（`other_changed` 判定） | `config.ui.domino_clipboard_enabled = new.compat.domino_clipboard_enabled;` + 加入 `other_changed` |

卡面只提了「panel 状态镜像 + UiConfig 持久化」，**漏掉 b / d / e 三跳**。缺 e 的后果：用户在设置里勾选后，**本次会话内复制闸门不生效**，要重启才生效——且 `save_storage` 仍会把新值写进 config，形成「界面显示已开启、行为还是旧值」的错位，极难排查。

### 🟠 P1-1：非 Windows「置灰」无法用 `with_setting_tooltip_inline_action` 实现

`iced_widget::Checkbox` **没有 `.disabled()` 方法**（0.14.2 `src/checkbox.rs` 全 API 无此项）。禁用语义只能靠 `on_toggle` 为空：`on_toggle_maybe(Option<F>)`（`checkbox.rs:167-172`），`on_toggle.is_none()` ⇒ `Status::Disabled`（`:344-348`）。

更关键：卡面「硬要求」的 `with_setting_tooltip_inline_action`（`components/tooltip.rs:54-66`）内部挂了 `.on_press(on_press)`——**非 Windows 下点击标签文字仍会切换开关，置灰被绕过**。非 Windows 必须换用同文件的无动作变体 `with_setting_tooltip_inline`（`tooltip.rs:40-49`）。

建议写法（与本仓 `#[cfg]`-on-statement 惯用法一致）：

```rust
let cb = checkbox(compat.domino_clipboard_enabled);
#[cfg(windows)]
let cb = cb.on_toggle(|enabled| Message::Settings(Event::DominoClipboardEnabledChanged(enabled)));

let label = text(t.compat_domino_clipboard).size(TEXT_SIZE_CONTENT).style(create_content_text_style());
#[cfg(windows)]
let label = with_setting_tooltip_inline_action(label, t.compat_domino_clipboard_hint,
    Message::Settings(Event::DominoClipboardEnabledChanged(!compat.domino_clipboard_enabled)));
#[cfg(not(windows))]
let label = with_setting_tooltip_inline(label, t.compat_domino_clipboard_unsupported_hint);
```

即：文案需要**第三条**（非 Windows 提示「仅 Windows 生效」），卡面只说了中英两条 + tooltip 注明，实际是 **2 × 2 = 4 条**（中/英 × Win/非 Win）。

### 🟠 P1-2：`set_clipboard_binary_pair` 写失败后的退化分支不能删

`clipboard.rs:117-127` 是「pair 成功 → return true」，`:129-136` 是「pair 失败 → 退化单格式」。加闸门时若图省事写成 `if enabled { pair } else { binary }` 并删掉退化分支，会在 `RegisterClipboardFormatA` 失败（`sys.rs:90-93`）等场景下让复制**整体失败**（落到文本 JSON）。正确形态是：`enabled` 时才尝试 pair，失败仍退化到单格式。

### 🟡 P2-1：Domino 编码器存在 ~1× 原始体的可避免拷贝（本卡不改，登记）

`domino.rs:251-254`：

```rust
let body_out: Vec<u8> = top.iter()
    .flat_map(|c| build_chunk(c.id, c.kind, &c.payload))   // build_chunk 每块新分配一个 Vec
    .collect();
```

而 `build_chunk`（`:81-88`）会 `Vec::with_capacity(6 + payload.len())` + 整段 `extend_from_slice`。eb 块的 payload 就是**整个音符体**（40 B/音符）。于是内存里同时存在 `eb_payload` + `build_chunk` 临时 + `body_out` 三份 ≈ 原始体的 3 倍——与实测 3.4× 吻合。改成 `Vec::with_capacity` + 直写 `extend_from_slice`（仓内已有 `push_chunk`，`:90-97`，正是为此写的）可省一份。

本卡设计说明明确「开启时编码路径原样」，故**不在本卡范围**，但应登记为后续优化；这也说明「开关默认关闭」是当前性价比最高的一刀。

### 🟡 P2-2：Domino 行为零测试覆盖

`crates/editor/ui-editor/src` 内 grep `domino` 只命中实现，**没有任何 `#[test]`**。验收项「开启时 Domino 双向互粘行为与现状完全一致」缺少回归基线 → 必须新增（见 §6）。

### 🟡 P2-3：`docs/research/clipboard-note-perf.md` 已过期

其 §3 引用的 `clipboard.rs:20-77` 是「全量 JSON 物化」时代（现 `clipboard.rs` 共 199 行且二进制优先），行号与结论均不再对应当前代码。本卡踩不到，但任何引用该文档的后续卡（尤其 ARCH-001）会被误导。

## 6. 验收标准补强

### 6.1 性能验收：**不需要新写 bench**，仓内已有现成探针

`crates/editor/ui-editor/benches/ui_boxselect_copy_bench.rs` 已具备全部要素：

- `:83` `LUMINO_UI_BENCH_CLIPBOARD`（`0` = 只编码不写剪贴板）
- `:79-81` `LUMINO_UI_BENCH_MIDI` / `_FRACTION` / `_MOVES` / `_CYCLES`
- `helpers.rs:109-113` 用 `EditorAction::Copy` 跑**完整生产路径**；`:203-220` 跑 Paste
- `:66` 全路径复制硬指标 `COPY_FULL_TARGET_MS = 200 ms`

⚠️ **注意一个反直觉的点**：bench 默认 `FRACTION = 0.05`（`:56`，≈280 万选中）**大于** `DOMINO_MAX_NOTES`，所以默认配置下 Domino 编码被保护闸跳过，**测不出差异**。要观测开关效果必须把选中数压到 **5 万 ~ 20 万**区间（例如调小 `LUMINO_UI_BENCH_FRACTION`）；这也再次印证 §3.3 结论 3。

推荐验收口径：
1. 选中 ≈15 万，开关**开**：全路径复制耗时 ≈ 打开前的值；`tracing::info!` 出现「Lumino 二进制 + Domino 二进制」双格式记录（`clipboard.rs:120-125`）。
2. 同一选中，开关**关**：全路径复制耗时下降 50–150 ms；日志退化为「已复制 N 字节二进制音符」（`clipboard.rs:130-134`），**且不出现** Domino debug 记录。
3. 开关本身无每帧成本：闸门是一次 bool 读取，位于 `#[cfg(windows)]` 块内紧贴调用点（`clipboard.rs:114` / `:167`），不进 `view`/`update` 每帧路径——审查 diff 即可确认，无需 bench。

## 7. 沉淀（可复用规律）

1. **「默认值照抄 X」必须核对 X 的实际属性**：`gpu_check_on_startup` 的默认值是 `true`（`default_true`），与「默认关闭」的需求正好相反。仓内「默认 false 的 UiConfig bool」正例是 `playback_key_colors_enabled`。**引用先例前先读先例的定义，不读名字。**
2. **「设置项 → 行为」的通路长度取决于消费点在哪一层**：
   - 消费点在 `Root`（弹 Toast、切主题）→ 1 跳，`Root` 方法直读 `self.settings`；
   - 消费点在 `ui-editor` 的 `Editor`（本卡、键色、橡皮、框选）→ **5 跳**（字段/初始化/setter/启动注入/变更同步），因为 `ui-editor` 不依赖 `ui-settings`。
   本卡错在先例归类，会直接造成「设置改了本次会话不生效」。
3. **「只在 `#[cfg(windows)]` 内被读的字段」是本仓的既有暗礁**：4 处 `#[cfg_attr(not(windows), allow(dead_code))]` 先例就是被 CI 的 `clippy --all-targets -- -D warnings` 逼出来的。新增 Windows-only 配置字段时，字段侧必须显式处置。
4. **「日志能区分两种跳过原因」才算有效日志特征**：`encode.rs:171-175` 的 debug 只在超限时打印，无法区分「开关关闭」与「超限跳过」，卡面把它当验收信号是无效的。有效信号是**成功路径的 info 双格式记录从有变无**。
5. **性能基准要落在真实路径上，且要检查保护闸是否把被测路径跳过了**：本仓 bench 默认 5% 选中（≈280 万）恰好大于 20 万保护闸 → 测不到 Domino。这是「bench 绿了但问题还在」的典型陷阱。
