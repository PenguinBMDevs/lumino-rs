### 2.2 窗口与逐帧驱动链（本卡真正的战场）

```
设置面板 = 独立 winit 窗口（dialog/src/window.rs:46-132，720×540，resizable）
  打开：host/dialog? → Host::new_settings_dialog (ui/src/host/builder.rs:181)
        → Root::new_settings_dialog (ui/src/root.rs:264) → **全新 RootState**
  关闭：runner/lifecycle/dialog.rs:83 → DialogManager::close_dialog
        (dialog/src/manager/lifecycle.rs:157) → 从 HashMap 移除，Host/Root 被 drop

每帧：runner/lifecycle/handler.rs:250-252  about_to_wait → dialog_manager.update()
        └─ manager/lifecycle.rs:178-192  MemoryMonitor ⇒ redraw_force()；其余 ⇒ redraw()
             └─ dialog/src/window/redraw.rs:7-21  gfx.with_frame(|..| ui.redraw_requested(..))
                  ├─ host/render.rs:52   process_frame_preparation()
                  │    ├─ events.rs:131-146  process_pending_events()（队列空则**直接早退**）
                  │    └─ frame.rs:78-85     needs_animation 门控 → route_message(AnimationTick)
                  │                          + window.request_redraw()
                  └─ host/render/ui.rs:30-39  **ui_dirty==false → 只 present 缓存帧，不重建 UI**
```

**关键判读**：
- `frame.rs:78-85` 的门控**只负责「喂 tick + 唤醒事件循环」，自身不置 `ui_dirty`**；对话框的 `ui_dirty` 唯一来源是 `process_pending_events` → `update_ui_state`（`events.rs:223-228`），而该路径在状态无变化且 iced 不返回 `State::Updated` 时传 `false`。因此**只加门控不加置脏 = 动画冻结在缓存帧**（这正是 `MemoryMonitor` 必须用 `redraw_force()` 的原因，见 `manager/lifecycle.rs:176-186`）。
- 对话框**没有**状态栏 `PerfUpdate`（每 100ms 一次的消息）这类周期性置脏源（主窗口有，见 `frame.rs:42-63`），所以不能指望"顺带被弄脏"。

### 2.3 关于页当前视觉基线

`about.rs` 四行文本 + 两个 `space()` 垫片，`spacing(SPACING_CONTENT=10)`、`padding(PADDING_CONTENT=20)`。对话框外层的自有标题栏**不含 logo**（`ui/src/titlebar.rs:116-137` 只有拖拽区 + 红绿灯），所以关于页是设置窗口内**唯一**的品牌落点，不构成"重复 logo"。

## 4. 卡面需澄清 / 修正项

### P0-1（会直接导致验收 3「完整触发彩蛋序列」不通过）
**只按"扩展 `frame.rs` 的 `needs_animation` 门控"实现，动画会在 1~2 帧后冻结。**
- 卡面未提"逐帧驱动"落在哪一层；源码事实是对话框有两个独立开关：**门控（喂 tick）** 与 **置脏（重建 UI）**。
- 修正：把 `frame.rs:78-85` 的判定表达式**提取为 `Host::needs_animation()`**（当前是内联表达式，散落会导致两处判定漂移），并：
  1. `frame.rs` 使用它（喂 `AnimationTick` + `request_redraw`）；
  2. `DialogManager::update()` 用它决定 `redraw_force()`（与 `MemoryMonitor` 同款）；
  3. `DialogWindow` 暴露 `needs_animation()` 转发到 `Host`。

### P0-2（会直接导致验收 5「重开不再出现」不通过）
**"消失"标志不能存在 `SettingsPanel` / `RootState`。**
- 每次打开设置面板都会 `Host::new_settings_dialog` → 全新 `RootState`（§2.2），面板内任何字段都会被重置。
- 修正（推荐 A，备选 B）：
  - **A（推荐）**：`ui-core` 加进程级 `static ABOUT_LOGO_VANISHED: AtomicBool` + `about_logo_vanished()/mark_about_logo_vanished()`（`#[cfg(test)]` 复位函数）。先例：`ui-core/src/resources/icon.rs:9` 的 `HIDPI_ENABLED: AtomicBool`。"仅进程内保持、不写配置"的需求语义与该结构**逐字对应**。
  - B：走"对话框 → 全局事件 → Runner → 主窗口 Root 存标志 → 开面板时注入"的链路（先例：`pending_theme_apply`，`root_state.rs:101-106`；注入先例：`inject_pending_gpu_check_ui`，`handler.rs:239-240`）。更"架构正确"，但为一个会话级布尔值引入 3 跳同步，**性价比明显低于 A**。

### P1-1（会直接导致验收 3 的"移动到任意位置"难做或抖动）
**视图层拿不到窗口尺寸，也没有控件位置回读能力。**
- `window::Window` 无尺寸字段；`Root::view(&self)` 是 `&self`（`root/view.rs:16-20`）→ **视图里不能推进动画状态**（必须走 `update`）。
- 修正：飞行坐标**全归一化**，用 `Stack` 覆盖层内的 `FillPortion` 占位器表达：
  ```
  column![ space().height(FillPortion(y_norm)),  row![space().width(FillPortion(x_norm)), logo, …], space().height(FillPortion(1-y_norm)) ]
  ↑ 固定尺寸 logo 之外的剩余空间按 portion 精确分配 ⇒ "占比"即"坐标"，与窗口尺寸/缩放无关
  ```
  注意：`FillPortion` 为 `u16`，落地帧需 `y ∈ [0, 0.999]`（留 ≥1 的余量，避免 0 值语义歧义）。
- **动画起点**：用 `mouse_area::on_move(Point)` 缓存最后悬停点，第 15 次点击时取该点作起点（点击必落在 logo 内，误差 ≤ 半个 logo 宽）。**该方案同时解决了"关于页被滚动过"导致常量化坐标失准的问题**（关于页在 `scrollable` 内）。
- 备选：给 `window::Window` 加 `size: Size`，在 `Host::resize`/`handle_resized_event`（`host/event/window/events.rs:14-21`）同步，之后可做像素级绝对定位。**代价**是新增一处必须保持同步的状态；归一化方案无此代价，故不推荐。

### P1-2（会直接导致"快速转动"做不出）
**`icon::view_with_size_and_theme` 返回不透明 `Element<'static>`，无法链式 `.rotation()/.opacity()`。**
- 修正：在 `ui-core/src/resources/icon.rs` 新增（`svg_element` 已是私有可复用的 `Svg` 构造器）：
  ```rust
  pub fn view_transformed(icon: Icon, w: u32, h: u32, theme: Option<&Theme>, rotation_rad: f32, opacity: f32) -> crate::Element<'static>
  ```
- **必须同时做 AABB 补偿**：`Svg::layout` 用 `rotation.apply(image_size)` 求包围盒（`svg.rs:176-183`），`ContentFit::Contain`（默认）会把旋转后的 AABB 塞进 `Fixed(w,h)`，导致**旋转过程中图被等比缩小**（app-logo `viewBox` 184×218，45° 时约缩到 77%，视觉上是"转动时周期性一缩一放"）。
  补偿：传入的 `w=h=LOGO_SIZE * (|cosθ| + |sinθ|)`（方形的 AABB 增长因子），即可让绘制尺寸恒定。`Length::Fixed` 保证布局盒恒定，**不会把同级内容顶开**（`svg.rs:186-195`），此项无需额外处理。

### P2-1（描述与仓库事实不符）
「音效…自录或网络获取均可」——但仓库现状是**零音频素材 + 无第三方素材台账**（全仓仅 `LICENSE`，无 `THIRD_PARTY`/`NOTICE`）。外链素材还需补一份许可溯源文档。见 §6 的推荐方案（程序化合成可完全规避）。

### P2-2（卡面表格"超时阈值可调"）
建议实现为**单一常量**（`CLICK_TIMEOUT = Duration::from_secs(2)`），不做用户可见配置——卡的验收标准里没有"可配置"这一条，且一旦进配置就意味着持久化（与"不写配置持久化"的设计说明相悖）。**需拍板**（§9-Q3）。

### P2-3（"窗口可见范围"的边界）
非原生标题栏模式下，设置窗口视图 = `column![自有标题栏(30px), content]`（`root/view/overlays.rs:228-238`）。若蛋层挂在 `view_settings_dialog` 内，则"窗口可见范围"= content 区（不含标题栏 30px）。若要真正顶到窗口底/顶，需把蛋层上提到 `view_dialog` 层。**需拍板**（§9-Q2）。

## 5. 实施方案（文件级）

### 5.1 状态与逻辑层（纯逻辑、可单测）

**新增** `crates/editor/ui-core/src/state/about_egg.rs`（`ui-core/src/state.rs` 里 `pub mod about_egg; pub use about_egg::AboutEggState;`）：

```rust
pub enum EggPhase { Idle, Shake, Spin, Detach, Fall, Impact, FadeOut, Vanished }

pub struct AboutEggState {
    clicks: u32,            // 连点计数
    last_click: Option<Instant>,
    origin: Option<(f32, f32)>,   // 归一化起点（来自 on_move 缓存的悬停点）
    target: (f32, f32),     // 归一化落点（x 任意、y ≥ 1.0 表示底部）
    phase: EggPhase,
    phase_start: Option<Instant>,
    spin_angle: f32,        // 弧度
    pos: (f32, f32),        // 归一化当前位置
    velocity_y: f32,        // 归一化速度（重力积分用）
    opacity: f32,
    impact_fired: bool,     // 音效幂等闸
}
```

要点：
- `on_click(now: Instant, hover: (f32,f32)) -> bool`：**惰性超时**——`now - last_click > 2s` 则 `clicks = 0` 再累加；满 15 置 `EggPhase::Spin` 并随机采样 `target`（`rand 0.8` 已是 workspace 依赖，需给 `ui-core` 加 `rand`；或退化为时间种子伪随机以免加依赖）。
- `update(now: Instant) -> bool`：按 `phase` 推进；`Shake` 用正弦包络（约 0.28s、2 次往复、±7px，`Padding{left/right}` 反向垫付保证布局盒不动）；`Spin` 约 0.5s、角速度 ~14 rad/s；`Detach` 把位置从 origin 插值到 target（~0.25s）；`Fall` 用 **匀加速** `y = y0 + 0.5*g*t²`（归一化高度 1.0、落底约 0.55s ⇒ `g ≈ 6.6`），`dt` 上限钳 50ms（防卡顿后瞬移）；`Impact` 触发音效回调并切 `FadeOut`（~0.35s）；`FadeOut` 结束 → `Vanished`，**清计数、写进程级消失标志**。
- **硬超时兜底**：进入彩蛋序列即记 `deadline = now + 4s`，`update` 超时无条件跳到 `Vanished`（防任何相位逻辑 bug 导致对话框永久逐帧重绘，见 §7-R1）。
- 所有时间量都以**参数传入的 `Instant`** 计算 ⇒ 单测可直接构造时间轴，无 `sleep`。

**新增**消失标志（`ui-core/src/state/about_egg.rs` 或独立 `ui-core/src/about_logo.rs`）：`static ABOUT_LOGO_VANISHED: AtomicBool` + 读写 + `#[cfg(test)] fn reset()`。

### 5.4 音效层（新基建）

**新增** `crates/audio/midi-io/src/ui_sfx.rs`（`midi-io/src/lib.rs` 加 `pub mod ui_sfx;`），`lumino-ui` 已依赖 `lumino-midi-io`，可直接调用：

```rust
pub fn play_pipe_impact();   // 幂等、绝不阻塞、失败静默
```

实现要点：
- **零素材**：用程序化合成"钢管落地"到 PCM 缓冲（详见 §6-A）。
- **专用线程 + 常驻流**：首次调用 `std::thread::Builder::spawn` 一个 worker（UI 线程绝不阻塞），worker 内 `cpal::default_host()` 打开输出流，用无锁/`mpsc` 环形缓冲喂样本；播放结束后**保留流**（下次零设备开销）。设备打开失败只 `tracing::warn!` 一次，不影响彩蛋其余流程。
- 设备选择可复用 `audio_devices::resolve_audio_output_device`（当前无主音量配置项，`config.rs` 只有 `audio_output_device`，故固定音量、峰值约 −12 dBFS）。
- 与合成器流并存：同为 cpal 共享模式；**ALSA 后端是唯一真实风险点**（§7-R3）。

### 5.5 消失状态（P0-2）

`ABOUT_LOGO_VANISHED: AtomicBool` 进程级；`about_view` 读它决定是否渲染 logo；彩蛋 `Vanished` 相位写入。重启进程即自动复位，无需任何清理代码（也就**不可能**被漏写进配置）。

## 6. 音效方案对比

| 方案 | 许可 | 体积 | 依赖 | 落地难度 | 结论 |
|---|---|---|---|---|---|
| **A 程序化合成（推荐）** | **无第三方素材 ⇒ 零许可问题** | 0 字节（运行期生成 ~0.6s 缓冲） | 仅 `cpal`（已有） | 中：写 ~60 行合成器 | ✅ **推荐** |
| B 内置 CC0 素材（Freesound/Pixabay） | 需逐条溯源留档（仓库**无** `THIRD_PARTY`/`NOTICE`，只有 `LICENSE`） | 50–120 KB | `hound 3.5`（已有）+ `include_bytes!` | 低 | ⚠️ 备选，须新增许可台账 |
| C 复用现有合成器播 MIDI 音 | 无 | 0 | 已有 | 低 | ❌ 钢管音色不可得，"哐"声不像 |

**方案 A 合成配方**（命中"钢管落地"听感，全部为公开声学常识，无版权客体）：
1. **瞬态**（0–8 ms）：白噪声 × 指数衰减，经 ~3 kHz 一阶低通 → 金属撞击的"啪"。
2. **主共振**（非谐分音，钢管/棒体特征）：3~4 个非整数比分音（如 320 / 811 / 1490 / 2360 Hz），各自指数衰减 τ≈0.22–0.35 s，高频衰减更快。
3. **音高下弯**：主分音在 60 ms 内下滑 ~4%（撞击后张力释放的"当—"感）。
4. 归一化到 −12 dBFS，淡出尾部 30 ms 防爆音，单声道复制到设备声道数。

## 7. 风险与缓解

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 逐帧重绘把对话框变成常驻满载（仓库有同类事故：`RedrawRequested` 自循环致 GPU 满载，`events.rs:125-130`） | 验收 7 不通过、耗电 | ①门控**只**在蛋动画期间为真；②`update()` 内**硬 deadline 4s** 无条件收尾；③`Vanished` 后 `is_visible()==false` ⇒ 蛋层不再 push、`needs_animation()` 为假；④实现后用 puffin/帧时实测 |
| R2 | 面板关闭/切页打断动画 | "不得卡死、不得残留状态" | 状态在 `RootState`；切页不影响（蛋层挂对话框根，不挂关于页）；关面板 = Host drop，天然无残留；音效 worker 为进程级、不持有窗口引用 |
| R3 | 新增 cpal 流与合成器流争设备（ALSA 尤甚） | 音效无声或影响回放 | 静默降级；仅在蛋触发时懒建流；必要时退化为"无音效但序列完整" |
| R4 | 蛋层吞掉点击 | 用户无法操作对话框 | 蛋层**不套 `mouse_area`**，容器不消费鼠标事件 ⇒ 点击穿透（对比 `settings_dialog.rs:83-98` 的 BPM 遮罩是**故意**用 `mouse_area` 捕获的） |
| R5 | 旋转期视觉缩放 | 观感像 bug | AABB 补偿（P1-2） |
| R6 | 起点取"点击点"而非 logo 精确左上角 | 最大偏移 = 半个 logo 宽 | 可接受（点击必落在 logo 内）；如追求精确，需 `window::Window` 加尺寸 + 常量化坐标，代价见 P1-1 |
| R7 | 菜单索引 `9 => about_view` 被别的卡改动 | 无 | 本卡只在 `about.rs` 内部加元素，不动索引 |
