# REF-LGS-010/011 · 声部参数静态/动态分离 + 包络模板去重

> 日期：2026-10-31 ｜ 分支：`ref-lgs` ｜ 机器：RTX 5080 / 驱动 610.88 / 48 kHz
> 结论：**逐位一致**；`sustained65536` 6 对中位 **filtered +19.8/+14.8/+10.6%**、
> **unfiltered +19.7/+14.9/+11.5%**（512/2048/4096）。每声部每块上传
> **≈250 B → 112 B**（新增声部额外 64 B 静态，一次性）。

## 2. 010：静态/动态分离

### 2.1 先删死字段（D2）

`grep` 证明 `render.wgsl` 从未读取 `p.sample_len` / `p.base_frame` / `p.channel`
（`channel` 自 REF-LGS-001 的按通道桶之后已改由桶索引决定）。三者连同
`Voice::sample_len` 一起删除：**116 B → 104 B**，零语义变化。

### 2.2 拆分

| 表 | 大小 | 内容 | 上传时机 |
|---|---:|---|---|
| `params_static`（**槽位**索引） | 64 B | `offset/sample_end/loop_*/amp/pan_*/filter_on/b0..a2/interp/channels` | **只在分配槽位时** |
| `params`（**声部下标**索引） | 44 B | `slot/is_active/release_at/env_base/env_count/release_idx/finished_idx/sample_offset*/start_at/speed` | 每块 |

- **槽位稳定**：`Voice.slot` 在首次上传时分配（LIFO 空闲表复用），
  `retain` 压缩声部列表不改变槽位，因此静态表不需要按块重排。
- 槽位回收集中在 `retain_voices` / `clear_voices`（`slot.rs`），
  `warm_gpu` 的预热声部也会归还槽位（否则每次预热泄漏一个槽位）。
- 静态上传按**连续区间合并**（`coalesce_dirty_slots`）后逐段 belt 写，
  常见情况下单块新声部落在相邻槽位。
- 扩容：`GrowableBuffer::ensure` 清零新区域并保留旧内容（`buffer.rs`）；
  CPU 镜像 `static_table` 用 `resize(.., zeroed())` 同步扩容。
  **未分配槽位永远不被读取**（只有分配时才写），因此不存在读未初始化数据。

### 2.3 为什么这些字段留在「动态」

- `speed`：`propagate_channel_pitch` 会给在响的声部直接改 `v.speed`
  （弯音/调音/RPN），不是生命周期不变量；
- `env_base`：011 之后是模板下标，淡出时切换模板；`env_count/release_idx/
  finished_idx` 随 CC72/73 与淡出改写；
- `sample_offset*`：采样表在 `upload_voices` 之后才上传（`upload_new_samples`），
  首块可能是 0、下一块才解析出真实偏移——保持动态可**免掉一整类 dirty 追踪**，
  且逐位一致；
- `start_at`：每次 note-on 不同（实例级）。

> 与卡内字段表的偏离：卡内把 `sample_offset*`/`speed` 算作静态。实测它们
> 会被解析/弯音改写，做成静态就必须在改写点打脏标记（漏一处即错音）。
> 动态表 44 B + 状态 68 B = **112 B**，已经满足卡内 ≤120 B 目标。

## 3. 011：包络模板去重 + append-only 上传

- 新 `EnvTemplatePool`（`env_pool.rs`）：`(kind, target, duration)` 序列做
  FNV-1a 哈希 → 候选链 → 逐字段比对；命中即复用，未命中才追加。
- `Voice.env_template` 在**驻留时**解析一次（新声部 / `refresh_env_stages`
  之后失效），每块零查表。
- GPU 侧 `env_stages` 从「每声部前缀和副本」变成「去重后的模板表」，
  **只在追加时上传尾部**（`pending()` + `mark_uploaded()`），稳态零上传。
- 淡出（REND-015 #115 的 5 ms 线性淡出）改成共享的**单 stage 模板**，
  不再逐声部写 12 B。
- `bind.rs` 每块无 `Vec` 重建（PREF-006 B 已复用；`grep Vec::new|to_vec` 为空），
  本卡不再重复改。

**每声部 env 占用：≈60–72 B → 0 B（稳态）**；模板总量由音色/包络变体数决定
（个位数到几十条），与声部数无关。

## 7. 偏离与已知缺口

1. **011 未单独出二进制**：两张卡同函数批次实施，A/B 为合并口径。
   归因：字节数 250 → 112 B 中，env 占 60–72 B（≈26%），`dispatch` 降幅
   与字节降幅线性吻合；`upload` 侧的逐声部 env 切片拷贝也随 011 消失。
2. **`sample_offset*`/`speed` 放动态**（见 §2.3）——卡内字段表按静态设计，
   实测会被改写；保持动态才逐位安全。
3. **`init.rs` 488 行 → 390 行**：把 `reset_channel_state` 与诊断入口拆到
   `engine/diag.rs`（文件长度约定）。

## 9. 后续注意

- 新增**静态字段**必须同时更新 `Voice::gpu_static` 与 `assign_static_slots`
  的「一次性写入」假设；任何生命周期内会被改写的字段只能放进 `VoiceParamsDyn`。
- `Voice.slot` 只能在 `retain_voices`/`clear_voices`/`warm_gpu` 三处回收，
  新增声部删除路径必须走这三个入口，否则槽位泄漏（`slot_count` 只增不减）。
- 包络语义（`to_gpu_stages`/`modify_env_stages`）未改；模板只是共享同一份
  `(kind, target, duration)`。
