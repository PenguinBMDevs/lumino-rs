# REND-002 实时多端口（CPU/LGS 对齐）· 行动方案

> 分支：`feat/rend-002-realtime-multi-port`（基于 dev `3fdafba7`）
> 范围：**实时**播放链路的多端口支持；离线侧已在 #87（PR #108/#110）完成。
> 用户口径：CPU 与 GPU 实时尽量对齐。

## 一、目标

同一份多端口文档，无论走 **XSynth（CPU）** 还是 **LGS（GPU）** 实时后端：
- `(port, ch) → port*16+ch` 全局通道语义一致；
- 端口间 CC/PC/PB/声部不串台；
- 文档装载/切换/关闭时端口布局正确重建（或轻量复位）；
- 单端口（16 通道）零行为变化。

## 二、现状审计（两者并不对称）

### A. CPU（XSynth）——已接线，但有缺口

**已有**：
| 能力 | 位置 |
|---|---|
| 布局 → `SynthFormat::Custom{channels}` + 每端口 ch9 打击乐 | `midi-io/src/api/xsynth/init.rs:30-38,115-116,200-207` |
| `set_midi_port_layout`：同布局轻量复位 / 异布局全量重建（成功才提交） | `api/xsynth/api.rs:49-70`、`init.rs:221-294` |
| 应用接线：装载 `load.rs:343-356`、关闭 `close.rs:28,54`、导出 `export.rs:65` | `src/runner/menu/file/*` |
| 初始化完成后的 desired/spawned 对齐 | `src/runner/midi_manager/recovery.rs:62-77`、`xsynth.rs:31-34,127-140` |
| 输出连接直接消费全局通道 | `api/xsynth_output.rs:86-142` |
| `PlaybackOutput` 覆写：打击乐模态 + 全通道踏板释放 | `api/xsynth_output.rs:221-239` |

**缺口/风险（需审计修复）**：
1. `apply_midi_port_layout` 在 `active_backend != XSynth` 时只暂存（`xsynth.rs:129-132`）→ **LGS 后端永远不应用布局**；
2. `finish_lgs_init` 没有 desired/spawned 对齐（对比 `finish_xsynth_init:62-77`）；
3. `export.rs:65` 在导出流程调用 `apply_midi_port_layout(doc.max_port())` —— 是否误触实时管线重建，需核实；
4. `handle_stream_recovery` → `recover_stream()` 是否保留当前布局（重建语义），LGS 侧默认实现行为待查。

### B. GPU（LGS）——完全未接

| 缺口 | 位置 |
|---|---|
| `LgsOptions` 无 `midi_max_port`；`SynthConfig` 走默认 → `midi_channels=16` | `api/lgs.rs:26-41,72-82` |
| `Lgs` 空实现 `SynthControl` → 无 `set_midi_port_layout` | `api/lgs.rs:279-280` |
| `LgsOutputConn` 全程 4bit 折叠（note/cc/pc/pb） | `api/lgs.rs:168-217` |
| `PlaybackOutput` 空实现 → 打击乐模态 no-op、踏板释放只覆盖 16 通道 | `api/lgs.rs:282-283`（对比 `xsynth_output.rs:221-239`） |
| 应用层 `init_lgs_blocking` 不传布局 | `src/runner/midi_manager/lgs.rs:52-64` |

## 三、实现方案

### A. LGS 引擎层（`crates/audio/midi-io` + `crates/audio/gpu-synth`）
1. **A1 布局选项**：`LgsOptions` 增 `midi_max_port: u8`（默认 0）；`Lgs::new` 以
   `channels_for_max_port_clamped(max_port)` 构建 `SynthConfig.midi_channels`。
2. **A2 布局重建**：`Lgs` 增 `midi_max_port` 字段并实现
   `SynthControl::set_midi_port_layout(max_port)`：
   - 异布局：停旧 `AudioPlayback` → 新建 `GpuSynth`（同音色库/选项/新布局）→ `AudioPlayback::start`
     → **热替换 `event_tx` 内层发送器**（所有 `LgsOutputConn` 自动跟随，与 XSynth 语义一致）；
     仅成功才提交布局，失败保持旧管线；
   - 同布局：轻量复位。GPU 无现成复位 API → 在 `GpuSynth` 增加 `reset_channel_state()`
     （清 `channels`/`voices`/`key_voices`/`active_notes`/`pending_events`，等价离线重置块），
     语义对齐 XSynth 的 `reset_channel_state`（清上一文档 bank/模态/声部）。
3. **A3 输出连接去折叠**：note_on/off/cc/pc/pb → `ch.min(255) as u8`（全局通道）；
   `send_raw` 保持低 4 位（live 输入无端口概念，固定 port 0）。
   **顺序硬约束：先 A2 后 A3**，否则 ch>15 越界（引擎会丢弃+告警）。
4. **A4 `PlaybackOutput` 覆写**（对齐 `xsynth_output.rs:221-239`）：
   - `release_all_dampers`：按 `midi_channels` 逐通道发 CC64=0（GPU 事件为逐通道 `(u8, MidiEvent)`）；
   - `set_percussion_mode`：暂 no-op + 显式注释（GPU 打击乐语义在 #107 REND-013；语义对齐记录）。

### B. 应用层接线（`src/runner`）
1. `start_lgs_async_init` 取 `desired_midi_max_port` 并记录 `spawned_midi_max_port`（镜像 `xsynth.rs:31-34`）；
2. `init_lgs_blocking` 传 `midi_max_port` 给 `ApiKind::Lgs`；
3. `apply_midi_port_layout` 支持 LGS 分支（`active_backend == Lgs` 时调 `api.set_midi_port_layout`）；
4. `finish_lgs_init` 补 desired/spawned 对齐（镜像 `finish_xsynth_init:62-77`）；
5. 审计 `export.rs:65` 与 `handle_stream_recovery`（见审计缺口 3/4）。

### C. CPU 侧补齐/验证
1. 把 `apply_midi_port_layout` 的"暂存/应用"逻辑整理为可测状态机（desired/spawned/active_backend），补单测；
2. 多端口文档在 XSynth 实时 E2E：load → layout applied → 逐端口 CC/pan 隔离（事件级单测已有
   `chase/track_rules`，补一条"布局应用后全局通道事件流"断言）；
3. 若用户实测 CPU 仍有失败：以复现路径为准定位（本方案不预设结论）。

### D. 顺序与提交切分
- 提交 1：A1+A2（LGS 布局重建能力，未摘掩码，零行为变化）；
- 提交 2：A3+A4（去折叠 + PlaybackOutput 覆写）+ B（应用层接线）；
- 提交 3：C（CPU 审计补齐）+ 测试；
- 每步单端口回归。

## 四、验收

1. 同一多端口 fixture（`port_pan_isolation.mid` / Night Voyager）在 **XSynth 与 LGS** 实时下：
   端口间 CC/Pan 隔离、无串台（听感；必要时声卡回环录制 RMS 对照，方法沿用离线隔离实验）；
2. 布局切换路径（装载多端口 / 切回单端口 / 关闭文档 / 后端 System→XSynth / System→LGS）无
   `event dropped` 告警、无越界、无静音；
3. 单端口零回归（16 通道路径不变）；
4. 重建耗时与听感：异布局重建 ~100-200ms（与 XSynth 同量级），重建即清声部（与 XSynth 一致）。

## 五、测试

- `LgsOutputConn` 通道透传单测：注入 mpsc 的 `SharedEventTx`，断言 ch16+ 原样到达（非折叠）；
- `set_midi_port_layout` 逻辑单测：同/异布局分支、失败回滚（GPU 依赖部分标 `#[ignore]` 或拆纯逻辑）；
- 应用层状态机单测（desired/spawned/apply）；
- `GpuSynth::reset_channel_state` 单测（纯状态，不需 GPU）。

## 六、风险

- LGS 重建期间有 ~100-200ms 断音（与 XSynth 全量重建一致；同布局走轻量复位规避）；
- `event_tx` 热替换的并发安全：所有 `LgsOutputConn` 经 `Arc<Mutex<Option<Sender>>>` 读取，
  替换与发送都在锁内，无窗口期丢事件；
- 外部 MIDI 输出（KDMAPI/winmm）保持 4bit 折叠（C1=a 决策），不在本卡。

## 七、实施进度（2026-10-04）

A1–A4 + B 已实现（本分支提交）：

- **LGS**：`LgsOptions.midi_max_port` → `SynthConfig.midi_channels`；`set_midi_port_layout`
  同布局轻量复位（`PlaybackControl::ResetState`）/ 异布局全量重建（构建成功才停旧流、起新流
  并热替换事件/控制发送器）；`LgsOutputConn` 去 4bit 折叠（`ch.min(255)`）；
  `PlaybackOutput` 覆写：踏板清理走引擎级控制命令，打击乐模态暂 no-op（#107）。
- **gpu-synth**：`GpuSynth::reset_channel_state`、`GpuSynth::release_all_dampers`；
  `AudioPlayback` 控制通道（ResetState / ReleaseAllDampers，不重开音频流）。
- **应用层**：LGS 异步初始化注入端口布局；`apply_midi_port_layout` 支持 LGS 分支；
  `finish_lgs_init` 完成时对齐 desired/spawned（镜像 XSynth）。
- **审计结论**：`export.rs:65` 的 `apply_midi_port_layout` 是"自动保存重载后强制重建清模态"
  的有意行为（同一文档 → 同布局 → 轻量复位），非缺陷；LGS `recover_stream` 走默认
  "不支持恢复"，`handle_stream_recovery` 不会被触发（后续如需设备热插拔恢复另立）。
- **测试**：LGS 全局通道透传（16/31）+ 控制通道踏板清理 2 项；workspace check/clippy/fmt 干净。
- **待人工验收**：LGS 实时多端口听感（端口隔离）+ 布局切换路径（装载多端口↔单端口↔关闭）；
  C 段（CPU 状态机单测）按需后续补。
