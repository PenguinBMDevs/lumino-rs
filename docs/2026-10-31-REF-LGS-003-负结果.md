# REF-LGS-003 · 负结果归档：mix 通道上界注入（不合并）

> 日期：2026-10-31 ｜ 分支：`ref-lgs-003`（**已删除**，改动已 revert）｜ 状态：**关闭（假设被实测否定）**
> 结论：功能正确、逐位一致，但性能 **−3.5% / −3.6%**（gate 2%）；不合并。
> 本文件是该卡的公开归档；原始记录在 `.ai-context/sessions/2026-10/2026-10-31-REF-LGS-003-负结果与决策记录.md`（gitignored）。

## 1. 卡片前提与演化

原卡（issue #188）假设：`mix.wgsl` 每线程静态分配约 **17.4 KiB** 私有内存
（`acc_rel_*` 4 KiB + `cur: array<MixStart,256>` 12 KiB + `frames` 1 KiB），
按 16 通道收窄可以"低风险快赢"。

实施前做了两项范围修订（D1/D6）：

1. **不合并 `acc_rel`**：released 与 sustained 分组的求和顺序不同，合并会改变
   浮点加法顺序，破坏逐位一致。`scatter100k`（释放密集）实测 90% 样本不同、
   `max|d|` −102.1 dBFS、RMS −123.8 dBFS → 若要做必须另立卡并给容差口径。
2. 卡范围重写为：**编译期把通道上界注入 shader**（`MAX_CHANNELS` → `CHANNELS`，
   按 `SynthConfig::midi_channels` 字符串替换）+ 删除死守卫
   `if (ch >= MAX_CHANNELS) break`；uniform `starts[256]` 保持不变。

同时 REF-LGS-001 已把 mix 改成「按通道桶 gather」——原卡里的 `cur`/`frames`
逐线程数组已不在新内核里，003 剩下的只有通道上界注入这一项。

## 2. 实现（已 revert）

| 文件 | 改动 |
|---|---|
| `gpu/shaders/mix.wgsl` | `MAX_CHANNELS` → `CHANNELS`；数组按 `CHANNELS`；删死守卫 |
| `gpu/pipelines.rs` | `mix_source(channels)` 字符串替换、`mix_private_bytes(channels)`（cfg(test)）、`create_mix_pipeline(..., channels)` |
| `gpu/resources.rs` | `GpuResources::new(..., midi_channels)` + `mix_channels` 字段 |
| `synth/engine/init.rs` | 传 `config.midi_channels`；`with_resources` 上界校验 |
| `synth/engine/bind.rs` | `debug_assert!(channels.len() <= res.mix_channels)` |

## 3. 验证

### 3.1 功能（全部通过）

- 单测 2/2：`mix_source_injects_the_compiled_channel_bound`、
  `declared_private_bytes_scale_with_channels`；
- 逐位一致（同块长/同配置）：
  - `sustained65536 @512`：`a3397a2279e0a11f`（与基线相同）；
  - `scatter100k @512`（`LUMINO_NO_LIMITER=1`）：`1ad03ca435f4783a`（与基线相同）；
- 声明私有内存（68 B/通道）：16→1.06 KiB｜32→2.1 KiB｜64→4.25 KiB｜
  128→8.5 KiB｜256→17.0 KiB。

### 3.2 性能 A/B（双二进制 + 顺序交替 + 6 对 + 中位）

| block | baseline | after（CHANNELS=16） | Δ |
|---|---:|---:|---:|
| 512 | 9.233 s | 9.554 s | **−3.5%** |
| 2048 | 2.968 s | 3.074 s | **−3.6%** |

每一对 after 都更慢；GPU 39 °C / SM 2782 MHz，无降频。

### 3.3 隔离实验

`control256`（保留全部 Rust 改动、强制注入 256 数组）vs 基线：**+0.7% / +2.2%**，
在噪声内 → 回归来自 **16 尺寸 shader 的代码生成**，不是 Rust 侧改动。

## 4. 结论

- 003 的前提（17.4 KiB 私有内存 → 1 KiB = 快赢）在 RTX 5080 + 驱动 610.88 上
  **不成立**：16 通道 mix 不是被声明私有内存卡住的（512 档宿主 `collect` 等待、
  2048 档小数组反而略慢）。
- 改动已全部 revert，临时分支已删除。
- 收益空间转向后续卡并已兑现：001（mix 并行形状）、002（`voice_out` 分块）、
  004（事件重放分桶，高事件密度 **+34.9%**）、010/011（上传瘦身 **+19.8%**）。

## 5. 方法论教训（已落进 013）

1. 单次对比会被环境漂移欺骗（同一天同一份代码测到 8.33 → 9.17 → 9.60 s）；
2. 可靠做法：保存 baseline/after 两个可执行文件 → 顺序交替（奇偶对调）→
   ≥6 对 → 中位；记录 GPU 时钟/温度；
3. 持续音夹具没有 released 声部，测不出 `acc_rel` 合并的差异，释放密集素材
   （`scatter100k`）是必需夹具；
4. 512 档是宿主瓶颈（collect≈13 ms/块 + upload≈3.5 ms/块），GPU shader 微优化
   容易被宿主噪声淹没。
