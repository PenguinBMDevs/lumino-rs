# UI-018 界面语言自动跟随系统（中文系→中文 / 其余→英语）· 调研报告

- 调研日期：2026-10-11
- 调研对象：需求「自动根据系统语言切换显示语言；中文系系统（简体/繁体/其他体）显示中文，其他语言（日语/英语/韩语等）显示英语」
- 分支：`feat/drawing-tools`（工作区有 5 个与 i18n 无关的改动：画刷粗细 1-100 等；**本次调研未改任何代码**）
- 调研方式：**源码逐条对质（含依赖源码）** + **本机 Windows 11 实测系统 API（C# P/Invoke）** + 网络检索（`web_search`/`web_fetch` 工具通道不可用，改走 shell HTTP，见 §10）
- 结论：**机制层面成本很低（1 个检测函数 + 1 个配置字段 + 1 个设置项，约 10 个文件）**；但有三件事必须先对齐：① 检测必须**按主语言子标签匹配**而不是整串相等（同一台机器上三个来源给的是 `zh-CN` / `zh-Hans-CN` 两种写法，实测见 §4）；② 老配置的「用户显式选择」不能被自动检测覆盖；③ **真正的成本在 i18n 覆盖率**——现有翻译 277 条，而 UI 可见的硬编码中文有 **1132 行 / 209 文件**（§7），英文系统用户会看到大面积中英混排。

## 2. 需求口径与判定边界

| 系统显示语言（示例 tag） | 期望界面 | 现状（本卡前） | 差距 |
|---|---|---|---|
| `zh-CN` / `zh-Hans-CN` / `zh-Hans-SG` / `zh-Hans-MY` / `zh-Hans-MO` | 中文（简体） | 中文（简体） | 无（现状即正确，属巧合：默认值就是中文） |
| `zh-TW` / `zh-Hant-TW` / `zh-Hant-HK` / `zh-Hant-MO` | 中文 | 中文（简体） | ⚠️ 文言/字形差异，接受则零成本，讲究则需新增繁体翻译包 |
| `ja-JP` / `ja` | **英语** | ❌ 中文 | **本卡要修的主症状** |
| `ko-KR` / `ko` | **英语** | ❌ 中文 | 同上 |
| `en-US` / `en-GB` / `en` | 英语 | ❌ 中文（首次启动） | 同上 |
| `de-DE` / `fr-FR` / `ru-RU` / … 其他一切 | **英语** | ❌ 中文 | 同上 |
| 空 / 只有 `C` / `POSIX` / 检测失败 | **建议保持现状（中文）** | 中文 | 见 §5.4 理由 |

**三条必须钉死的口径**（否则实现会跑偏）：

1. **用户显式选择 > 系统检测**：设置面板里手动选过语言之后，绝不能被下一次启动的自动检测覆盖——这是「用户选择静默丢失」级别的缺陷。
2. **检测必须容错**：任何未识别的 tag 按「非中文」处理 → 英语（需求原文：其他语言显示英语）。
3. **区域格式 ≠ 显示语言**：`GetUserDefaultLocaleName()` 给的是「区域/日期格式」，一台机器完全可以「区域=中国，显示语言=English」。要取的是**显示语言**（§4.1 实测两者在本机同为 `zh-CN`，纯属这台机器两者一致，不能据此推断）。

## 4. 系统语言检测：平台事实（含本机实测）

### 4.1 Windows（本机 Windows 11 专业工作站版，实测）

用 C# `Add-Type` 直接 P/Invoke（复现命令见 §11）：

| 手段 | 实测返回 | 说明 |
|---|---|---|
| `GetUserPreferredUILanguages(MUI_LANGUAGE_NAME)` | **`[zh-CN, en-US]`**（`num=2`） | ✅ **就是「显示语言」列表**，本卡应采用 |
| `GetUserDefaultUILanguage()` | `0x0804`（LANGID，zh-CN） | 单个语言 ID，无脚本信息 |
| `GetSystemDefaultUILanguage()` | `0x0804` | 系统安装语言（非用户偏好） |
| `GetUserDefaultLocaleName()` | `zh-CN` | ⚠️ **区域格式**，与本卡需求不同的概念 |
| `Get-WinUserLanguageList`（Win11「语言和区域」） | `zh-Hans-CN`、`en-US`、`en-CA` | ⚠️ **同一台机器是带脚本子标签的写法** |
| `GetUILanguageFallbackList` | ❌ `Unable to find an entry point … in DLL 'kernel32.dll'` | **本机不可用**，别用它 |
| `LANG` / `LC_ALL` | 空 | Windows 上不存在 POSIX 环境变量 |

**三条硬结论**：

1. **API 选对了**：MS Learn 对 `GetUserPreferredUILanguages` 的定义是「Retrieves information about the **display language** setting」，`MUI_LANGUAGE_NAME` = 「Retrieve the language strings in language name format」。社区结论一致：该函数返回列表**只由「Windows 显示语言」这一个用户级设置决定**（SO 高赞答案原文：*"their returned langtag list is determined solely by current user's Windows display language selection. It is a user-wide single-selection setting."*）。NVDA 项目也正是为此专门改用该 API（nvaccess/nvda#12707）。
2. **它是「主显示语言 + en-US」**：SO 高赞答案的现场观测与本机实测完全一致（*"the function always only returns the first entry (the main Windows display language), and 'en-US'"*）。所以 **取首项**（即 `sys_locale::get_locale()`）就够了；保序遍历亦无害。
3. **⚠️ tag 形态不统一**：MUI API 给 `zh-CN`（RFC 3066 风格），Win11 设置界面/WinRT 给 `zh-Hans-CN`（BCP 47 带脚本）。Windows 官方语言包表中同族还存在 `zh-Hans-MO`（简体澳门）与 `zh-Hant-MO`（繁体澳门）。**任何整串相等匹配都会在真实机器上翻车**。

### 4.2 macOS

- `sys-locale` 走 `CFLocaleCopyPreferredLanguages()`（`sys-locale-0.3.2/src/apple.rs:49,143`），Apple 文档定义为「Returns the array of **canonicalized language IDs** that the user prefers」→ 返回形如 `zh-Hans-CN`、`en-US` 的 BCP 47 列表。
- ⚠️ GUI 进程的 `LANG` 通常为空，**不能**指望环境变量；必须走 CoreFoundation。
- ⚠️ 该 API 返回的是**语言偏好列表**，与「区域」是两件事（Apple 文档明确提示 *"the preferred language may not match the locale's language"*）——正是我们要的语义。

### 4.3 Linux / BSD

`sys-locale-0.3.2/src/unix.rs:67-135`，优先级：

```
LANGUAGE（可含多个，冒号分隔）> LC_ALL > LC_MESSAGES > LANG
   └─ 每个值：剥掉 .编码 与 @修饰符，'_' → '-'   （"ru_RU.UTF-8" → "ru-RU"）
```

- ⚠️ `LANG=C` / `LANG=POSIX` 在容器、CI、SSH 环境极其常见，会被原样转成 `"C"` / `"POSIX"` → **必须在业务层特别处理**（§5.4）。
- ⚠️ 已知上游 TODO：POSIX 修饰符（`@euro` 之类）不做语义转换（源码注释指向 1Password/sys-locale#32）。

### 4.4 为什么选 `sys-locale` 而不是自己写 FFI 或换别的库

| 候选 | 结论 |
|---|---|
| **`sys-locale 0.3.2`（推荐）** | 已在依赖图内（见 §1 #3），Windows 后端是**自带的 22 行 kernel32 FFI**（`src/windows_sys.rs`），零平台依赖、`no_std` 兼容、MSRV 1.56（<< 本仓 1.92）、双许可 MIT/Apache-2.0（与本仓 AGPL 兼容）、提供**保序列表** `get_locales()` |
| `locale_config` | 另一套模型（进程/线程 locale 栈），对本需求是过度设计；且需新增依赖 |
| `os-locale` | 已停止维护，无 `get_locales()` 语义 |
| 自己 P/Invoke | 要自己处理三平台 + UTF-16 缓冲两段式调用（本机探针就踩了「StringBuilder 在首个 NUL 截断」的坑）；重复造轮子且拿不到 macOS 的 CF 绑定 |

> `Cargo.toml` 只加一行：`sys-locale = { workspace = true }`（`[workspace.dependencies]` 里锁 `"0.3.2"` 与 lock 对齐）。**`Cargo.lock` 不会新增任何包**。

## 5. 映射算法（RFC 4647 §3.4 Lookup 的极简版）

### 5.1 规则

```
输入：系统语言 tag 列表 L（按偏好降序）
1. 对 L 中每个 tag，按 RFC 4647 Lookup 逐级截断（zh-Hant-CN-x-p → zh-Hant-CN → zh-Hant → zh）
2. 取截断后的**主语言子标签**（第一个 '-' 之前，ASCII 小写化）：
   - "zh"            → 中文       → Language::ZhCn
   - 其他任何值       → 英语       → Language::EnUs
3. 全部 tag 都落在 {C, POSIX, 空} → 「无法判定」→ 走 §5.4 默认策略
```

```rust
// 建议签名（纯函数，可单测，不碰真实系统）
pub fn language_from_tags<I, S>(tags: I) -> Option<Language> where I: IntoIterator<Item = S>, S: AsRef<str>;
pub fn detect_system_language() -> Language;   // 内部 = language_from_tags(sys_locale::get_locales()).unwrap_or_default()
```

### 5.3 繁体（Hant）的处理策略

| 选项 | 成本 | 何时选 |
|---|---|---|
| **A. 繁体也显示简体**（本卡默认） | 0 | 需求原文只说「中文系系统显示中文」，可接受 |
| B. Phase 2 新增 `Language::ZhTw` + 繁体翻译包 | 277 条文案再来一套 + 21 处 match 全部要加臂 | 有繁体用户反馈时 |
| C. 繁体回落英文 | 0 | ❌ 不建议：对繁体用户是体验倒退 |

> 若走 B，算法只需在 `zh` 分支内再判脚本子标签（`Hant` / `TW` / `HK` / `MO` → `ZhTw`，其余 → `ZhCn`）。**建议现在就把 `language_from_tags` 写成「返回 `Option<Language>` + 内部独立判定函数」**，将来加变体不必重写调用方。

### 5.4 「无法判定」的默认值（需产品确认）

| 候选 | 理由 | 风险 |
|---|---|---|
| **保持现状 `ZhCn`（推荐）** | 本仓默认值/主要用户群是中文 Black MIDI 社区；`LANG=C` 下把中文用户切成英文，是**主动制造回归** | 无（行为与今天一致） |
| 一律 `EnUs` | 「无信息即国际化默认」的通行做法 | 容器/CI/SSH 场景下中文用户被误切英文 |

> 折中规则（推荐落地）：**列表非空且含任一非 `C`/`POSIX` 的 tag → 按 §5.1 判定；列表为空或只含 `C`/`POSIX` → 用 `Language::default()`（ZhCn）。**

## 6. 方案对比与推荐

### 6.1 方案 A：给 `Language` 加第三个变体 `System`（❌ 不推荐）

- **打断 21 处 exhaustive `match`**（编译器会全部报错，这是可控的，但要逐个补语义）：

| 文件 | 处数 |
|---|---|
| `crates/tools/extras/src/i18n/format.rs` | 6 |
| `crates/editor/ui-core/src/sidebar_event/group.rs` | 4 |
| `crates/editor/ui-core/src/sidebar_event/route.rs` | 4 |
| `crates/editor/ui-settings/src/pages/audio/types.rs` | 3 |
| `crates/core/core/src/types.rs`（`Display`） | 1 |
| `crates/tools/extras/src/i18n/locale.rs` | 1 |
| `crates/tools/extras/src/i18n/settings.rs` | 1 |
| `crates/editor/ui-core/src/button_descs.rs` | 1 |
| **合计** | **21** |

- **语义污染**：`System` 不是一种「可以查表的语言」，每个 `match` 都得写 `System => 用解析后的语言`，等于把「偏好」和「生效值」混在一个类型里，且 `config.json` 会存进 `"system"`。
- 唯一优点：类型上强约束。**但代价大于收益**。

### 6.2 方案 B：偏好与生效值分离（✅ 推荐）

```rust
// 新增（crates/core/core/src/storage/config.rs 或 core 新增 locale.rs）
#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize, Default)]
pub enum LanguagePreference {
    #[default] #[serde(rename = "system")] System,
    #[serde(rename = "fixed")]   Fixed(Language),
}

// UiConfig 新增字段（**不是**改 language 的类型）
#[serde(default)]
pub language_preference: Option<LanguagePreference>,   // None = 老配置，见迁移矩阵
// language: Language  ❌ 不动：它永远是「已解析的生效值」，95 处引用零改动
```

**解析点**（`src/storage/config.rs::ConfigWrapper::new`，`language` 首次被读之前）：

```
language = match (existed, language_preference) {
    (false, _)                              => detect_system_language(),            // 全新安装：跟随系统
    (true,  Some(System))                   => detect_system_language(),            // 用户选了跟随系统
    (true,  Some(Fixed(l)))                 => l,                                    // 用户显式选择
    (true,  None)                           => inner.ui.language,                    // 老配置：保留（见下）
};
```

**迁移矩阵**（本卡最容易埋雷的地方）：

| 场景 | 配置现状 | 行为 | 说明 |
|---|---|---|---|
| 全新安装 | 无 config.json | 跟随系统 | `existed == false`（`src/storage/config.rs:15` 现成标志） |
| 老用户，从未改过语言 | 有文件、`language` 字段可能缺失或有 `"zh-CN"` | **保留**现有值 | ⚠️ 无法区分「系统自动填的」与「用户选的」，**保守不覆盖** |
| 老用户，手动选过英文 | `"language": "en-US"` | 保留英文 | ✅ 用户选择不丢 |
| 用户首次打开设置页 | — | 面板显示「跟随系统」 | 一旦他改成固定语言，写 `Fixed(l)` |
| 老配置出现语言切换行为 | — | 不变 | 想修「老配置卡在中文」的日本用户，可经 §6.4 覆盖或手动切一次（**建议在设置页加一句提示**） |

> 可选增强（P2，需产品拍板）：老配置且 `language == "zh-CN"` 且检测结果非中文时，**一次性**弹提示「检测到系统语言为 X，是否切换界面语言？」——比静默改写安全，比不处理友好。

**设置面板 UI**：`Language::all()` 是 `[Language; 2]`，`pick_list` 需要 `Clone + PartialEq + Display`。**已有现成范式**：同文件里的 `LocalizedNoteCountDisplay`（`crates/editor/ui-settings/src/pages/ui_settings.rs:19-49`）就是「配置值 + 本地化显示名」的包装类型——照抄它写 `LanguageOption { System, Fixed(Language) }` 即可，`Change` 事件走新增的 `Event::LanguagePreferenceChanged(...)`（`ui-core/src/settings_event.rs` 加一个变体）或复用 `LanguageChanged` + 一个布尔开关（checkbox 范式见同文件 `:121-134`）。

### 6.3 方案 C：只改 serde 默认值（最小改动，仅作降级）

```rust
#[serde(default = "lumino_core::locale::detect_system_language")]  // 需要 core 依赖 sys-locale
pub language: Language,
```

- ✅ 约 3 个文件改完，首次启动就能跟随系统。
- ❌ **给不出「跟随系统」选项**（选择器只有两态，选了就永久固定）。
- ❌ **老配置一旦落过盘就再也回不到自动**（`"zh-CN"` 与「用户选的简体中文」不可区分）——即 §6.2 迁移矩阵里的雷，方案 C 无法拆。
- 适用：只想最小验证检测逻辑是否工作。

### 6.4 覆盖优先级（建议实现）

```
LUMINO_LANG 环境变量（新增，便于 CI/无 GUI 排障/罕见系统）
  > config.ui.language_preference = Fixed(l)
    > detect_system_language()
```

`LUMINO_LANG` 需要一个 `Language::from_tag(&str) -> Option<Language>`（复用 §5.1 的同一函数）——顺带把 §3.1「无 FromStr」这个洞补上。

## 11. 复现命令

```powershell
# ① Windows 系统语言实测（本报告 §4.1 的数据来源）
#    注意：StringBuilder 会在首个 NUL 截断，必须用 IntPtr 手工解码才能看到完整列表
$cs = @"
using System; using System.Text; using System.Runtime.InteropServices;
public class Mui2 {
  [DllImport("kernel32.dll", CharSet=CharSet.Unicode, SetLastError=true)]
  static extern bool GetUserPreferredUILanguages(uint dwFlags, out uint pulNumLanguages, IntPtr pwszLanguagesBuffer, ref uint pcchLanguagesBuffer);
  const uint MUI_LANGUAGE_NAME = 0x8;
  public static string Preferred() {
    uint num = 0, len = 0;
    GetUserPreferredUILanguages(MUI_LANGUAGE_NAME, out num, IntPtr.Zero, ref len);
    var p = Marshal.AllocHGlobal((int)len * 2);
    try {
      if (!GetUserPreferredUILanguages(MUI_LANGUAGE_NAME, out num, p, ref len)) return "ERR";
      var b = new byte[len * 2]; Marshal.Copy(p, b, 0, b.Length);
      var list = new System.Collections.Generic.List<string>();
      foreach (var x in Encoding.Unicode.GetString(b).Split('\0')) if (x.Length > 0) list.Add(x);
      return "[" + string.Join(", ", list) + "] num=" + num;
    } finally { Marshal.FreeHGlobal(p); }
  }
}
"@
Add-Type -TypeDefinition $cs -Language CSharp
[Mui2]::Preferred()                     # 本机 → [zh-CN, en-US] num=2
Get-WinUserLanguageList | % { $_.LanguageTag }   # 本机 → zh-Hans-CN, en-US, en-CA
(Get-Culture).Name; [System.Globalization.CultureInfo]::CurrentUICulture.Name

# ② sys-locale 已在依赖图内（§1 #3）
cargo tree -i sys-locale --workspace

# ③ cosmic-text 真的在启动时调 sys-locale（§3.4 依赖链）
#    见 %USERPROFILE%\.cargo\registry\src\*\cosmic-text-0.15.0\src\system.rs:384

# ④ 硬编码中文扫描（§7 的口径）
Get-ChildItem crates\editor,src\runner -Recurse -Include *.rs -File |
  Where-Object { $_.FullName -notmatch '(?i)test|bench' -and $_.Name -notmatch '(?i)zhcn|enus|translations\.rs' } |
  ForEach-Object {
    $n = 0; $inTest = $false
    foreach ($l in (Get-Content $_.FullName)) {
      if ($l -match '^\s*#\[cfg\(test\)\]') { $inTest = $true }
      if ($inTest -or $l -match '^\s*//') { continue }
      if ($l -match 'tracing::|debug!|warn!|error!|info!|trace!|assert|panic!|expect\(') { continue }
      if ($l -match '"[^"]*[\u4e00-\u9fff][^"]*"') { $n++ }
    }
    if ($n -gt 0) { [pscustomobject]@{ File = $_.FullName; Count = $n } }
  } | Sort-Object Count -Descending

# ⑤ 映射算法原型（§5.2 的 30 条表）
function Resolve-Language([string]$tag) {
  if ([string]::IsNullOrWhiteSpace($tag)) { return 'unknown' }
  $t = $tag.Trim().Replace('_','-')
  if ($t -match '^(?i)(C|POSIX)$') { return 'unknown' }
  if ((($t -split '-')[0]).ToLowerInvariant() -eq 'zh') { return 'ZhCn' }
  return 'EnUs'
}
@('zh-CN','zh-Hans-CN','zh-Hant-TW','zh-Hant-HK','zh-Hans-MO','zh-Hant-MO','ja-JP','ko-KR','en-US','de-DE','C','') |
  ForEach-Object { "{0,-16} -> {1}" -f $_, (Resolve-Language $_) }
```
