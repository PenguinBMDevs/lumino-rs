# wgpu 30 统一迁移：调研与规划

> 状态：P0 已通过（3/3 位精确），待继续 P1–P5
> 日期：2026-11-28
> 目标：`wgpu 30.0.1` + `naga 30.0.1` + 官方 `egui-wgpu 0.37`，删除 `lumino-egui-bridge`
> 结论：技术可行；P0 位精确验证已通过，剩余风险为帧错误模型与 egui 渲染器收口

## 一、结论摘要

1. **双版本共存已确认**：主程序全链路是 `wgpu 27.0.1 / naga 27.0.3`；
   `wgpu 30.0.1 / naga 30.0.1` 只由 `egui_kittest 0.37 → egui-wgpu 0.37` 带进测试图。
   同一份 `Cargo.lock` 里两套 `wgpu-core/hal/types` 并存，二进制体积与编译时间都在付双份成本。
2. **旧计划的阻塞前提已经失效**：`docs/2026-11-06-egui-ui-rewrite-execution-plan.md`
   §二 的执行发现建立在「iced_wgpu 与 gfx 共用同一个 `Device`」之上。当前 `Cargo.lock`
   已无任何 `iced*` 包，主程序是 egui + gfx 共用 `Device`（`crates/editor/ui/src/host/render_ctx.rs`）。
   因此不再需要「先做 27 桥接、后整体升 30」，桥接 crate 应在本次迁移中直接删除。
3. **升级不是纯机械替换**，有 4 类必须写代码的变更：
   `Surface::get_current_texture` 枚举化 + `SurfaceError` 删除、`Buffer::get_mapped_range` 返回 `Result`、
   `InstanceDescriptor` 构造方式重写、naga 30 对整数跨阶段插值的强制校验。
4. **DSP 只读区不需要改一个字符**：`render.wgsl` / `mix.wgsl` / `mix_reduce.wgsl`
   用 naga 30 全部校验通过；`gpu/layout.rs` 字段集不涉及。但 naga 27→30 的代码生成
   在 `render.wgsl` / `mix.wgsl` 上**有差异**（`mix_reduce.wgsl` 逐字节相同），
   必须用 `hash_render` 做实机位精确门禁后才能继续。
5. **4 个 gfx 着色器会被 naga 30 直接拒绝**：`note.wgsl` / `note_vertical.wgsl` /
   `onion_note.wgsl` / `onion_note_vertical.wgsl` 的 `VertexOutput @location(3) border_width: u32`
   缺少 `@interpolate(flat)`。这是 wgpu 30 的破坏性变更，不是可选清理。

### 2.4 旧计划前提失效

`docs/2026-11-06-egui-ui-rewrite-execution-plan.md` 的 Phase 1 仍写着
「先做 `egui-wgpu 0.37 → wgpu 27` 桥接，UI 替换完成后再整体升 30」。
当前事实：

- `Cargo.lock` 中 `iced*` 包为 0；
- `lumino-ui` 生产路径已是 `egui + lumino-egui-bridge + lumino-gfx` 共用设备；
- 因此桥接只在「iced 仍参与渲染」时有必要，现在它是一笔可以直接删除的临时债。

## 三、27 → 30 破坏性变更核对表

> 来源：`wgpu` v30.0.1 仓库 `CHANGELOG.md`（v28/v29/v30 三节），
> 以及本机 registry 中 `wgpu-27.0.1` 与 `wgpu-30.0.1` / `wgpu-types-*` 源码逐字段比对。
> 下表「处」为本仓库实际命中数（`rg` 统计）。

### 3.1 A 类：结构与语义变更（必须改代码）

| # | 变更 | 影响面 | 处理要点 |
|---|---|---|---|
| A1 | `Surface::get_current_texture` 返回 `CurrentSurfaceTexture` 枚举；`SurfaceError` 删除；`SurfaceTexture::present()` → `Queue::present()`；`suboptimal` 字段变 `Suboptimal(frame)` 变体 | 2 个调用点 / 5 文件（含注释与错误类型）；`SurfaceError` 32 处 / 5 文件 | `OutOfMemory` / `Other` 在 30 没有对应变体，必须新建内部帧错误枚举；`acquire_frame` 的 Android 重试、`frame_error::classify_frame_error`、`device_status` 注释与测试同批重写 |
| A2 | `Buffer::get_mapped_range*` 返回 `Result<_, MapRangeError>` | 32 处 / 24 文件 | 读回路径必须是 `?` 传播，禁止 `expect`；`gpu-synth/synth/engine/readback.rs` 属 DSP 自主区，需保持 `unwrap_used = deny` |
| A3 | `Instance::enumerate_adapters` 变 `async` | 4 处命中 / 3 文件 | `device_check` 同步诊断入口需改 async 或在调用点 `block_on`；注意不得在音频回调/渲染线程阻塞 |
| A4 | `InstanceDescriptor` 删除 `Default` / `from_env_or_default`，新增 `display` 字段；`Instance::new` 改传值 | 15 处 / 15 文件 | 无窗口句柄场景用 `InstanceDescriptor::new_without_display_handle_from_env()` 再覆写 `backends/flags`；`Instance::new(desc)` |
| A5 | `StagingBelt::new(device, chunk)`；`write_buffer` 去掉 `device` 参数 | 1 + 4 处（gpu-synth） | 设备所有权前移到 belt 构造 |
| A6 | `push_error_scope` 返回 `ErrorScopeGuard` | 1 处（测试） | `let scope = ...; scope.pop().await` |
| A7 | `Limits::max_storage_buffer_binding_size` / `max_uniform_buffer_binding_size` u32 → u64 | gpu-synth 5 处（含测试）；gfx 多处 `as u64` 仍可编译 | 常量 `DESIRED_STORAGE_BINDING_SIZE` 同步为 u64，避免 `min` 类型不匹配 |
| A8 | `BufferSlice::size()` 返回 `u64`（原 `NonZeroU64`），空 slice 合法；`BufferBinding` 改 `TryFrom` | 0 处直接命中 | 以后新增空 slice 绑定会在 `TryFrom` 失败，需在封装层显式处理 |

### 3.2 B 类：机械字段/类型变更（编译器逐条报错）

| # | 变更 | 处数 | 备注 |
|---|---|---:|---|
| B1 | `RenderPassDescriptor` 新增 `multiview_mask: Option<NonZeroU32>` | 35 / 22 文件 | 全部填 `None` |
| B2 | `RenderPipelineDescriptor::multiview` → `multiview_mask` | 6 | 同上 |
| B3 | `PipelineLayoutDescriptor`：`bind_group_layouts: &[Option<&_>]`，`push_constant_ranges` → `immediate_size: u32` | 9 | 本项目全部 `push_constant_ranges: &[]` → `immediate_size: 0` |
| B4 | `VertexState::buffers: &[Option<VertexBufferLayout>]` | 5 | 空布局仍是 `&[]`；有布局要 `Some(...)` |
| B5 | `DepthStencilState::depth_write_enabled/depth_compare` → `Option<_>` | 8 + 断言 4 | 仅模板测试的管线用 `None`；写深度用 `Some(true)` |
| B6 | `SamplerDescriptor::mipmap_filter` → `MipmapFilterMode` | 4 | 与 `min/mag_filter` 的 `FilterMode` 分离 |
| B7 | `SurfaceConfiguration` 新增 `color_space` | 1 真实构造 | 用 `SurfaceColorSpace::Auto` 保持历史行为；`get_default_config` 自动带出 |
| B8 | `RequestAdapterOptions` 新增 `apply_limit_buckets` | 9 | 保持 `false`，不要顺手启用分桶（会改变 limits） |
| B9 | `AdapterInfo` 新增 `device_pci_bus_id/subgroup_*/transient_saves_memory/limit_bucket` | 只读 | 不构造即不破坏 |
| B10 | `IndexFormat::byte_size` 返回 u32；`TextureUsages::TRANSIENT` → `TRANSIENT_ATTACHMENT`；`CLIP_DISTANCE` → `CLIP_DISTANCES` | 0 | 本项目未使用 |
| B11 | `Features`/`ExperimentalFeatures` 仍存在（子结构 `FeaturesWGPU/FeaturesWebGPU`），`Features::empty/default` 可继续用 | — | 已核对 `wgpu-types-30.0.1/src/features.rs`、`tokens.rs` |

### 3.3 C 类：WGSL / naga 30（已实测）

wgpu 30 的 WGSL 规则变化：

- 整数跨阶段 I/O 不再自动 `flat`，必须显式 `@interpolate(flat)`；
- `@builtin(primitive_index)` 需 `enable primitive_index;`；
- `@builtin(view_index)` 类型变 `u32`；
- `enable` 指令指向不可用能力会直接拒绝。

本仓库实测（naga 30.0.1 `Validator` + `Capabilities::all()`）：

| 结果 | 文件 |
|---|---|
| **校验失败（4）** | `gfx/src/shaders/note.wgsl`、`note_vertical.wgsl`、`onion_note.wgsl`、`onion_note_vertical.wgsl`（均为 `VertexOutput @location(3) border_width: u32` 缺 `@interpolate(flat)`） |
| 校验通过（24） | 其余全部，含 DSP 三件套 `render.wgsl` / `mix.wgsl` / `mix_reduce.wgsl` |

代码生成对比（同一份源码，naga 27.0.3 vs 30.0.1，SPIR-V/HLSL/MSL 三后端）：

| 着色器 | SPIR-V | 结论 |
|---|---|---|
| `mix_reduce.wgsl` | **逐字节相同** | 无风险 |
| `render.wgsl` | 6152 → 6279 words，差异首行是新增局部 `float _e34 = acc;` | 多出临时变量与拷贝，算术顺序需运行时确认 |
| `mix.wgsl` | 2778 → 2916 words，新增 `bool local` 等 | 同上 |
| `texture_waterfall.wgsl` | 相同（仅 MSL 复合字面量多一层花括号） | 无风险 |

**不能仅凭静态差异判定位精确**：多出的临时变量若只是拷贝，浮点结果不变；但 `render.wgsl`
的采样/混音循环是位精确验收的核心，必须以 `hash_render` 实机哈希为准。见 §五 Phase 0。

### 3.4 D 类：egui 渲染器收口

`egui-wgpu 0.37` 的 `Renderer` 与临时桥接的差异：

| 能力 | 临时桥接 `lumino-egui-bridge` | 官方 `egui-wgpu 0.37` |
|---|---|---|
| 构造 | `Painter::new(&device, format)` | `Renderer::new(device, format, RendererOptions)` |
| 纹理 | `update_textures(device, queue, &mut delta)` | `update_texture(device, queue, id, delta)` 逐项 |
| 顶点/索引 | 每帧重建 | `update_buffers(...) -> Vec<CommandBuffer>` |
| 绘制 | `render(&mut RenderPass<'_>, Screen)` | `render(&mut RenderPass<'static>, &ScreenDescriptor, jobs)` |
| 清屏 | `Screen.clear` 内置 | 调用方建 pass 时给 `LoadOp::Clear` |
| 可预测采样 | 固定四抽头 + `PREDICTABLE` 等价 | `RendererOptions::PREDICTABLE` |

迁移要点：

1. `ui/src/host/render/egui_overlay.rs` 与 `ui-runtime/src/app/state.rs` 是仅有的两个消费者；
   `ui-egui/tests/bridge_parity.rs` 在桥接删除后失去对象，应改为官方 renderer 的
   kittest 对比或删除。
2. `render` 要求 `RenderPass<'static>`，需要 `pass.forget_lifetime()`，并保证
   `update_buffers` 在 `render` 之前、同一个 encoder 内。
3. 桥接里的 `clear` 参数移到调用方的 `RenderPassColorAttachment::ops`，
   像素基线必须重跑（sRGB 目标下 clear 位置不同会改变首帧边缘像素）。
4. 官方 renderer 的纹理格式约束与桥接一致（`Rgba8Unorm` 图集），
   但 `PREDICTABLE` 必须显式开启，否则 dithering 会让基线差 1。

## 五、最高风险：LGS 位精确性（Phase 0 必须先做）

### 5.1 为什么必须先做

`AGENTS.md` 的 DSP 验收模型要求 **bit-exact + 正确听感 + 块大小无关**。
wgpu 版本变化会改变 naga 代码生成（§3.3 已证实 `render`/`mix` 的 SPIR-V 有差异），
而 `hash_render` 是唯一能自动判定「输出是否仍然逐样本一致」的 oracle。
如果先做完全部 API 迁移再发现哈希变化，回滚成本会覆盖整个分支。

### 5.2 Phase 0 步骤（约 0.5–1 人日）

1. 在 `dev`（wgpu 27）上构建基线并留档：
   ```bash
   cargo build --release -p lumino-gpu-synth --example hash_render
   copy target\release\examples\hash_render.exe test-file\bench\hash_render_wgpu27.exe
   ```
2. 在 `feat/wgpu30` 分支只修 `lumino-gpu-synth`（14 个错误）与 `naga = "30.0"`，
   不动 gfx/ui；`cargo build -p lumino-gpu-synth --example hash_render` 可以独立成立
   （gpu-synth 不依赖 gfx）。
3. 构建 `hash_render_wgpu30.exe`，同一台机器、同一驱动、同一 MIDI/SF2 夹具下对比：
   ```bash
   python scripts/lgs_ab.py --baseline test-file/bench/hash_render_wgpu27.exe \
       --after target/release/examples/hash_render.exe --all
   ```
4. 判定：
   - **逐字节一致** → 继续全量迁移，`hash_render` 作为后续每个阶段的回归门；
   - **有差异** → 停止实现，按 `AGENTS.md` §4 提交「DSP 只读申请」：
     列出差异样本、量化差值、给 A/B 试听段落，由用户决定接受或改用其他 wgpu 版本。

### 5.3 已知观察（供 Phase 0 参考）

- `mix_reduce.wgsl` 的 SPIR-V 逐字节相同，说明归约路径风险最低；
- `render.wgsl` 的差异首行是 `float _e34 = acc;`，属于「多一次拷贝」而非「换算式」，
  但 `render.wgsl` 内含采样与包络，必须实测；
- `mix.wgsl` 新增 `bool local` 临时量，理论上不触碰浮点；仍需实测。

## 六、迁移策略

### 6.1 不能按 crate 逐个合并

`lumino-gfx` 的 `RenderContext`/`WgpuResources` 把 `wgpu::Device/Queue` 暴露给
`lumino-ui` 与 `egui_overlay`；单边升级会让同一个 `Device` 出现两种类型，无法编译。
因此 `gfx + ui + ui-runtime + egui-bridge` 必须同批切换。

`gpu-synth` / `midiplayer` 没有共享设备，可以先行（Phase 0 正是利用这一点）。

### 6.2 推荐提交序列（单分支、分段提交、合并前全绿）

| 阶段 | 内容 | 可独立验证 |
|---|---|---|
| P0 | 基线二进制 + gpu-synth 单独升级 + `hash_render` 对比 | 位精确哈希 |
| P1 | 依赖升 30 + A 类重写（gfx 帧错误、读回、实例/适配器） | `cargo check -p lumino-gfx` |
| P2 | B 类机械字段（gfx/ui/gpu-synth/midiplayer/ui-runtime） | 全 workspace check |
| P3 | 4 个 WGSL 加 `@interpolate(flat)` + GPU 基线 | 像素基线 |
| P4 | `egui-bridge` → 官方 `egui-wgpu`，删除 crate | 像素基线 + 真实窗口 |
| P5 | 测试/基线/文档收口，全量 nextest | CI 等价 |

> 为什么 P3 单独：4 个 shader 的改动会改变顶点输出插值属性，
> 必须与「纯 API 迁移」分开提交，便于二分定位视觉回归。

### 6.3 分支与回滚

- 分支：`feat/wgpu30`；`dev` 在合并前保持 27，随时可发布。
- 每个阶段末尾保留可运行的 `hash_render` 与 GPU 基线证据；
- 若 P0 哈希不一致：整分支作废，不留半迁移状态；
- 若 P3 像素基线不一致：回滚该提交，API 迁移可保留。
