# UI-017：框选精度全局统一（钢琴卷帘框选 X 向量化 + 边界命中防误选）

> 记录日期：2026-09-30 ｜ 分支：`81-ui-017框选精度全局统一卷帘框选-x-向量化-边界命中防误伤改动范围已收敛`
> 关联：与走带框选口径（`arrangement::interaction::geometry`）、文字工具框（生成框）刻意区分，见「口径台账」

## 背景

钢琴卷帘框选（marquee）X 向此前使用鼠标**原始 tick**（全精度），不跟随工具栏「音符精度」：
低精度模式下框缘判定不可预测，与用户按格思考的边界不一致。同时框选命中使用**闭区间**，
恰好贴在框边界上的音符也会被选进来。

## 设计取舍（评审已签字）

### 1. 量化语义 = **单元覆盖式**（整格覆盖）

**选框 = 鼠标触碰过的全部 `snap_precision` 单元。**

- 按下记录**锚点单元低边** `A = floor(press / p) * p`；
- 拖动期间两端由 `(A, 鼠标 tick)` 统一推算：
  - 右拖 → `(A, floor(m) + p)`
  - 左拖 → `(A + p, floor(m))`
- 因此**两端恒落格线**、**方向保持**（左拖 `start > current`，供 Spring 动画按移动端驱动）、
  **锚点固定可回缩**（向左拖再拖回右侧不会单向扩张）。

否定方案与理由：

| 方案 | 否决理由 |
|---|---|
| 单侧 `snap_tick`(floor) 刷两端（原卡方案） | 大端内缩 → 框内重叠音符**漏选**；小端反向拖动时外扩**整整一格** → 选中鼠标从未扫过的音符。即 `tests/selection_precision.rs` 记录过的历史坑（曾用 `snap_tick_forward` / floor） |
| 两端 round（最近格线） | 外扩半格且会向内缩；鼠标扫过但未跨格的音符会**漏选**，违反「重叠即选中」 |
| 两端 ceil/floor 向内收缩 | 1/4 精度下 press 2200 → drag 5000 会得到**空框**，不可用 |

**固有代价（已确认接受）**：按下点所在格整体参与选中；音符未对齐格线时（如导入 MIDI）
命中会比鼠标位置提前最多一格。对格线对齐音符，本方案与「精确跟随」的判定翻转点重合
（均为 `m = T`），行为等价——即**量化交付的是口径统一与边界可预测，不减少框缘误选**；
误选由下述第 2、3 项修复。

### 2. 命中口径 = tick 轴**半开**、key 轴**闭**

- tick 轴 `[min_tick, max_tick)`：起点恰等于框右边界、终点恰等于框左边界的音符**不入选**
  （低精度下防框缘误选）；跨边界且有内部交叠的长音符**仍入选**；
- key 轴 `[min_key, max_key]`：`key` 是离散格，「整格覆盖」语义，且增量差集
  （`rect_subtract`）的 key 代数依赖闭区间。

`drag::selection::marquee_hits` 收敛为**全项目框选口径唯一来源**；索引路径与无索引窗口
兜底两条路径必须同口径，防「工程规模不同 → 框选结果不同」的口径分裂。

### 3. **不改共享原语** `NoteSpatialIndex::update_query`

框选需要半开，但 `update_query` 是共享原语，且**闭区间是有意为之**：

- `impls/playback.rs` 以 `update_query(tick, tick, 0, 255, ..)`（零宽区间）取播放头**活跃**
  音符，半开化会漏掉起点恰在播放头的音符 → 起播瞬间第一个音符不高亮；
- `rendering/visible_notes.rs` 以视口边界裁剪，闭区间避免边界音符漏渲染。

因此新增**框选专用入口** `update_query_marquee`（遍历骨架以 const generic 携带口径参数，
两种口径各自单态化，热路径无额外分支），并在 `update_query` 文档中写明「禁止半开化」。

## 卡片条目修订（评审签字 2026-09-30）

| 原卡片条目 | 修订为 | 理由 |
|---|---|---|
| 「i2m 框选保持原始精度不量化（豁免）」 | **「i2m 框选与卷帘同口径（单元覆盖式）」** | 代码事实：i2m 起点**早已**被 `snapped_tick`(floor) 量化（`i2m.rs` 构造点 + `image_to_midi.rs` 注释「X 向 snap」），**终点却是鼠标原始 tick** —— 本就是「一端量化一端精确」的混合口径。豁免会保留该分裂；统一后两端同源，且与 i2m 自身「X 按精度 snap」的设计意图一致。影响：区域框终点从任意 tick 变为格线，生成音符与预览宽度按精度步进 |
| 「为何 floor 而非 round：floor 只把框边界向内收缩，永不外扩」 | **删除该论断** | 事实错误：floor 作用在小端是**外扩**（反向拖动外扩一格）。正解为「小端覆盖单元低边、大端覆盖单元高边」的成对量化 |
| 「吸收/收敛改动范围至 4 个文件」 | **实际 19 文件** | 卡片漏了主命中路径（`note-core/spatial_index.rs`）、第三条框选链路（文字工具）、Spring 动画目标、i2m 构造点 |

## 口径台账（本卡决策项，未纳入统一）

| 链路 | 量化 | 语义 | 处置 |
|---|---|---|---|
| 指针 / Y 向 / 橡皮擦 Shift 框选 | 单元覆盖式 | **查询框** | 本卡统一 |
| i2m 区域框选 | 单元覆盖式 | 生成框 | 本卡统一（见上表） |
| 文字工具框选 | round（`snap_precision`） | **生成框**（边界即生成音符位置） | 刻意保留；两处注释写明判据 |
| 走带框选 `geometry::snap_tick` | round + 拍号感知 | 查询框 | **保持现状**；`tests/arrangement_snap_ledger.rs` 测试固化，改动即变红（`snap_tick` 有多个共享调用方，统一前需先梳理调用链） |
| 音符拖动 / 拉伸首尾 | delta round / 绝对 floor | — | 本卡未改，符合既有双原语规则 |

**判据（供后续新增交互二选一）**：边界会成为**产物**的框必须量化（round 语义）；
边界只用于**查询既有音符**的框按「单元覆盖式」量化，且命中用半开区间。
