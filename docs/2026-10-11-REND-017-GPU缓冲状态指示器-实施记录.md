## 一、决策记录（评审拍板）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 指示器位置 | **状态栏**（右侧指标组，CPU/MEM/FPS 左侧） |
| 2 | 未播放时 | **也显示**（GPU 渲染线程常开、数据真实；直接服务「编辑时也感觉迟钝但无法判断」的排障诉求） |

## 二、实现链路（9 成是接线，全部无锁）

```
PlaybackStatsReader（gpu-synth，已存在）
  → GpuBufferStats::snapshot（新增：queue_ms 换算 + 瞬时/短窗负载）
  → SynthControl::gpu_buffer_stats()（midi-io 扩展能力，默认 None；仅 Lgs 覆写）
  → MidiManager::gpu_buffer_stats()（runner 直通）
  → RunnerInner::tick_gpu_buffer_status（250ms/4Hz 节流）
  → Host::set_gpu_buffer_status（变更为准标脏）
  → StatusBar GPU 组（Q/LOAD/V/UR + 异常时 GOV/DROP）
```

### 1. gpu-synth（数据层）

- `PlaybackStatsReader` 新增 `samples_per_second`（**交错样本/秒 = 计数速率 × 声道数**；
  重采样时按设备率、否则引擎率——`start.rs` 构造时确定）。队列毫秒换算必须走这个口径，
  Lgs/UI 侧拿不到双率与声道信息，不要重复推导。
- `STATS_RING` 128 → **1024**（8KB/实例）：支撑 3 秒短窗。默认配置 512@64k 一块 8ms，
  3 秒 = 375 块；旧 128 环只能覆盖约 1 秒。
- 新增 `average_renderer_load_window(window)`（取最近 k 个已填充样本）；旧
  `average_renderer_load()` 改为全环口径委托（此前无消费方，口径变化无影响）。
- 新增 `GpuBufferStats`（pub, Copy, Default, PartialEq）与 `snapshot(window_samples)`；
  队列负值（渲染落后）毫秒钳 0、原始值保留在 `queue_samples`。

### 2. midi-io（暴露层）

- `SynthControl::gpu_buffer_stats()` 默认 `None`（REND-002 能力扩展机制，Kdmapi/System/XSynth
  零改动）；`lib.rs` 转出 `GpuBufferStats`。
- `Lgs` 新增 `stats: PlaybackStatsReader` 字段：`new()` 与 `set_midi_port_layout` 的
  **Rebuild 分支**（整体重建 `AudioPlayback`）两处刷新；`lgs/stats.rs`（新文件）承载
  3 秒→样本数换算 `load_window_samples(block_size, sample_rate)` 与快照打包。
- 选型记录：**轮询快照**而非把 reader 句柄一次性交给 UI——端口布局重建会替换
  `AudioPlayback`，句子柄必然冻结失效且需补重推点；轮询经最新 `self.api` 现场读天然免疫，
  也免去 PlaybackFrame 热结构改动。

### 3. runner + UI 通道

- `RunnerInner::gpu_stats_last_poll`（`inner.rs`）＋ `GPU_STATS_POLL_INTERVAL = 250ms`；
  `handle_midi_reinit`（每帧 about_to_wait）尾部调用。
- `Host::set_gpu_buffer_status`：快照有变化才 `mark_dirty`（静息不空转重绘）。

### 4. 状态栏指示器（UI）

- 格式：`GPU  Q 248ms→  LOAD 63%  V 512  UR 0`；异常时追加 `GOV 2` / `DROP 12`。
- 颜色分级（纯函数 + 单测）：LOAD <60% 常规 / 60–90% warning / ≥90% danger；
  UR >0 danger；GOV 1=warning、≥2=danger；DROP >0 danger。
- LOAD 取数按设置：`ShortAverage → average_render_load`，`Instant → render_load`。
- 显示门控：总开关关 / 快照为 None（非 LGS、后端未就绪、重建窗口）→ 整组隐藏。

### 5. 设置链路（三层字段，全部纯显示、不重建后端）

- `UiConfig`：`gpu_buffer_status_enabled`（默认 true）、`gpu_governor_metrics_enabled`
  （默认 true）、`gpu_load_display: GpuLoadDisplay`（默认 `ShortAverage`）；
  旧配置缺字段回落默认（单测锁定）。
- `SynthSettings`（ui-settings）+ `Event::{GpuBufferStatusEnabledChanged,
  GpuGovernorMetricsEnabledChanged, GpuLoadDisplayChanged}` + `panel.rs` 分发。
- LGS 设置页：两个 Checkbox + 一个 pick_list（`LocalizedGpuLoadDisplay` 本地化包装）。
- 持久化：`persist.rs` 进 `other_changed` 与 `patch`，**明确不进 `lgs_changed`、不
  `mark_for_reinit`**（改开关不会重建合成器）。

## 五、遗留与说明

1. **真机复验项**（两项验收）需在实际 LGS 播放（如 Bad Apple 8.49M）下执行：
   观察 Q 深度随渲染抖动、UR 在过载时的增长、GOV/DROP 与 `[GOVERNOR]` 日志同步；
   并分别验证 LOAD 两口径（瞬时抓尖峰 / 3 秒平均稳定）与开关持久化。
2. **`flush_epoch` 死代码发现**（不在本卡范围）：`start.rs` 的过载重同步清队列机制
   在 `7bb878b9`（REND-016 改「宁糊不切」）后无任何递增点——该路径永不触发，
   不影响本卡指标准确性；是否清理由 REND-016 owner 后续裁决。
3. **极端小块配置的 3 秒窗封顶**：block=64（1ms/块）时 3 秒需要 3000 样本，被环容量
   1024 夹紧到约 1 秒（`lgs/stats.rs` 注释已注明）；常见配置（256–1024 块）不受影响。
4. 队列以毫秒整数显示（量程 0–600ms；容量按时间封顶 32ms–600ms，默认配置 256ms）；
   分辨率已对齐数据源极限（回调按块/段消费，个位数毫秒粒度），颜色与趋势承担危险度表达。
