## 一、改动总览

| 项 | 落点 | 说明 |
|---|---|---|
| **按轨写回（核心）** | `editor-state/.../async_commit.rs` | `PendingCommit` 新增 `track_id`（`apply_move_ops_async` 启动时捕获）；`poll_async_commit` 的整轨替换、脏标记、历史全部按**发起轨**执行，绝不使用 `current_track`。已切轨时不发旧索引段内事件，改按单轨 `Delta` 标脏 |
| 切轨守卫（止血） | `ui-editor/src/track.rs` | 新增 `has_pending_commit()`；`switch_to_track` 在异步提交窗口内拒绝切轨并告警 |
| 切轨守卫（Runner 兜底） | `src/runner/menu/file.rs` | `TrackSelected` 事件处理先查 `has_pending_commit`，命中则忽略（Runner 直调 `set_current_track` 绕过了 UI 守卫） |
| **超时降级** | `ui-editor/src/impls/editor_impl/commit.rs` | `drain_async_commit` 增加 30s 墙上时钟上限：超时 → 日志 + `cancel_async_commit` + 清 pending_drag + `mark_notes_changed`，绝不再无限 `yield_now` 自旋占核 |
| MoveOp 回滚/计数 | `editor-state/.../history/ops.rs` | 插入失败（返回 0）时回插已删音符；删除集合显式记录 `deleted_notes`；恒真表达式 `deleted.min(inserted.max(deleted))` 改为 `modified += deleted` |
| 跨轨移动钳制 | `ui-editor/src/arrangement_ops/move_notes.rs` | `dest_visual` 钳制到 `[0, track_count-1]` 并过滤无效文档轨；旧实现越界时 `unwrap_or(dest_visual)` 指向不存在的轨 → `insert_note` 失败被忽略 → 静默丢音 |
| Razor 回滚 | `ui-editor/src/arrangement_ops/razor.rs` | 先校验目标轨存在；两个 `insert_note_with_id` 结果检查；失败回插原音符、`continue`（不计 split_count、不广播同步条目） |
| 粘贴计数 | `ui-editor/src/clipboard/paste.rs`、`paste_interop.rs` | 以 `batch_insert_notes_to_track_with_ids` 返回的实际条数为准计数/选择冻结/协作广播；目标轨不存在时跳过并告警（消除"显示已粘贴 N"与对端幻影音符） |
| **gfx grow 早退** | `gfx/src/gpu_note_buffer/internal.rs`、`ops/upload.rs` | `grow` 在 `required > max_capacity` 时显式返回 false；`upload_all` 丢弃返回值改为检查并早退（旧实现向旧的小 buffer 全量写入 → wgpu 校验错误风险） |

## 四、遗留与说明

- **性能批未做**（selection O(n²)、走带写路径全扫、`push_update_range` O(start) 等）：
  卡内约定"独立提交"，待后续小卡/提交处理；
- MoveOp 回滚分支为**防御性**：同一 `track_id` 下删除成功则插入必然成功
  （`batch_insert_notes` 仅空输入/轨不存在返回 0），难以构造自动化用例，已加注释；
- `GpuNoteBuffer::grow` 的前置守卫覆盖"超硬件上限"这一最危险路径；wgpu `create_buffer`
  本身不返回 `Result`（失败走 validation error 通道）属 API 限制，记录在案；
- 超时值 30s 为保守上限（正常提交不被误杀），目的是杜绝"永不自旋"而非限制提交耗时。
