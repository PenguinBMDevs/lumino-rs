# DEBT-10 / T-34：i18n 双体系收敛 spec

> 日期：2026-11-27
> 状态：**迁移已完成（2026-11-27）**
> 关联：`2026-11-26-DEBT-10-结构减法与尺寸治理.md`、T-12

## 1. 现状（迁移前快照）

| 体系 | 位置 | 规模 | 使用方 |
|---|---|---|---|
| catalog + `tr!` | `crates/core/core/src/i18n/catalog/*` | 13 个分片文件 + `catalog.rs` | 191 个文件、1348 处 `tr!` / `trf!` |
| extras i18n | `crates/tools/extras/src/i18n/{translations,settings}.rs` | 156 + 153 个字段；`main` / `settings` 各 2 份中英静态表 | 30 个生产文件、458 处字段访问 |

两套都能产出中文 / 英文文案，新增一条文案时无法从类型上判断该放哪边，于是同一概念出现两份。

两套都能产出中文 / 英文文案，新增一条文案时无法从类型上判断该放哪边，于是同一概念出现两份。

## 2. 规则（立即生效）

1. **运行期 UI 文案只进 catalog**：新增 `tr!` 字面量必须登记在
   `i18n/catalog/<域>.rs`，由 `catalog.rs` 的字面量门禁守护。
2. `lumino_extras::i18n` **冻结**：只允许修 bug，不新增词条；新需求一律走 catalog。
3. 设置页的结构化标签（`settings.rs` 里的 `SettingsLabels` 等）如果必须保留类型，
   数据从 catalog 取，不再自带一份中英文常量表。
4. 一个概念只允许一个 key；中英文同 key 的分片文件按域归属（shell / view / settings / …）。

## 3. 迁移顺序（已完成）

1. ✅ 盘点 `extras/i18n` 的公开符号与调用点：实际 41 个文件使用
   `lumino_extras::i18n`（30 个生产文件、458 处字段访问）。
2. ✅ 把 309 个字段去重后的 254 条新词条搬进 `catalog/legacy_extras.rs`
   （4 个分片函数）；7 条与既有 catalog 冲突的译文按「一个概念一个 key」
   保留 catalog 既有英文。
3. ✅ `MainTranslations` / `SettingsTranslations` 移到
   `crates/core/core/src/i18n/compat.rs`，字段由 `tr_in` 从 catalog 取值，
   `OnceLock` 按语言缓存；调用点只换 import，不改 UI 结构。
4. ✅ 删除 `crates/tools/extras/src/i18n.rs` 与 `src/i18n/` 全目录，
   删除 `extras` 的 i18n re-export；41 个调用方改为 `lumino_core::i18n`。
5. ✅ `compat.rs` 增加 `LEGACY_KEYS` 守护测试：每条兼容字段的原文必须能在
   catalog 找到英文；`tr!` / `trf!` 覆盖率门禁继续生效。

## 4. 验收（实测）

- 新增一条文案只改 1 个 catalog 分片（+ 如新增 key 需登记 1 处）✅；
- `rg "translations.rs|SettingsLabels" crates/tools/extras` 为空 ✅（exit 1）；
- `cargo nextest run -p lumino-core -p lumino-ui-core` 绿 ✅；
- 兼容层 309 字段全部由 catalog 取词，无第二张中英映射表 ✅。
