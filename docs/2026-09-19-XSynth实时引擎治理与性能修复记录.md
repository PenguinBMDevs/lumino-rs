# XSynth 实时引擎治理与性能修复记录（2026-09-19）

## 背景

96kHz + 重型音色库（TWGMD Remake VI）+ 超密黑乐谱（Bad Apple 3.14M，单通道 331 万音符）
实时播放出现：声部爆炸、冻结长音、间歇性停滞、音频落后进度条、爆音。
经过一整天逐层 RCA，最终定位到 **6 个独立根因**，全部修复并验收通过。

## 根因与修复

| # | 根因 | 证据 | 修复 | fork 提交 |
|---|------|------|------|-----------|
| 1 | **debug 构建未优化 DSP**：`[profile.dev]` 无 opt-level，实时光栅渲染慢约 10 倍（6.5µs vs 0.45µs/声部/块） | headless 实时管线 release 实测 0.45µs/声部；app debug 实测 ~6.5µs | lumino 根 `Cargo.toml` 增加 `[profile.dev.package.xsynth-*] opt-level = 3` | （lumino 侧） |
| 2 | **共享声部计数失真**：计数靠渲染后差值对账，硬抢占下长期偏差，治理/入场控制读假数 | 日志：每秒硬抢 2000+，V 纹丝不动 | `VoiceBuffer` 在 push/pop/remove/trim/clear 全部增删点同步 `AtomicU64` | `54bc3c5` |
| 3 | **入场控制吞 NoteOff**：撞到软目标后"同键有 deferred 就吞 NoteOff"，把在响音符的 NoteOff 吃掉 → 冻结长音 | 撞墙后 V 钉死、load 持续上涨、`samples=0` | 每键 `sounding` 计数：键上有在响音符时 NoteOff 必须直通；仅取消"从未发声"的 deferred | `52515e9` |
| 4 | **分通道预算误伤单通道**：预算按通道数均分，单通道文件只拿到 1/16 | MIDI 普查：该文件 `channels=1`、峰值并发 3366 | 预算改为**全局共享池**（`soft − 当前总声部`），通道按需原子取用 | `40f8028` |
| 5 | **"推迟/丢弃新音符"语义错误**：撞上限后推迟并补发旧音 → 碎片化、音频落后进度条 | "一下一下往前蠕动"、"间歇性断档" | 改为**抢旧不丢新**：预算耗尽时先抢占最不重要的旧声部（T1/T2 短淡出）再让新音符发声 | `9d01e22` |
| 6 | **负载略超限时不作为**：只按声部数治理，负载持续 >1 时只是超时渲染 | load 略超、缓冲被抽干 | **负载自适应目标**：load>0.9 持续 200ms → 每块 ≤1% 缓慢收缩；load<0.6 持续 1s → 缓慢恢复；地坂 = 名义目标 5%；瞬时尖峰忽略 | `e70c6860` |
| 7 | **洪峰注入窗口**：单块 drain 4096 事件 ×16 通道，1M NPS 洪峰在闸门触发前注入数十万音符 | 卡 3–4s 后恢复 | 单块注入封顶（256/通道/admit）+ 瞬时 `load>2.0` 立即开闸 | `29353ed` |
| 8 | **播放器"迟到补发"**：`tick <= 播放头` 无迟到判断，播放线程停顿/跳变后把区间内所有过时音符一次性补发 | 爆破点后持续衰减的噼啪声 | `LATE_NOTE_SKIP_SECS=0.15`：进度条领先 150ms 以上的音符直接跳过（不发 NoteOn、不登记 NoteOff） | （lumino 侧） |
| 9 | **洪峰尾料逐块消化**：紧急模式退出后残留 NoteOn 在正常模式被"抢一个放一个"；管道硬删无淡出 | 爆后持续噼啪 | 紧急模式进出边沿整队列冲洗（丢弃残留 NoteOn 并配对取消 NoteOff）；上限回收统一软抢占（1ms 淡出），硬删仅留给 L4 看门狗 | `e5b869e` |

其它一并修复的遗留：`send_events` bench 缺 `max_voices` 字段、等功率声像测试过期断言、
NPS 移除后过期的 skipped 测试、`remove_ended_voices` 的 O(n²) 搬移（改单趟重建）。

## 最终语义（已验收）

- **连续播放优先**：每个新 NoteOn 都会发声；撞上限时抢占最旧/最轻/释放中的声部（1ms 淡出），
  即"顶到上限有硬切、但音乐不断"。
- **全局上限**：用户设 `xsynth_global_voice_limit`（None=自动 10000），
  运行目标 = `xsynth_voice_target_ratio × 上限`（默认 `1 − 1/e ≈ 0.632`）。
- **负载自适应**：持续轻度过载会自动缓慢降目标（多切旧声部），轻载后缓慢恢复；
  瞬时尖峰不触发。
- **保命闸**（可选，默认关）：负载持续 >1.0 或单块尖峰 >2.0 时临时限流 NoteOn，
  回落后自动解除；关闭时不存在任何 NoteOn 丢弃路径。

## 性能基线（96kHz，TWGMD Remake VI，Ryzen 9 9950X3D）

| 场景 | 结果 |
|---|---|
| release 实时管线，Auto 并行 | 0.45 µs/声部/块（4480 声部 → load 0.20） |
| release 实时管线，串行 | 4.7 µs/声部/块（约 10 倍慢，验证并行生效） |
| 离线标定台（Auto） | 0.48 µs/声部/块；27k 声部 → load 1.36 |
| app（debug + xsynth opt-level 3） | V=7700 → load 0.74；V=1925 → load 0.20 |
| 洪峰（1M NPS 瞬时） | 保命闸兜底，load_peak 从 1.97 降到 1.05，3–4s 停滞压缩到秒级内 |

## 已知限制

- 单通道超密文件（如 StarT 164M，42 万 NPS）超出实时能力，会以切音/限流应对，不可能全音符实时。
- V 上限的实际容量 ≈ 按 0.5–1.0 µs/声部/块反推（本机 96kHz 约 1–2 万声部为 load 1.0 边界）。

## 验收记录

用户实测（cap 自动 + ratio 0.77 + 保命闸开）：
- 连续无断档，撞上限按预期切最旧声部（乱切旧声部可接受、不允许断档）；
- 瞬时 1M NPS + 3W Poly 洪峰在保命闸下挺过，恢复后**无噼啪残余**；
- "迟到即弃"生效：进度条领先超过 150ms 的音符不会被延后补发。
- 结论：**验收通过**（2026-09-19）。
