## 根因与修复

### 1. 48kHz 音色库整体升调（+147 cents）

- 现象：TWGMD（48kHz SF2）GPU 导出 A4 = 478.75Hz（+146.1c）。
- 根因：`SoundFont::load` 把目标采样率硬编码为 `44_100`，48k 样本被重采样到 44.1k 后仍按原生率播放，整体升高 `44100/48000`；44.1k 音色库恰好无害，掩盖了问题。
- 修复：
  - `crates/audio/gpu-synth/src/soundfont.rs`：`load` 增加采样率参数并传入 `load_soundfont`；zone 的 `native_rate` 记录实际数据域；懒重采样同率直通；`native_rate_for` 回退 `self.sample_rate`。
  - `crates/audio/gpu-synth/src/synth/engine.rs:955`：调用处传 `self.config.sample_rate`。

### 2. 实时预算丢音 + `active_notes` 截断

- 根因：实时路径按 `limit`（默认 4）做块级 spawn 预算门控，黑乐谱整块触发时丢弃最新事件；`active_notes` 用 u8 统计，>255 截断。
- 修复（`crates/audio/gpu-synth/src/synth/engine.rs`）：
  - 移除块级预算门，改为 `MAX_SPAWNS_PER_KEY_PER_BLOCK = 65536` 的病理硬顶（由裁剪路径兜底），块内不再丢事件。
  - `active_notes` u8 → u32。
  - 新增测试 `spawn_guard_only_caps_pathological_bursts`。

### 3. RPN/NRPN 与 CC100/101

- 根因：CC100/101 接线颠倒（规范：CC100 = DataEntry MSB，CC101 = DataEntry LSB），用规范编码的 RPN（音高范围/微调/粗调）从未生效；DataEntry 未按 RPN 号写入对应槽位；NRPN 被误当 RPN 处理。
- 修复：
  - `engine.rs` 的 `handle_rpn_cc` / `apply_cc`：RPN 0/1/2 分槽写入（灵敏度/微调/粗调），灵敏度统一 `/128`，微调标准 14-bit（中心 8192）；NRPN 独立命名空间，CC98/99 选中后 DataEntry 消费丢弃；补 4 个 CC 驱动测试。
  - fork `xsynth-Lumino`：`core/src/channel/control.rs` 同步修复（CC98/99 NRPN 消费、灵敏度 `/128`、微调默认 14-bit）。
- 依赖：分支 `fix/rpn-nrpn-midi-spec`，commit `2ee23ec6cb30108dce02dc5b1bb435bf92461548`；`Cargo.lock` 中 `xsynth-core` / `xsynth-realtime` / `xsynth-soundfonts` 均 pin 到该 rev。

### 4. CPU 弯音归一化符号错误

- 根因：`PitchBend::as_int()` 返回带符号偏移（-8192..=8191，中心 0），旧实现 `as_int()/8192 - 1` 把中心映射为 -1.0（全下弯音），CPU 渲染中所有中心 PB 事件都被额外拉低一个灵敏度值。
- 修复：`crates/tools/export/src/audio/event.rs` 抽出 `pitch_bend_normalized()` 直接 `/8192`，并补中心/最小/最大/半程上弯回归测试。

### 5. 同 tick 排序与非稳定/域文档

- `crates/core/project/src/project/conversion.rs`：`sort_unstable_by_key(tick)` → 稳定 `sort_by_key`，保留 CC→PC→PB 装配顺序，保证同 tick 的 RPN 选择/DataEntry 先于 PB 生效。
- `crates/audio/midi-loader/src/event.rs`：PitchBend 域文档改为 signed `-8192..=8191`（中心 0），注明 raw 取值需 `bend.0.as_int()`。
- `crates/core/project/src/project/data_formats.rs`：测试数据 `8192` → `0`（偏移量域）并补中心断言。
