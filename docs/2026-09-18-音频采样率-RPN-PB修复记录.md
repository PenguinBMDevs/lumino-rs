## 根因与修复

### 1. 48kHz 音色库整体升调（+147 cents）

- 现象：TWGMD（48kHz SF2）GPU 导出 A4 = 478.75Hz（+146.1c）。
- 根因：`SoundFont::load` 把目标采样率硬编码为 `44_100`，48k 样本被重采样到 44.1k 后仍按原生率播放，整体升高 `44100/48000`；44.1k 音色库恰好无害，掩盖了问题。
- 修复：
  - `crates/audio/gpu-synth/src/soundfont.rs`：`load` 增加采样率参数并传入 `load_soundfont`；zone 的 `native_rate` 记录实际数据域；懒重采样同率直通；`native_rate_for` 回退 `self.sample_rate`。
  - `crates/audio/gpu-synth/src/synth/engine.rs:955`：调用处传 `self.config.sample_rate`。

### 2. 实时预算丢音 + `active_notes` 截断

- 根因：实时路径按 `limit`（默认 4）做块级 spawn 预算门控，黑乐谱整块触发时丢弃最新事件；`active_notes` 用 u8 统计，>255 截断。
- 修复（`crates/audio/gpu-synth/src/synth/engine.rs`）：
  - 移除块级预算门，改为 `MAX_SPAWNS_PER_KEY_PER_BLOCK = 65536` 的病理硬顶（由裁剪路径兜底），块内不再丢事件。
  - `active_notes` u8 → u32。
  - 新增测试 `spawn_guard_only_caps_pathological_bursts`。

### 3. RPN/NRPN 与 CC100/101

- 根因：CC100/101 接线颠倒（规范：CC100 = DataEntry MSB，CC101 = DataEntry LSB），用规范编码的 RPN（音高范围/微调/粗调）从未生效；DataEntry 未按 RPN 号写入对应槽位；NRPN 被误当 RPN 处理。
- 修复：
  - `engine.rs` 的 `handle_rpn_cc` / `apply_cc`：RPN 0/1/2 分槽写入（灵敏度/微调/粗调），灵敏度统一 `/128`，微调标准 14-bit（中心 8192）；NRPN 独立命名空间，CC98/99 选中后 DataEntry 消费丢弃；补 4 个 CC 驱动测试。
  - fork `xsynth-Lumino`：`core/src/channel/control.rs` 同步修复（CC98/99 NRPN 消费、灵敏度 `/128`、微调默认 14-bit）。
- 依赖：分支 `fix/rpn-nrpn-midi-spec`，commit `2ee23ec6cb30108dce02dc5b1bb435bf92461548`；`Cargo.lock` 中 `xsynth-core` / `xsynth-realtime` / `xsynth-soundfonts` 均 pin 到该 rev。

### 4. CPU 弯音归一化符号错误

- 根因：`PitchBend::as_int()` 返回带符号偏移（-8192..=8191，中心 0），旧实现 `as_int()/8192 - 1` 把中心映射为 -1.0（全下弯音），CPU 渲染中所有中心 PB 事件都被额外拉低一个灵敏度值。
- 修复：`crates/tools/export/src/audio/event.rs` 抽出 `pitch_bend_normalized()` 直接 `/8192`，并补中心/最小/最大/半程上弯回归测试。

### 5. 同 tick 排序与非稳定/域文档

- `crates/core/project/src/project/conversion.rs`：`sort_unstable_by_key(tick)` → 稳定 `sort_by_key`，保留 CC→PC→PB 装配顺序，保证同 tick 的 RPN 选择/DataEntry 先于 PB 生效。
- `crates/audio/midi-loader/src/event.rs`：PitchBend 域文档改为 signed `-8192..=8191`（中心 0），注明 raw 取值需 `bend.0.as_int()`。
- `crates/core/project/src/project/data_formats.rs`：测试数据 `8192` → `0`（偏移量域）并补中心断言。

### 6. 实时 RPN/NRPN 自动化被丢弃 + 同 tick 选择顺序

- 根因：
  - 实时组装（`ui/root/editor_ops/playback.rs`）对 `AutomationTarget::Rpn/Nrpn` 直接返回空（`_ => {}`），RPN/NRPN 自动化在实时回放中被静默丢弃；离线导出与合成器侧均正常；
  - `midi_events` 跨 lane 汇总顺序 = lane 创建顺序，同 tick 的 DataEntry(CC6/38) 可能先于选择 CC(98–101) 发出，数据会写到上一次选择的参数上（导入文件先出现 NRPN 时尤甚）。
- 修复：
  - `note-core` 新增 `AutomationLane::to_midi_cc_events()`：RPN/NRPN → CC 序列；选择前缀每条数据都发（自包含，seek 安全）；数据统一双字节 14-bit（7-bit 目标 MSB 承载原值、LSB=0），避免位宽歧义；
  - 实时路径接入展开结果，并加同 tick 顺序守卫：选择(98–101) → 其他 → DataEntry(6/38)，不同 tick 与无关消息保持原序。
- 验证：note-core 新增 10 个展开单测；ui 新增 T1/T2 集成测试（修复前必红：RPN lane 无 CC 输出；对抗序 6→101→100 被纠正为 101→100→6）；实机（XSynth Realtime + SGM）听到 -50c→+50c→回中，临时埋点日志确认 CC 序列完整到达合成器（埋点已在验收后移除）。

### 7. seek/循环回绕不追齐模态状态（chase）

- 根因：CC/Program/PitchBend/RPN-NRPN 都是“当前值”模态。seek 只把游标二分到目标 tick，不重发 seek 点之前的状态；暂停中 seek 连 `all_notes_off`/`reset_control` 都不发，任何后端都会保留跳转前旧值（典型：在 RPN 微调偏高处暂停 → 跳到后方 → 播放仍偏高）。
- 修复（`crates/audio/midi-io/src/playback/engine/control/chase.rs`）：
  - `compute_chase()`：当前轨 `midi_events` 与非当前轨 `document.control_events` 按 tick 合并，取每通道最后状态；
  - `seek()` 暂存 `pending_chase`，`Command::Seek` 在重置后 flush（暂停中 seek 同样发送，按 Play 即为正确状态）；
  - 循环回绕（`handle_loop_wrap`）追齐 `loop_start` 之前状态；
  - 输出顺序：Program → 选择 CC(98–101) → DataEntry(6/38) → 其他 CC → PB；只追最后一次被选中的参数家族。
- 验证：新增 6 个 chase 单测；midi-io 37、ui 333 单测全绿；实机验收：偏高处暂停 → 跳后方 → 播放立即回正，播放中 seek 无残留。

## 遗留事项

1. **实时高密度播放杀音符/断音**：xsynth-realtime 内置固定 `max_nps = 10_000`（`realtime_synth.rs`），`should_send_for_vel_and_nps` 超限直接丢 NoteOn；Bad Apple（3.3M 音符，平均约 15.6k NPS）会大量丢音。与本轮 RPN 改动无因果，待单独立项（提高/按力度分级限流、buffer/采样率调整、或高密度工程走 LGS/Core）。
2. **XSynth 初始化慢**：按设备原生采样率全量预处理音色库（96kHz + SGM-V1.2 约 117 秒，每次启动缓存未命中）。缓解：设备切 48kHz 或换小音色库；产品级需落盘缓存/进度提示。
3. **System 回退日志误导**：`MIDI 播放输出: 无法创建任何输出连接，播放将无声` 与实际不符（沿用启动时的 System 连接仍会发声）。
4. fork 分支 `fix/rpn-nrpn-midi-spec` 建议合并回 master 后再删除，避免 `Cargo.lock` 的 rev pin 失效；未合并前请保留分支。
5. 灵敏度统一 `/128`（与 XSynth 一致，非 GM 常见的 `/127`），外部音色库行为回归时需注意。
6. `.codegraph/` 目录未跟踪，建议确认后加入 `.gitignore`。
