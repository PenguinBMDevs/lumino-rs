## 二、Phase 1：准备与基础设施（第 1 月）

### Week 1-2：环境准备

**目标**：建立重构的基础设施，确保后续工作可并行。

**任务清单**：

- [ ] 创建 `refactor/` 分支（从 `main` 切出）
- [ ] 设置 CI 流水线（编译 + 测试 + lint + 覆盖率）
- [ ] 创建新 crate 目录结构（空 crate，先用 `pub use` 重导出）
- [ ] 编写重构文档（本文档集）并同步到团队

**具体步骤**：

```bash
# 1. 创建重构分支
git checkout -b refactor/architecture-2026

# 2. 创建新目录结构
mkdir -p crates/lumino-app/src
mkdir -p crates/lumino-editor/src
mkdir -p crates/lumino-audio/src
mkdir -p crates/lumino-gfx/src
mkdir -p crates/lumino-core/src
mkdir -p crates/lumino-network/src
mkdir -p crates/lumino-tests/src

# 3. 初始化空 crate（先用重导出保持兼容）
# crates/lumino-core/src/lib.rs
pub use lumino_core::*;        // 原 core
pub use lumino_event::*;       // 原 event
pub use lumino_message::*;     // 原 message
pub use lumino_extras::*;      // 原 extras
```

**验收标准**：
- `cargo check` 通过
- `cargo test` 通过（现有测试）
- CI 流水线绿色

### Week 3-4：PipelineBuilder 与 TrackedResource

**目标**：建立渲染管线的新基础设施，不影响现有代码。

**任务清单**：

- [ ] 创建 `lumino-gfx/src/pipeline.rs`（PipelineBuilder）
- [ ] 创建 `lumino-gfx/src/gpu_resource_tracker.rs`（TrackedBuffer/TrackedTexture）
- [ ] 创建 `lumino-gfx/src/renderer.rs`（Renderer trait）
- [ ] 为 PipelineBuilder 写单元测试
- [ ] 为 TrackedBuffer 写单元测试

**验收标准**：
- PipelineBuilder 能创建简单 pipeline
- TrackedBuffer 的 Drop 正确减少资源计数
- 新代码有 100% 测试覆盖率

## 三、Phase 2：核心重构（第 2 月）

### Week 5-6：Crate 合并（核心层 + 音频层）

**目标**：合并 `core`/`event`/`message`/`extras` → `lumino-core`，合并音频 crate → `lumino-audio`。

**风险**：高（影响编译依赖图）

**回滚策略**：保留旧 crate 目录一周，新 crate 用 `pub use` 重导出。

**任务清单**：

- [ ] 将 `core/` 代码物理移动到 `lumino-core/src/`
- [ ] 将 `event/` 代码物理移动到 `lumino-core/src/events/`
- [ ] 将 `message/` 代码物理移动到 `lumino-core/src/actions/`
- [ ] 解决 `message` 对 `midi-loader` 的反向依赖
- [ ] 将音频 crate 代码物理移动到 `lumino-audio/src/`
- [ ] 统一音频层的错误类型

**具体步骤**：

```bash
# 1. 移动 core 代码
git mv crates/core/core/src/* crates/lumino-core/src/
git mv crates/core/event/src/* crates/lumino-core/src/events/
git mv crates/core/message/src/* crates/lumino-core/src/actions/

# 2. 更新 Cargo.toml
# 删除旧 crate 的 [workspace.members] 条目
# 添加新 crate 的条目

# 3. 解决反向依赖
# 将 message 中的 MidiDocument 引用改为 Box<dyn Any>
```

**验收标准**：
- `cargo check` 通过
- `cargo test` 通过
- 无循环依赖（`cargo tree | grep -i cycle` 为空）

### Week 7-8：编辑层合并 + 状态管理重构

**目标**：合并 `editor-state`/`ui-editor`/`ui-settings`/`ui-core` → `lumino-editor`，建立事件驱动架构。

**风险**：极高（影响所有编辑功能）

**回滚策略**：保留旧 `editor-state` 一周，新 `EditorSession` 通过适配器兼容旧 API。

**任务清单**：

- [ ] 将编辑 crate 代码物理移动到 `lumino-editor/src/`
- [ ] 创建 `EditorSession` 结构体
- [ ] 创建 `DocumentEvent` enum
- [ ] 将 `EditorData` 拆分为 `Document` + `EditorView`
- [ ] 逐个替换 `sync_*` 函数为事件驱动
- [ ] 更新所有测试

**验收标准**：
- 所有编辑操作正常（插入/删除/移动音符）
- 撤销/重做功能正常
- 渲染增量自动推导正确

## 四、Phase 3：质量提升（第 3 月）

### Week 9-10：代码整洁度

**目标**：消除 clone，收紧可见性，拆分大文件。

**任务清单**：

- [ ] 用 `cargo clippy -- -W clone_on_ref_ptr` 找出所有 clone
- [ ] 优先处理热路径（音频渲染、MIDI 处理）
- [ ] 审查所有 `pub` 项，降级不必要的可见性
- [ ] 识别所有超过 400 行的文件，拆分为子模块

**验收标准**：
- clippy 无 clone 警告
- `pub` 项数量减少 30%
- 所有文件行数 < 400

### Week 11-12：测试补全 + 文档

**目标**：为 13 个无测试 crate 补测试，提升文档覆盖率。

**任务清单**：

- [ ] 为 `audio/midi-io` 写基础测试
- [ ] 为 `audio/playback` 写 Timeline 测试
- [ ] 为 `editor/gfx` 写 PipelineBuilder 测试
- [ ] 为 `editor/editor-state` 写状态管理测试
- [ ] 为所有 pub 函数添加文档注释
- [ ] 启用 `#![warn(missing_docs)]`

**验收标准**：
- 所有 crate 至少有一个测试文件
- 核心模块覆盖率 ≥80%
- `cargo doc --no-deps` 无警告

## 六、风险管理

### 6.1 风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| Crate 合并引入循环依赖 | 中 | 高 | 先用 `pub use` 重导出，逐步迁移；每日 `cargo check` |
| 状态管理重构破坏撤销/重做 | 高 | 高 | 保留旧 History 实现一周；写大量回归测试 |
| 音频层合并破坏 KDMAPI | 低 | 高 | KDMAPI 代码隔离在单独文件；有物理设备时手动测试 |
| 渲染管线重构降低性能 | 中 | 中 | 性能基准测试；PipelineBuilder 只做代码组织，不改变 GPU 命令 |
| 团队成员不熟悉新架构 | 中 | 中 | 重构文档 + 代码审查 + 配对编程 |
| 重构时间超期 | 高 | 中 | 分阶段交付，每阶段可独立合并；优先做高风险项 |

### 6.2 回滚策略

**每个 Phase 的回滚点**：

```
Phase 1：随时可回滚（只新增基础设施）
Phase 2：保留旧 crate 一周，新 crate 用 pub use 兼容
Phase 3：纯代码优化，不影响架构，随时可回滚
Phase 4：最终验证，不通过则延长 Phase 4
```

**紧急回滚命令**：

```bash
# 如果 Phase 2 出现问题，快速回滚到 Phase 1
git checkout refactor/architecture-2026-phase1

# 恢复旧 crate 目录
git restore crates/core/core/
git restore crates/core/event/
git restore crates/core/message/
```
