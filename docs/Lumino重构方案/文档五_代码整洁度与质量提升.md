# Lumino 重构方案 —— 文档五：代码整洁度与质量提升

> 目标：消除 559 次 clone，控制文件体积，提升文档覆盖率，统一代码风格

---

## 一、当前问题诊断

### 1.1 Clone 泛滥

**数据**：559 次 `.clone()` 调用，31 次 `Arc::clone`。

**问题**：热路径（音频渲染、MIDI 事件处理）中大量不必要的内存分配。

**典型案例**：

```rust
// crates/editor/ui/src/root/handlers/material.rs:803 行
// 素材处理中几乎肯定存在大量 Vec/String 的克隆

// 某处代码（示意）
fn process_material(material: &Material) -> Vec<Texture> {
    let textures = material.textures.clone(); // 不必要的克隆
    let mut result = Vec::new();
    for tex in textures { // 消费了克隆
        result.push(tex.process());
    }
    result
}
```

### 1.2 可见性控制薄弱

**数据**：1916 个 `pub`，376 个 `pub(crate)`，比例约 5:1。

**问题**：
- 大量本应是私有的实现细节被暴露
- 外部 crate 可能依赖了内部实现
- 重构时难以判断哪些改动会破坏兼容性

### 1.3 文件体积失控

| 文件 | 行数 | 问题 |
|------|------|------|
| `crates/audio/note-core/src/automation.rs` | 4642 | 一个文件 4000+ 行 |
| `crates/editor/gfx/src/grid.rs` | 2662 | 网格渲染逻辑 |
| `crates/editor/ui-editor/src/arrangement/click_canvas.rs` | 2113 | 点击画布 |
| `crates/editor/ui-editor/src/drag.rs` | 2098 | 拖拽逻辑 |
| `crates/core/memtrace/src/lib.rs` | 2080 | 内存追踪器 |
| `crates/editor/ui/src/root/handlers/material.rs` | 803 | 素材处理 |
| `crates/audio/midi-io/src/api/kdmapi.rs` | 1119 | KDMAPI FFI |

**clippy.toml 中明明写了**：
```toml
too-many-lines-threshold = 400
```

### 1.4 文档覆盖率极低

**数据**：3686 行 doc comment / 153166 行代码 ≈ **2.4%**

**问题**：
- 大量 pub 函数无文档
- 复杂算法（如 `ChunkedList` 的分裂逻辑）缺乏说明
- 新贡献者难以快速理解代码

### 1.5 测试覆盖不均

**数据**：13 个 crate 完全无测试，测试文件过大（最大 1128 行）。

| 有测试的 crate | 测试处数 | 无测试的 crate |
|---------------|---------|---------------|

| `editor/ui-editor` | 47 | `editor/gfx` |
| `editor/ui` | 30 | `editor/dialog` |
| `network/cloud` | 8 | `tools/extras` |

## 二、重构方案

### 2.1 Clone 消除策略

#### 原则

1. **函数参数优先用引用**：`&[T]` 替代 `Vec<T>`，`&str` 替代 `String`
2. **返回值优先用引用**：生命周期标注明确时返回 `&T`
3. **Cow 策略**：读时共享，写时克隆
4. **Arena 分配**：大量小对象用 arena 分配器

#### 具体措施

**措施 1：热路径零 Clone**

```rust
// 改前：音频渲染热路径
pub fn render_notes(notes: Vec<NoteEvent>, tempo_map: TempoMap) -> Vec<f32> {
    let mut samples = Vec::new();
    for note in notes { // 消费了 notes
        samples.extend(render_note(note, tempo_map.clone()));
    }
    samples
}

// 改后
pub fn render_notes(notes: &[NoteEvent], tempo_map: &TempoMap) -> Vec<f32> {
    let mut samples = Vec::new();
    for note in notes { // 借用
        samples.extend(render_note(note, tempo_map));
    }
    samples
}
```

**措施 2：String 用 Rc<str> 或 Interning**

```rust
// 改前：轨道名称、标记文本等频繁克隆
pub struct Track {
    pub name: String, // 克隆成本高
}

// 改后：不可变字符串用 Rc<str>
pub struct Track {
    pub name: Rc<str>, // 克隆 = Arc 引用计数 +1，O(1)
}

// 或者使用字符串驻留（如果重复度高）
pub struct Track {
    pub name: StringId, // 内部是 u32，指向全局字符串表
}
```

**措施 3：批量操作避免中间 Vec**

```rust
// 改前：批量插入音符
pub fn insert_notes(&mut self, notes: Vec<NoteEvent>) {
    for note in notes {
        self.insert(note); // 每次可能触发 Vec 扩容
    }
}

// 改后：预分配 + 批量写入
pub fn insert_notes(&mut self, notes: &[NoteEvent]) {
    self.reserve(notes.len());
    for note in notes {
        self.insert_unchecked(note.clone()); // 只在最后统一排序/验证
    }
    self.sort_and_dedup();
}
```

**措施 4：Arc::make_mut 封装**

```rust
// 改前：每个编辑函数都手写
let model = Arc::make_mut(&mut self.data.model);
model.tracks[track].notes.push(note);

// 改后：封装到 Document 中
impl Document {
    pub fn modify_track(&mut self, index: usize) -> &mut Track {
        Arc::make_mut(&mut self.model).tracks[index]
    }
}

// 使用
self.document.modify_track(track).notes.push(note);
```

### 2.2 可见性收紧

#### 目标

将 `pub` : `pub(crate)` 比例从 5:1 调整到 2:1。

#### 策略

**步骤 1：审查所有 `pub`**

```bash
# 生成 pub 项列表
grep -rn "^pub " crates/ --include="*.rs" | grep -v "pub use" | grep -v "pub mod" > pub_items.txt

# 按 crate 统计
awk -F: '{print $1}' pub_items.txt | sort | uniq -c | sort -rn
```

**步骤 2：降级不必要的 `pub`**

```rust
// 改前
pub fn internal_helper(x: i32) -> i32 { x * 2 }

// 改后
pub(crate) fn internal_helper(x: i32) -> i32 { x * 2 }

// 或者完全私有
fn internal_helper(x: i32) -> i32 { x * 2 }
```

**步骤 3：建立 API 边界**

每个 crate 的 `lib.rs` 明确声明公开 API：

```rust
// lumino-core/src/lib.rs

// 公开 API（精简）
pub use crate::document::Document;
pub use crate::events::DocumentEvent;
pub use crate::types::{NoteEvent, TempoMap, Track};
pub use crate::config::Config;

// 内部模块（不公开）
mod document;
mod events;
mod types;
mod config;
mod utils; // 内部工具函数
```

### 2.3 文件拆分

#### 规则

1. **400 行限制**：超过 400 行必须拆分为子模块
2. **单一职责**：每个文件只负责一个概念
3. **测试文件独立**：测试代码放在 `tests/` 目录或文件末尾的 `#[cfg(test)]` 模块

#### 拆分示例

**示例 1：`automation.rs`（4642 行）**

```
crates/audio/note-core/src/
├── automation/
│   ├── mod.rs          # 公开 API（<100 行）
│   ├── types.rs        # 类型定义（Event, Curve, Point）
│   ├── parser.rs       # 解析逻辑
│   ├── serializer.rs   # 序列化逻辑
│   ├── evaluator.rs    # 曲线求值
│   ├── interpolation.rs # 插值算法
│   └── tests.rs        # 测试
```

**示例 2：`material.rs`（803 行）**

```
crates/editor/ui/src/root/handlers/material/
├── mod.rs              # 公开 API
├── loader.rs           # 素材加载
├── cache.rs            # 缓存管理

```

**示例 3：`kdmapi.rs`（1119 行）**


## 三、代码风格统一

### 3.1 导入组织

**统一规则**：

```rust
// 1. std 库
use std::collections::HashMap;
use std::sync::Arc;

// 2. 外部 crate（按字母序）
use bytemuck::{Pod, Zeroable};
use iced_core::{Color, Point, Rectangle};
use wgpu::{Buffer, Device, Queue};

// 3. 内部 crate（按层级）
use lumino_core::{NoteEvent, TempoMap, Track};
use lumino_editor::{EditorView, Selection};

// 4. 当前 crate
use crate::pipeline::PipelineBuilder;
use crate::renderer::Renderer;
```

**工具**：使用 `rustfmt` + `imports_granularity = "Crate"` 自动格式化。

### 3.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 结构体 | PascalCase | `NoteEvent`, `EditorSession` |
| 枚举 | PascalCase | `DocumentEvent`, `Tool` |
| 函数 | snake_case | `insert_note`, `render_frame` |
| 常量 | SCREAMING_SNAKE_CASE | `EVENT_CHUNK_CAPACITY` |
| 类型别名 | PascalCase | `NoteId`, `TrackIndex` |
| trait | PascalCase | `Renderer`, `ActionHandler` |
| 生命周期 | 'a, 'buf | `'a`, `'data` |

### 3.3 错误处理统一

**统一使用 `thiserror`**：

```rust
// lumino-core/src/error.rs
use thiserror::Error;

#[derive(Error, Debug)]
pub enum LuminoError {
    #[error("音轨不存在: {0}")]
    TrackNotFound(usize),

    #[error("无效的 tick: {0}")]
    InvalidTick(i32),

    #[error("文档未加载")]
    DocumentNotLoaded,

    #[error("IO 错误: {0}")]
    Io(#[from] std::io::Error),

    #[error("MIDI 解析错误: {0}")]
    MidiParse(String),

    #[error("渲染错误: {0}")]
    Render(String),
}

pub type Result<T> = std::result::Result<T, LuminoError>;
```

## 四、实施步骤

### Phase 1：Clone 消除（2 周）

1. 用 `cargo clippy -- -W clone_on_ref_ptr` 找出所有 clone
2. 优先处理热路径（音频渲染、MIDI 处理）
3. 用 `&[T]` 替代 `Vec<T>` 参数
4. 用 `Rc<str>` 替代频繁克隆的 `String`

### Phase 2：可见性收紧（1 周）

1. 审查所有 `pub` 项
2. 降级不必要的 `pub` 为 `pub(crate)` 或私有
3. 在每个 crate 的 `lib.rs` 中明确公开 API

### Phase 3：文件拆分（2 周）

1. 识别所有超过 400 行的文件
2. 按功能拆分为子模块
3. 确保拆分后编译通过

### Phase 4：文档补全（持续）

1. 为所有 pub 函数添加文档注释
2. 为复杂算法添加说明
3. 添加代码示例
4. CI 中启用 `#![warn(missing_docs)]`

### Phase 5：测试补全（2 周）

1. 为 13 个无测试 crate 补基础测试
2. 拆分过大测试文件
3. 提升核心模块覆盖率到 80%
