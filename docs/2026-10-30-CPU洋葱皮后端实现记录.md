# CPU 洋葱皮后端（Q3 B）实现记录

- 日期：2026-10-30
- 范围：Step 1 ~ Step 6b（CPU 渲染核心 → gfx 叠加层 → Host 接入 → 后端选择/守卫 →
  脏区/局部上传 → 源顺序 → **像素一致性 + 1080p 性能实测 + 验收**）
- 结论：CPU 洋葱皮链路已可用、可测、有量化数据；GPU/CPU **在 100% / 125% / 150%
  三档物理相机下逐像素严格 0 差异**（含每侧 2px 边框、含「填充边界恰好落在像素中心」
  的退化几何），另有半像素滚动与 1e6px 超宽音符两条回归同为 0 差异。
  两侧都统一到确定性规则：**边界等号归填充**——CPU `notes.rs::{fill_start, fill_end}`，
  GPU `onion_note.wgsl` 的屏幕像素空间严格不等判定（不再走 UV 重心插值，
  因此没有宽度相关的 epsilon，也没有插值噪声）。

## 1. 架构链路

```
                     ┌──────────────────────────────────────────────────────┐
 MidiDocument  ─────►│ lumino-cpu-onion（纯 CPU，无 wgpu / 无 winit）       │
 （唯一权威音符源     │  TrackIndex::build         聚合索引，不复制音符       │
   Arc 共享，编辑层    │  CpuOnionRenderer::render_full / render_region       │
   与渲染层同一份）   │  （tokio 多 band 并行 + AVX2 运行时检测 + 标量兜底） │
                     └───────────────────────┬──────────────────────────────┘
                                             │ CpuFrame：透明背景 RGBA8 sRGB
                                             │ 音符 alpha=255、每侧 2px 边框、
                                             │ 重叠 first-wins、无抗锯齿
                     ┌───────────────────────▼──────────────────────────────┐
                     │ lumino-editor-state：编辑增量（CpuOnionDirty/Change）│
                     │ lumino-ui::host::render::cpu_onion                    │
                     │  相机 → 物理像素；静音表展开；指纹冻结（不变则复用）  │
                     │  脏区计划 → CpuOnionFrame{version, dirty_rect}        │
                     └───────────────────────┬──────────────────────────────┘
                                             │ RenderData → RenderParams::cpu_onion_frame
                     ┌───────────────────────▼──────────────────────────────┐
                     │ lumino-gfx::CpuOnionRenderer（WGPU 渲染线程）         │
                     │  上传决策状态机 → 纹理全量/局部写                     │
                     │  屏幕空间四边形：网格之后、GPU 洋葱皮与当前轨之前     │
                     └──────────────────────────────────────────────────────┘
```

数据流要点：

- **音符数据只有一份**：`Arc<MidiDocument>`，CPU 光栅期间不复制音符；`TrackIndex`
  只存 `max_len / long_notes / measure_counts / track_note_counts` 等聚合量。
- **像素只产出一份**：CPU 光栅结果直接作为叠加层纹理，不回到文档、不落盘。
- **GPU 侧同时刻只驻留当前轨**：`OnionSkinState::set_cpu_current_only(true)` 后
  GPU 洋葱皮 buffer 仅当前轨（事件级增量），非当前轨/静音轨由 CPU 叠加层负责。

## 2. 关键决策

| # | 决策 | 理由 / 影响 |
|---|------|-------------|
| 1 | **GPU 只画当前轨，CPU 画洋葱轨**（Q3 B） | 当前轨要编辑即时性（GPU 事件级增量、零重传）；洋葱轨是低频变化的背景层，适合 CPU 光栅 + 脏区 + 空间换时间 |
| 2 | 外观口径以 `onion_note.wgsl` **源码**为事实源 | 边框 = 线性色 ×0.4、`border_width` 低 16 位 = 1 ⇒ 每侧 **2px**；CPU 端必须做 linear→sRGB 编码才与屏幕像素同值；音符 alpha 恒 255；无抗锯齿；重叠 first-wins |
| 3 | 排列/取色单一入口 | CPU `NoteStyle` 与 GPU 实例都取 `palette::current_track_color_f32(track)`；调色板变化时 GPU 重建实例色、CPU `refresh_palette` 重建缓存，两侧同步 |
| 4 | **入口 / 出口禁用** | 纵向卷帘、工程走带、全屏瀑布流、侧栏钢琴瀑布预览、视频导出面板与导出中：一律拒绝切到 CPU 或拒绝该功能（`root::handlers::cpu_guard` 提示 + Runner 侧最终兜底），并把导出出口与瀑布流过渡封住——宁可拒绝，不做静默错位降级 |
| 5 | **会话锁**：加载 MIDI/工程后禁止切换后端 | `Host::onion_backend_locked()` = `midi_load.is_loaded()`（`session_lock::MidiLoadLock` 单源）。刻意不用 `document.is_some()`：启动即挂 2 轨空白文档，用「有文档」当锁会让设置页从第一帧起永久锁定。空白工程 → 选 CPU → 加载 MIDI 锁定 → 关闭工程解锁 |
| 6 | **当前轨编辑跳过 CPU 重绘** | CPU 指纹只覆盖洋葱轨内容 + 静音位图 + 相机 + 调色板版本 + 后端语义；编辑当前轨不递增 CPU 版本。`EditorData::set_cpu_onion_dirty_enabled` 只在 CPU 后端开启脏区记录，GPU 后端零开销 |
| 7 | **脏区重绘** | `render_region(rect)` 只重画 `[x,x+w)×[y,y+h)`，与「整帧同参数后取同一块」逐像素一致（band 互不重叠 + 无跨像素耦合 + first-wins 按 band 内序）；滚动走 `shift_frame` + `render_strip` 窄条 |
| 8 | **局部上传** | `CpuOnionFrame::dirty_rect`（帧内像素坐标）+ gfx 上传状态机：**版本紧邻**才局部写，尺寸变化 / 版本跳号 / 脏区越界一律保守全量（版本跳号＝中间那次区域重绘没落进纹理，只写本帧脏区会永久留旧像素） |
| 9 | **同 tick 源顺序** | band 内「长音符流」与「正常窗口流」在 `start_tick` 相等时**回文档按 tick 组查询**，按全局源索引绘制，对齐 GPU 洋葱皮区「源索引 = 深度序」；避免固定「长音先画」导致的边框可见性错位 |
| 10 | band 数上限 4 | `available_parallelism().clamp(1, 4)`；再多的线程只增加调度开销与每 band 一块缓冲的内存 |
| 11 | **边框/填充边界统一「等号归填充」**（Step 6b 修复，两侧各一处） | CPU 与 GPU 原先都在「填充边界恰好落在像素中心」的退化点上出错/不确定：<br>① CPU 四边同用 `ceil(edge-0.5)` ⇒ 右/下等号处多数 1 列/行描边（125% 实测 48 处、150% 实测 36 处）；现拆成 `fill_start`（四边原式）与 `fill_end`（`floor(edge-0.5)+1`）；<br>② GPU 用 UV 边距判边框，等号处落在**重心插值末位噪声**上（实测同一行、`uv.y` 与边距逐位相同的两个实例结论相反）；现改为**屏幕像素空间**判定（`local = position.xy - rect_min`），等号归填充且不含插值量 |

## 5. DPI：100% / 125% / 150%

- 相机在 `ui::host::render::cpu_onion::camera` 换算到**物理像素**（与 GPU 主轨屏幕坐标
  同口径），`CpuOnionFrame{x, y, width, height}` 也是物理像素；gfx 叠加层**不做**任何
  DPI 缩放（`CpuOnionUniform` 原样传递矩形）。
- Step 6a 已锁死 150% 非整数几何：`scale=1.5`、`offset=(37.3, 21.9)`、
  `size=(333.3, 200.1)`、`scroll=(12.7, 3.3)`、`zoom=(1.7, 20.3)` →
  物理矩形 `(55, 32)` / 尺寸 `(499, 300)` / 相机浮点值 `(19.05, 4.95, 2.55, 30.45)`。
- Step 6b 在 **100% / 125% / 150%** 三个物理相机下逐像素比较 GPU 与 CPU（§6）：
  **三档全部严格 0 差异**（覆盖 / alpha / RGB 逐字节相同，含每个音符的 2px 边框）。
  三档都带小数几何（125% 的 `zoom=(1.25, 12.5)`、150% 的 `(1.5, 15.0)`，相机刻度
  `0`）且**刻意包含**「填充边界恰好落在像素中心」的退化点：归属由两侧确定性的
  「等号归填充」规则决定（CPU `fill_start`/`fill_end`；GPU 屏幕像素空间严格不等），
  不再受浮点插值噪声影响。另有 125% + 0.3px 半像素滚动用例覆盖非退化小数几何。

## 6. GPU / CPU 全像素对比（Step 6b 实测）

### 6.1 口径

| 项 | CPU 侧 | GPU 侧 |
|----|--------|--------|
| 入口 | `CpuOnionRenderer::render_full` | `NoteRenderer::new_onion_skin` + `prepare_pass`（compute cull）+ `draw`（indirect）＝**生产主路径** |
| 目标 | 透明背景 RGBA8（sRGB 编码） | `Rgba8UnormSrgb` + `Depth32Float`，`LoadOp::Clear(TRANSPARENT)` |
| 相机 | `CanvasCamera`（画布 = canvas 区域，无键盘栏/标尺） | `CameraUniform`（`keyboard_width`/`ruler_height`/`canvas_offset` = 0，`max_key_index = key_count-1`） |
| 取色 | `NoteStyle`（`palette::current_track_color_f32` → `srgb_encode`） | 同一 `current_track_color_f32` → `pack_key_color` |
| 排除 | `current_track` / `muted[]` | 上传集合预先过滤 + `ViewState.current_track = 0`（无主轨） |

比较规则：双方 alpha=0 的背景**忽略**；一方覆盖另一方不覆盖 → **几何差异**；
双方覆盖 → alpha 必须 255，并比较 RGB。断言是**严格逐像素相等**（无阈值、无容差、
无「合法色」放宽）。

### 6.2 结果（画布 256×144 = 36 864 像素）

| 用例 | 双方覆盖 | 几何差异 | 颜色差异 | 最大通道差 | alpha 违规 |
|------|---------:|---------:|---------:|-----------:|-----------:|
| 1 单轨单音（矩形/2px 边框） | 400 | **0** | **0** | 0 | 0 |
| 2 同 tick 长/短音源顺序 | 5 120 | **0** | **0** | 0 | 0 |
| 3 多轨颜色 / 重叠 first-wins / 当前·静音排除 | 1 900 | **0** | **0** | 0 | 0 |
| 4 DPI 100%（刻度 0） | 480 | **0** | **0** | 0 | 0 |
| 5 DPI 125%（刻度 0，**含退化等号几何**） | 725 | **0** | **0** | 0 | 0 |
| 6 DPI 150%（刻度 0，**含退化等号几何**） | 1 125 | **0** | **0** | 0 | 0 |
| 7 DPI 125% + 0.3px 半像素滚动 | 789 | **0** | **0** | 0 | 0 |
| 8 超宽音符 1e6 px（边框宽度回归） | 2 560 | **0** | **0** | 0 | 0 |
| GPU `ViewState` 语义（主轨/静音/洋葱轨） | — | — | 见下 | — | — |

用例 5/6 是**故意保留**的 tie 几何：125% 下 `sx+sw-2 = 10.5`（像素 10 中心）、
`sy+2 = 14.5`（第 14 行中心），150% 下 `sx+2 = 6.5`（像素 6 中心）——
这些边界在真实 fractional zoom / scroll 下必然出现，测试不绕开。

### 6.3 结论

1. **100% / 125% / 150% 三档（含退化 tie 几何）+ 半像素滚动 + 超宽音符，
   全部整帧逐像素严格相等**（覆盖、alpha、RGB 全 0 差异），断言无阈值、无容差。
   颜色能严格相等的原因是两路取色同源（`current_track_color_f32`），且
   `pack_key_color` 的 `(byte/255*255)` 8 位往返对 0..=255 全部无损。
2. **本轮两处修复**（§2 决策 11 / §2.1）：
   - **CPU**：四边同用 `ceil(edge-0.5)` ⇒ 右/下等号处多数 1 列/行描边；拆成
     `fill_start` / `fill_end` 后 125% **48 → 13**、150% **36 → 36**（后者全是左/上）。
   - **GPU**：UV 边距判定的等号落在重心插值末位噪声上。实测证据：125% 行 14 的
     `uv.y` 与边距是**逐位相同的 f32**（`0.1599999964237213`），但实例 A（`sw=8.75`）
     判填充、实例 B（`sw=6.25`）判边框——同一理想判定、不同宽度、相反结论。
     改为屏幕像素空间判定后，等号归填充由 `local == side_px` 的严格不等式决定，
     与插值无关。**最终三档全部 0 差异**。
3. **为什么不用 UV epsilon（记录被否方案）**：`eps_uv` 的等效像素宽度是
   `eps * sw`——1e-4 UV 在 1e6px 宽音符上等于 100px，会把整条边框吃光。因此没有
   采用任何宽度相关的收敛，而是把判定搬进像素域（与宽度无关）。用例 8 是这个
   回归的守门人：1e6px 宽音符的左边框必须仍是 `x=0,1` 两列描边、`x>=2` 填充，
   GPU/CPU 逐像素一致。
4. 另有一条 GPU 侧语义用例（与 CPU 不等价、单独断言）：全量实例 + `ViewState`
   时主音轨染主轨蓝 `[124,196,255,255]`、静音轨完全无片元 `[0,0,0,0]`、
   洋葱轨使用调色板实例色 —— 实测逐字节命中。

## 7. 1080p 性能实测（release）

**命令**（必须 release；debug 下测试会自动拒绝执行）：

```text
cargo test --release -p lumino-cpu-onion --test perf_1080p -- --ignored --nocapture
```

**环境 / 数据**：`debug_assertions=false`（release），CPU 12 核，band 数 4
（`available_parallelism().clamp(1,4)`）；视口 1920×1080，`zoom = [0.25 px/tick, 12 px/key]`，
64 轨 / **200 000 音符**，tick 均匀分布于 `[0, 12000)`，key 均匀分布于 `[40, 120]`，
每音 48 tick（12 px 宽）；**可见音符 128 082（64.0%）**，band 内绘制次数
130 332 ~ 131 139（跨 band 音符重复计数）。

| 测量项 | 冷启动 | p50 | p99 | max | mean |
|--------|-------:|----:|----:|----:|-----:|
| `render_full`（60 帧，每帧横向滚 1px） | 27.10 ms | **26.28 ms** | **34.94 ms** | **38.90 ms** | 27.12 ms |
| `render_full` 第 2 组（热态 60 帧） | — | 26.11 ms | 37.73 ms | 43.26 ms | 27.43 ms |
| `render_region` 200×24 脏区（60 帧） | — | **0.248 ms** | **0.454 ms** | 1.325 ms | 0.269 ms |

| 规模 | `TrackIndex::build` | 语料构建（含 `batch_insert_notes`） |
|------|--------------------:|-----------------------------------:|
| 200 000 音符 / 64 轨 | **1.67 ms**（三次 1.67 / 1.67 / 1.84） | 10.2 ms |
| 1 000 000 音符 / 64 轨 | **8.60 ms**（三次 8.70 / 8.60 / 8.65） | 55.5 ms |

局部上传 vs 全量上传（**计算值，非实测**：`width*height*4` 字节）：
全量 `8 294 400 B` vs 200×24 脏区 `19 200 B` → **432×**。

复测说明：同一台机器同一命令先后两次测得 `render_full` p50 **28.43 / 26.28 ms**、
p99 **39.25 / 34.94 ms**，即整帧口径存在约 ±8% 的**运行间抖动**（与上文的帧间上升
同源，疑频率/功耗策略）。上表取最近一次；读者不应把个位数百分比差异当作改进或回退。

**读数说明（原始数据见上，不做美化）**：

- 1080p 全帧在 12 核机器上 **p50 ≈ 26~28 ms**（≈ 36~39 fps），是本方案的真实成本：
  每帧要做整帧 `u32` 复合缓冲清零 + 4 band 光栅 + 整帧 `u32 → RGBA8` 输出转换
  （1920×1080×4 B ≈ 8.3 MB 写）。**因此脏区路径是必需的**，
  200×24 脏区 p50 **≈ 0.24 ms**（比整帧快 ≈ 110~120×），单音符编辑不会掉帧。
- 两组独立 60 帧序列都呈**帧间单调上升**（≈23 ms → ≈37 ms），但可见音符数恒定
  （130 332 → 131 052，±0.6%），且第二组从头重新回到 ≈23 ms ⇒ **不是工作量增长、
  不是逐帧泄漏**，疑为 CPU 频率/功耗策略所致（未深究）。故报告同时给出
  p50（整组）与逐帧原始值，读者可自行判读；未据此做任何"优化"结论。
- 本轮未在 release 下实测 gfx 纹理上传耗时（`write_texture`），只给出字节数比值。

## 8. 已知边界与未自动化项

1. **GPU/CPU 逐像素严格一致已在 100%/125%/150%（含退化等号几何）、半像素滚动、
   超宽音符上全部达成**，无「排除几何」——等号归填充由两侧确定性规则保证
   （CPU `fill_start`/`fill_end`；GPU 屏幕像素空间严格不等判定）。
2. **`onion_note_vertical.wgsl`（纵向转置）仍是 UV 边距判定**：本步只改横向
   `onion_note.wgsl`，纵向路径未动——CPU 后端下纵向卷帘本就被禁用（§8.5），
   因此没有 CPU/GPU 对比需求，但横向/纵向的边框判定实现就此不同源，属于记录在案的
   已知不一致（详见 `crates/editor/gfx/src/shaders/README.md`）；如需统一请另开卡。
3. **整帧像素拷贝仍在**：CPU 侧每帧把 `Vec<u8>` 整帧快照成 `Arc<[u8]>` 交渲染线程；
   Step 5b 只把 **GPU 上传**降到脏矩形（`CpuOnionFrame::dirty_rect`），
   CPU → UI 线程的整帧拷贝未变。
4. **版本跳号即降级为全量上传**：渲染侧三缓冲会合并中间帧，版本不紧邻时只写本帧
   脏区会永久留下旧像素，故保守全量（`UploadPlan::Upload`）。
5. **不兼容入口一律禁用而非降级**：纵向卷帘、工程走带、全屏瀑布流、侧栏钢琴瀑布
   预览、视频导出（面板与导出中）在 CPU 后端下拒绝执行；Runner 侧另有兜底。
6. **测试侧的轨道编码是重写而非引用**：GPU 实例的 `border_width` 高 16 位 =
   `track+1` 由 `ui::onion_skin::onion_border_width` 生成，该函数是 `pub(crate)`，
   测试按同一表达式重写（`NOTE_BORDER_WIDTH | ((track+1) << 16)`）——若该编码在未来
   变化，测试会以颜色/覆盖差异失败，不会静默漂移。
7. **只覆盖横向钢琴卷帘**：纵向转置坐标、瀑布流、走带、导出路径未纳入像素对比
   （这些路径在 CPU 后端下本身被禁用）。
8. **`render_strip`（滚动窄条）未纳入像素对比**：本轮覆盖 `render_full` 与
   `render_region`；窄条路径已由 crate 内单测覆盖其与整帧的一致性，但没有 GPU 对照。
9. **性能数字仅本机**（12 核 Windows / release）；未做跨机器、跨平台对比，
   也未引入 criterion（保持零新依赖、无 CI 抖动断言）。

## 9. 手工验收清单

前置：dev 构建，空白工程启动。

- [ ] 空白工程 → 设置页把「洋葱皮渲染后端」切到 **CPU**（此时不应锁定）。
- [ ] 加载一份 >= 3 轨的 MIDI：加载后设置页后端下拉**锁定**（不可切换）。
- [ ] 当前轨音符由 GPU 绘制（选中/编辑即时响应）；其余轨由 CPU 洋葱皮绘制，
      颜色/边框与 GPU 当前轨观感一致（2px 深色边框、无抗锯齿）。
- [ ] 编辑**当前轨**音符：不触发 CPU 重绘（无卡顿、无闪烁）。
- [ ] 编辑**洋葱轨**音符（切换到该轨编辑后再切回）：只有编辑区域重绘，
      其余画面不闪。
- [ ] 滚动：平滑滚动时无撕裂/错位（整数位移 + 窄条）；快速拖动滚动条后画面正确。
- [ ] DPI：100% / 125% / 150% 三档下音符矩形与边框位置正确（与 GPU 当前轨对齐）。
- [ ] 静音某条洋葱轨：该轨立刻消失；取消静音恢复。
- [ ] 切轨（把某条轨设为当前轨）：被切走/切来的轨道归属正确（GPU/CPU 分工随切轨迁移）。
- [ ] 入口闸：CPU 后端下尝试 纵向卷帘 / 工程走带 / 全屏瀑布流 / 侧栏钢琴瀑布预览 /
      视频导出 → 均被拒绝并提示，不出现错位画面。
- [ ] 关闭工程 → 后端选择**解锁**（可切回 GPU）；切回 GPU 后洋葱皮恢复 GPU 绘制。
- [ ] 全程无 panic、无 wgpu 校验错误日志。
