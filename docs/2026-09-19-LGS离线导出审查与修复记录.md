## 本次改动

- `crates/audio/gpu-synth/src/synth/engine.rs`
  - `trim_key_voices`：首行 `if limit == 0 { return; }`——`limit == 0` 是"每键不限制"
    （与 UI 文案、`spawn_budget_allows` 一致），绝不能让 0 走到 `saturating_sub` 变成"全杀"。
  - `select_evictions`：删掉"候选不足就放开保护组"的兜底——`truncate` 本身容忍候选不足，
    该兜底只会在异常输入下悄悄破坏"新音符必发声"。候选不足时宁可少抢。
  - `dispatch` 的设备上限分支：用 match 绑定直接 `push`，去掉 `unwrap()` 与"先 push 空组再回填"。
  - 新增单测 `evictions_never_steal_the_protected_group_when_candidates_run_short`。
- `crates/tools/export/src/audio/config.rs`
  - 新增 `normalize_layer_limit`（`None` / `Some(0)` → `None`），`layer_limit_from_ui` 改为复用它：
    0 语义只有一处定义。
  - `AudioRenderConfig::layer_limit` 文档修正为"每 (通道, 键)"并写明两端计数口径（CPU 按层/voice，
    GPU 按音符组）。
  - 新增单测 `test_normalize_layer_limit_folds_some_zero_into_none`。
- `crates/tools/export/src/audio/event.rs`（CPU 侧）：`SetLayerCount(normalize_layer_limit(...))`。
- `crates/tools/export/src/audio/gpu_backend.rs`（GPU 侧）：去掉 `n.max(4)`，与 CPU 严格同值；
  新增单测 `gpu_per_key_limit_does_not_silently_raise_small_values`，原配置测试断言同步改严。
- `crates/editor/ui-core/src/state/audio_export_state.rs`：删除死字段 `max_voices`（含默认值 2048 与
  与实际行为不符的注释）；`layers` 注释按真实语义修正。**不接 UI 接线**（全局复音上限是产品决策，
  见"遗留"）。
- `crates/editor/ui/src/view/widgets.rs`：`dialog_checkbox_style` 真正处理 `Status::Disabled`
  （禁用态统一半透明），否则"灰显"只是文案。
- `crates/editor/ui/src/view/audio_export_dialog.rs`：GPU 后端下复选框显示**引擎实际行为**
  （限幅恒开、淡出恒开）而不是用户上次在 CPU 下的选择。

## 遗留（本次刻意不做，需要产品/负责人决策）

1. **离线导出的全局复音上限**：`max_voices = 0`（无限制）是 `4aff0d91` 的既定选择（对齐 CPU/XSynth
   基准），代价是极端素材下 V 可达数万、渲染时间不可接受。UI 侧不做新接线，故本次只删掉骗人的
   死字段；若要恢复上限，需要同时定义 UI 控件语义、默认值与 xsynth 侧的对齐方案。
2. **音色库解析阶段不可中止、GPU 渲染阶段无百分比进度、无容量预检**（`4aff0d91` 已知项）——属于
   体验类改动，独立排期。
3. **`eprintln!` 告警**：`lumino-gpu-synth` 刻意不继承工作区 lint、也未依赖 `tracing`（见其
   `Cargo.toml` 注释），本次不为一行告警引入新依赖。
