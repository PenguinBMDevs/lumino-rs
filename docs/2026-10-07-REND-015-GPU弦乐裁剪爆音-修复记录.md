# REND-015（#115）GPU 弦乐裁剪爆音 · 修复记录（2026-10-07）

> 关联卡：#115（REND-015）｜修法来源：`docs/2026-10-04-REND-015-GPU弦乐裁剪爆音-检查点.md`
> 结论：**已实施并听感验收通过**（用户验收设置：LGS 实时、buffer 1024、每键 32、力度过滤 1）。
> 相关语义：#105（释放优先、绝无淡出硬杀）、#94（端口级每键上限）。

## 一、根因（按当前代码复核）

现象：CC73（Attack Time）+ 高频弦乐高 poly 触发裁剪 → 尾段连续噼啪；后端 GPU/LGS 实时。

1. 裁剪淡出 **1 ms**（`gpu-synth/src/synth/engine/pool.rs` fade stage `(sr / 1000)`），密集裁剪下
   淡出叠加成"电锯音/噼啪"（CPU 侧 REND-009 已改 5 ms 并验证）；
2. **无每块裁剪限流**：`trim_port_key_voices` 每块把全部超限组一次性裁掉，密集段落每块批量制造淡出；
3. **无迟滞**：`> cap` 即触发（超 1 个就裁），cap 边界上每块小批量持续抢；
4. "已在淡出 → 直接 ended" 的假设按"1 ms 一块内播完"编写：5 ms 淡出可能跨块，同块
   （独占裁剪/块内裁剪先行打上淡出）会被端口级裁剪直接掐掉，淡出根本播不出来。

## 二、修复内容

| 项 | 落点 | 说明 |
|---|---|---|
| 5 ms 淡出 | `engine/pool.rs`（并行/串行两处）、`engine/types.rs` | 新增 `FADE_OUT_MS = 5` / `fade_frames(sr)`；对齐 CPU `KILL_FADE_SECS = 0.005` |
| 淡出完成判定 | `engine/trim.rs`（端口级/全局上限/物理兜底）、`engine/cc.rs`（块内） | 新增纯函数 `fade_complete`：`global_frame - release_at >= fade_frames` 才允许 `ended`，未播完的保持淡出自然结束 |
| 每块限流 128 | `engine.rs` 字段 `trim_fade_budget` + `engine/events.rs` 每块重置 + `trim.rs`/`cc.rs` | 端口级与块内裁剪**共享**预算，组粒度取用；超出部分留待后续块（`trimmed_group_count`） |
| 迟滞 | `engine/trim.rs` 触发阈值 | `cap + max(1, cap / 4)`（`trim_hysteresis`）；触发后仍裁到 cap |
| 预算护栏 | `engine/types.rs` `trim_fade_budget_for` | 有全局池上限时 clamp 到 fade 槽位数（`max_voices / FADE_SLOTS_FRACTION`），避免预算撑满槽位逼出硬杀 |
| 物理兜底顺序 | `engine/trim.rs` | 溢出时先结束**已淡完**的，再牺牲未淡完的（安全网语义不变） |
| 独占类豁免 | `engine/cc.rs` `trim_exclusive` | 独占类（hi-hat 等）不占预算，保持即时释放语义 |
| 死分支清理 | `engine/cc.rs` `trim_key_voices` | 不可达的 `if v.fade_out { ended }` 分支随 5 ms 语义一并移除 |
| 注释同步 | `voices.rs`、`types.rs`、`trim.rs`、`cc.rs` | 全部 "1 ms" 表述改为 5 ms + 限流/迟滞说明 |

## 三、行为变化（已知且用户确认）

- 每键有效复音上限在 **cap ~ cap+25%** 之间浮动（默认 cap=4 时最高约 6；cap 可 0..128）；
- 过载裁剪不再"一块裁完"，最多 128 组/块（约 16 组/ms @ 8 ms 块），分多块追赶；
- 释放优先、新音符必发声、绝不无淡出硬杀（#105 音频语义）全部不变；
- **无裁剪的素材输出 bit-exact**（不触发 `fade_out` 即无任何变化）。

## 四、验证

- 新增单测（`engine/tests.rs`，5 项）：5 ms 帧数换算、淡出完成判定（含未播完/非裁剪/未释放边界）、
  迟滞阈值、预算槽位 clamp、预算分批；
- `cargo test -p lumino-gpu-synth`：**52 passed / 0 failed** + 7 doctest 全绿；
- `cargo fmt`、`cargo clippy -p lumino-gpu-synth --all-targets` 零告警；
- 用户听感验收（2026-10-07）：LGS 实时、**buffer 1024 / max_voices_per_key 32 / velocity_filter 1**，
  CC73 + 高频弦乐场景**通过**（连续噼啪消失；单/多端口无异常）。

## 五、后续观察（不阻塞）

- 用户实测口径：进入 LGS 后先让它渲染一会再开播，效果稳定（初始化/预热时序的体验优化另议）；
- 极小 buffer（64/128 帧）+ 高采样率时 5 ms 淡出跨多块属预期行为，靠 `fade_complete` 判定保证不硬切；
- 常量集中位置：`engine/types.rs`（`FADE_OUT_MS` / `MAX_TRIM_FADES_PER_BLOCK` / `trim_hysteresis`），
  后续如需按设备/素材调参可从这里入手。
