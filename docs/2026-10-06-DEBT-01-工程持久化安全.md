# DEBT-01 工程持久化安全（#118）

> 来源：全仓屎山扫描 2026-10-06（分片 4）｜优先级 **P0** ｜类型：数据安全 / tech-debt
> 总报告：`docs/2026-10-06-全仓屎山扫描-总报告.md`

## 背景

工程保存对用户原文件**直接覆盖写**；LMPJ 归档解析**信任文件头字段**。两者叠加：
一次保存中断、或打开一个被截断的工程文件，都会造成**用户工程损坏或进程崩溃**。

## 证据（file:line）

| 项 | 位置 | 说明 |
|---|---|---|
| 保存无原子性 | `crates/core/project/src/project/save.rs:117-122`、`crates/core/project/src/project/folder.rs:110-119` | 先截断再写；调用方 `src/runner/menu/file/save.rs:321-357` |
| 越界解析 | `crates/core/project/src/project/archive.rs:205,228-242` | offset/size 无上界/溢出校验，截断文件即 panic |
| CRC 只写不验 | `archive.rs:281,289`（写）；读路径无校验 | 损坏不可检出 |
| 风险放大 | `crates/core/diagnostics/src/memory_monitor.rs:263-294` | 95% 直接 `abort` |
| 关闭挂死 | `src/runner/menu/file/save.rs:158-186,300-303` | 保存确认选「保存」但保存未启动 |
| 写盘非原子 | config / ui_state 写盘（分片 4 M5） | 解析失败静默重置 |

## 修复方案（最小路径）

1. `save_to_archive` / 文件夹保存改「同卷 `.tmp` → `sync_all` → `rename` 原子替换」；
   Windows rename 目标存在时先旧→`.bak`，失败保留备份 + 用户提示；
2. `archive.rs` 头字段全部 `checked_add/checked_mul` + 统一 `slice_at -> Result`；
3. 读取时校验 CRC / `original_size` / `version`；
4. save→close 挂死路径复现并修（状态机断言）。
