## 一、接线地图（4 处，含顺序约束）

```text
保存：export.rs   project.shapes = editor.shapes_snapshot()
                    │
打开：load.rs     project = load_project(path)
                  shapes = project.shapes.clone()      ← 必须在转 ParsedMidi 之前取
                  parsed = project_to_parsed_midi(&project, path)
                    │
事件：emit(MidiParsed(parsed))                        ← 文档装载：clear_drawn_shapes()
      emit(ProjectShapes(shapes))                     ← 之后灌回形状（顺序不可反）
                    │
消费：file.rs      ProjectShapes(shapes) → ui.root_mut().editor.load_shapes(shapes)
清空：editor_ops.rs clear_drawn_shapes() 同时清 shape_store
```

**顺序约束的根因**：文档装载路径（`midi_handler.rs:84` → `clear_drawn_shapes`）会清空形状存储；
若 `ProjectShapes` 先于 `MidiParsed` 处理，刚加载的形状会被立刻清掉。已在两处代码注释里写明。

## 二、集成夹具（3 项）

1. `test_shapes_snapshot_roundtrips_through_load` — 建 2 个形状 → 快照 → 新编辑器 `load_shapes`
   → 形状原样还原；且**不生成音符**（音符由工程文档承载）。
2. `test_k_is_preserved_across_roundtrip` — `k = 0.375` 经往返后仍是 0.375
   （k 丢失会让形状跨缩放走形，这是移植最易漏的语义）。
3. `test_regeneration_is_zoom_independent` — 改视口缩放（×2.5 / ×0.5）后用**同一参数**再生成，
   音符数量与几何逐条不变 ⇒ 再生成只看几何，不吃视口缩放。

## 四、过程中处置的环境问题（如实记录）

`cargo test -p lumino-ui` 首轮失败：**D 盘可用空间 0 GB**（`os error 112`）。
处置：确认 `target/` 在 D 盘、`target/debug/incremental` 占 3.74 GB → 打印并校验解析路径与工作区
`target\debug\incremental` 完全一致后删除（只删构建缓存，不碰源码），D 盘回到 3.47 GB；
随后以 `CARGO_INCREMENTAL=0` 复跑，`lumino-ui` 507 项通过。
**这不是代码问题，但也不是"甩锅环境"——是定位到具体目录并处置后再复跑得到的绿灯。**
