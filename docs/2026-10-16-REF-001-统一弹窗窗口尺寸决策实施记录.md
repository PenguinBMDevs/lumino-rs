## 2. 与调研文档的偏差（3 处，均由实测推翻原判断）

### 2.1 ❌「两个轴都压缩」不成立 → 改为「宽度硬约束 + 高度压缩」

调研 §1.2 的探针结论「压缩限制下根 `Fill` 也能量出自然尺寸」**只对含固定尺寸内容的树成立**。
一旦树里有文本，两轴同时压缩会**把宽度压成 0**，文本随即按 0 宽折行，量出的高度虚高到荒谬：

| 现象 | 实测证据 |
|---|---|
| 提示文字被量成 208px 高 | 保存确认对话框（16px 字号，一行文案）——`debug_dump_dialog_layout_tree` |
| 说明文字被量成 337px 高 | 内存监控对话框（11px 字号） |
| 4 类高度直接顶到工作区上限 1040 | 批量编辑 / 内存监控 / 找回音轨 / 云连接 |

机理：iced flex 在「同一层子节点横向全是 `Fill`」时，pass 2 用 `cross`（初值 0）
作为子节点的 `max_width`（`iced_core/src/layout/flex.rs`）。而 `view_dialog` 的自定义
标题栏包裹层正是 `column![标题栏(Fill), 内容(Fill)]`。

**修正后的测量口径**（`measure_content_height`）：

```text
Limits::new(
    Size::new(layout_width, 0.0),        // 宽度 min = max = 声明宽度（硬约束）
    Size::new(layout_width, max_height),
).height(Length::Shrink)                 // 只压缩高度
```

修正后 17 类内容高度全部落回合理区间（见 §3），其中保存确认 169（旧 180）、
变速 256（旧 250）、云连接 446（旧 515）。

### 2.2 ➕ 新增第四类：「钉死高度」（`min_height == max_height`）

调研把「含滚动区的对话框」归为「声明 `max_height` 即可」。阶段 F 的 dump 显示
**这类对话框的测量连高度都不可信**：

```text
=== Settings root=720×152
  size=(688,40)
    size=(200,0.0)        ← 外层被压成 0 高
      size=(200,524.0)    ← 菜单列表内容真实高 524，完全没被计入
```

即设置面板的测量**漏掉整块菜单（524px）**，按测量结果开窗会得到 152px 高的设置窗口
（严重回归）。云文件浏览 / 画刷设置的列表在打开时为空，同理。

**处置**：这 4 类（设置 / 工程设置 / 云文件浏览 / 画刷设置）用
`DialogSizeHint::pinned(w, h)`（`min = max`）钉死高度 = 原值。钉死的对话框
**不依赖测量** ⇒ 测量失败（0/NaN）也不会退回种子尺寸。

### 2.3 ❌ 删除 `height_cap` / `flex_spacer`（测量期开关整套方案）

调研阶段 C 计划用「测量期开关 + 视图内 `max_height`」表达滚动区偏好。落地时发现
**窗口级上限能表达同一语义且零视图改动**：

```text
高 = clamp(测量高度, 下限, 上限)；上限 = min(声明上限, 工作区)
```

内容短于上限 ⇒ 窗口贴合内容；内容超上限 ⇒ 夹到上限并交给滚动区。
视图保持纯 `Fill` ⇒ **用户放大可缩放对话框时滚动区仍随之增长**（这是视图内
`max_height` 做不到的）。因此 `lumino-ui-core` 的测量开关模块**写完即删**。

仅保留一处视图改动：`draw_settings_dialog.rs` 的 `space().height(Length::Fill)`
（"把按钮推到底部"）在窗口贴合内容后失去意义，且测量期会吃掉整个上限 → 改固定间距。

## 4. 关键实现

### 4.1 窗口归属（P0-1，同时修掉一个既有缺陷）

`is_dialog_window` 原先只查 `dialogs`（UI 就绪）。分帧初始化期间（阶段 1/2）窗口
已存在但不在 `dialogs` ⇒ 它的 `Resized`/`Moved`/`CloseRequested` 落到主窗口分支，
把对话框的物理尺寸/位置写进**主窗口持久化状态**（`ui_state.w/h/x/y`），
`CloseRequested` 还会被当成主窗口关闭请求。

改为查 `claimed_windows`（阶段 1 建窗即认领，`close_dialog` 与初始化失败路径释放）。
已认领但 UI 未就绪时，事件被 `handle_dialog_event` 安全消费（查不到就绪窗口 ⇒
无副作用并返回 `true`）。

### 4.2 时序（P0-2）

```text
阶段 1 建窗(hidden, 种子尺寸) + 认领   ┐ 同一帧
阶段 2 建 GFX                          ┘
阶段 3 建 Host(种子尺寸) + 注入状态     ← 下一帧
入册后首帧（DialogManager::update）
  ├─ 同帧稍早：try_fill_recover_track_entries 已注入内容 ← 必须在这里测
  ├─ measure_dialog_window_size(工作区)
  ├─ request_inner_size + 回读 inner_size 同步 ui/gfx（不等事件回程）
  ├─ 居中到主窗口（夹进工作区）
  └─ set_visible(true) → 首次 redraw
```

测量失败（`Size::ZERO`）⇒ 回退 `SEED_DIALOG_SIZE` 并**照常显示**（单测锁定
`usable_size` 拒绝 0/负数/NaN/∞）。

### 4.3 工作区与定位（P0-4）

winit 0.30 不暴露工作区，Windows 走 `MonitorFromWindow(MONITOR_DEFAULTTONEAREST)`
+ `GetMonitorInfoW().rcWork`；其它平台退化为整屏尺寸（已在文档标注为已知降级）。
定位用 `centered_position`：主窗口外框中心居中 + 夹进工作区（含负坐标副屏、
窗口大于工作区时贴左上角，均有单测）。

> 本轮**未**给对话框设置 owner 窗口（保持不变：每个对话框占独立任务栏按钮）。

## 7. 遗留风险与后续

1. **4 类钉死高度**（设置 / 工程设置 / 云文件浏览 / 画刷设置）：内容变化仍需回填数字
   ——这是「滚动区自己决定布局、测量不可信」的代价，已写入声明表注释。
   若将来要让它们也测量驱动，需要先改造对应视图（让滚动区有稳定的内在高度）。
2. **`use_native_titlebar = false` 时宽度测量恒为 0**（标题栏包裹层结构所致）——
   因为宽度一律取声明值，**当前无影响**；但不要再引入"用测量宽度定窗口"的代码。
3. 阶段 G（非阻塞 TODO）未动：`ScaleFactorChanged` 重建 viewport（P1-1）、
   `UiState.w/h` 单位统一（P1-2）、`lifecycle.rs` 阶段注释修正（P1-3）。
4. `DialogType::ExportProgress` 仍是死视图（Runner 侧无打开路径），本轮只保证
   它参与尺寸断言不 panic。
