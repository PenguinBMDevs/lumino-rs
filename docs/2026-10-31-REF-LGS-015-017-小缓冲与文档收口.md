## 1. REF-LGS-015：LOOKAHEAD=256 与 64/128 块长

### 1.1 结论：走方案 B（修内核），不钳制配置

卡片给的两个方向：

- **A. 钳制配置**：`block_size ≥ 256`，设置页同步收紧；
- **B. 修复内核**：让 limiter 支持 `block < LOOKAHEAD`。

**选 B，且内核修复已经存在**：

1. `DEBT-04 #121` 已把延迟线推进改成通用形式
   （`(old_tail ++ raw).last(LOOKAHEAD)`，`limiter.rs:95-102`），
   旧实现在 `n < 256` 时对 `raw.len() - 512` 负索引 panic 的路径已消失；
2. `REF-LGS-008` 的 `limit_stream` 在 `block < 512` 时退化为「一块一窗」
   （`limiter.rs:26-42`），不引入额外延迟，也不改变历史行为。

因此**不需要**收紧设置页的 64/128 选项，也不需要改 `crates/editor`
（该目录当前有 DRAW 工作流的未提交改动，本卡刻意不碰）。

### 1.2 实机复现（修复后）

`hash_render` + `rich.sf2` + `sustained65536`，1 s 音频，限幅开启：

| block | wall | peak | 结果 |
|---|---|---|---|
| 64 | 385.8 ms | 0.997287 | 无 panic |
| 128 | 223.0 ms | 0.984352 | 无 panic |
| 256 | 126.4 ms | 0.980002 | 无 panic |
| 512 | 93.4 ms | 0.980004 | 无 panic（基线） |

### 1.3 小块的音质口径（必须写清，避免误读）

`block < LOOKAHEAD(256)` 时，前瞻窗口在块边界被截断，末段回退到**本块峰值**
（`limiter.rs:169-173`）。所以：

- **不会**削波：`soft_knee` 把幅度硬性压在 1.0 以内（上表 peak ≤ 0.9973）；
- **但**瞬时峰值的前瞻不如大块充分，主观上大动态素材可能比 512 档更"紧"；
- 这是实时小缓冲的固有取舍（低延迟 vs 前瞻），不是缺陷，也不影响离线导出
  （009 已把离线默认块长定为 2048）。
