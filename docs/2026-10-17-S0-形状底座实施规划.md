# S0 形状底座 · 实施规划与更改功能面积

> 上游：`docs/2026-10-17-Spiderweb图形工具缺口清单与移植规划.md` §5/§6
> 日期：2026-10-17 ｜ 状态：口径已拍板，待开工
> 已确认口径（用户拍板）：
> 1. **形状本地存盘、不跨机同步**（协作只同步音符，形状同步列为 S0 之后跟进项）；
> 2. **不新建 crate**（见 §2 修订说明）；
> 3. **撤销不改 `EditorSnapshot`**，走已有的历史 group 回调 + 形状变更日志。

---

## 1. S0 的目标（一句话）

让「一个形状」从**一次性烘焙的几何残留**，变成**可持久、可回改、可撤销的文档对象**：
形状进工程文件 → 形状参数变更可重新生成音符 → 形状与它生成的音符在**同一个撤销单元**内同生共死。
S0 不交付任何用户可见的工具/面板，交付的是 T1 全部算子的地基。

---

## 2. 修订说明：为什么不需要新 crate（证据）

| 事实 | 证据 |
|---|---|
| 编辑器域数据类型本来就住在 `lumino-core` | `Tool`、`BrushConfig`、`NotePrecision`（`crates/core/core/src/types.rs:35,179,68`） |
| `lumino-core` 已依赖 `serde` / `serde_json` / `bincode` | `crates/core/core/Cargo.toml:15-20` |
| 该 crate 已有 serde 派生先例 | `Language`（`types.rs:273-280`） |
| `lumino-project` 已依赖 `lumino-core` | `crates/core/project/Cargo.toml` |

**结论**：形状模型作为 `crates/core/core/src/shape.rs` 落进 `lumino-core` —— **新增 crate 数 0，新增依赖边 0**。
初版规划里的 `crates/editor/shape-ops` 被删除；音符级后处理（通道消解）放 `lumino-note-core`，
交互与再生成留在 `ui-editor`（那里已有 `path_notes` / `fill_spans` / `shape_cells` 三套现成内核）。

> 若 T1 之后算子体积超过 `ui-editor` 承载能力，再考虑抽 crate——**现在抽属于提前设计**。

## 3. 任务卡（5 张）

### S0-1 形状数据模型（4 人日）

- 落点：`crates/core/core/src/shape.rs`（`lib.rs` 挂 `mod shape` + re-export）
- 内容：`ShapeModel { id, track, kind, geometry, style, ops, k, name, hidden }`；
  `ShapeKind`（line/poly/free/curve/arc/custom/funnel）；`ShapeGeometry`（点列 / 外接框 + 参数）；
  `ShapeStyle`（填充、门长、描边宽度、通道策略…S0 只放字段不实现语义）；
  `ShapeOp`（**带标签的信封枚举**，S0 只有 `Noop` 变体，为 T1 的 tumour/claw/strum/… 预留）；
  `k`（绘制时每 key 几拍）—— 见 §6 风险 R3。
- 验收：serde 往返；非法数据（NaN、负长度、超 255 key）**返回 Err 而非 panic**；`ops` 顺序保真。
- 测试：`cargo test -p lumino-core shape`

### S0-2 工程部件 `.lmshapes`（3 人日）

- 落点：`crates/core/project/src/project/{data_formats.rs, folder.rs, project.rs, save.rs, load/folder.rs, load/archive.rs}`
- 格式（照抄既有通用部件范式，`folder.rs:128-170`）：
  `[magic b"LMSH" 4B][version u16 = 1][zstd(level 3)(bincode(LmshapesData))]`
- 关键规则：
  - **缺失即空**：加载时 `if path.exists()` 才读（`load/folder.rs:42-58` 同款写法）；
  - **非空才写**：形状为空时不写部件 → **老工程保存后字节不变**；
  - `LuminoProject` 只加 `pub shapes: Vec<ShapeModel>` 一个字段；`::new`（`project.rs:110`）补 1 行。
    全仓 `LuminoProject` **无结构体字面量**（外部一律走 `::new`），改动面因此只有 1 处。
- 验收：往返；老工程（无部件）加载成功且保存字节不变；**含未知部件的工程被"只读已知部件"的加载器读取不报错**。
- 测试：`cargo test -p lumino-project shapes`

### S0-3 文档级形状存储 + 撤销日志 + 再生成接线（5 人日）

- 落点：`crates/editor/editor-state/src/editor_state/shape_store.rs`（新）、
  `editor_state.rs`（字段/new/reset）、
  `crates/editor/ui-editor/src/interaction/shape_ops.rs`（新）、
  `crates/editor/ui-editor/src/impls/editor_impl/history.rs`（复用 `on_undo_group`/`on_redo_group`，`:81`/`:206` 已接线）
- 核心机制（**照抄仓库已有范式**，不发明新机制）：
  - 形状对象与它生成的音符共用**历史 group_id**：现有 `drawn_shape.rs:528/545` 已用 group 回调维护
    「图形与音符同生共死」，S0 只是把「一次性平移回放」升级为「参数版本回放」；
  - `ShapeStore` 记录 `group_id → Vec<(shape_id, ShapeModel)>` 的**前像**；undo/redo 回放前像并**重新生成音符**；
  - 参数提交 = 1 个 `OpKind::Other` 快照（`Other` 不参与 300ms 合并窗口 → 一次提交 = 一条 undo，正是所需）。
- 明确不做：`EditorSnapshot` 不加字段（`note-core/src/history/snapshot.rs:24-49` 保持原样），`OpKind` 不加变体。
- 验收：改参数 → undo → **形状与音符同时回退**；redo 复原；连续两次参数变更各自独立成组。
- 测试：`cargo test -p lumino-editor-state shape_store`、`cargo test -p lumino-ui-editor shape_ops`

### S0-4 通道底座（1.5 人日）

- 落点：`crates/audio/note-core/src/channels.rs`（新）
- 内容：`raw`（原样，允许同 key 重叠）与 `single`（同 key 重叠：前者在后者起点截断、后者延长到前者原终点；
  同 tick 起音合并为最响且最长的一条）。
- 明确不做：`auto`（多通道分配）、Split 口径（same key / any）、通道 10 —— 归 S0 之后。
- 测试：`cargo test -p lumino-note-core channels`

### S0-5 集成与兼容夹具（1.5 人日）

- 端到端：建形状 → 存工程 → 重开 → 形状与音符一致；
- 撤销一致性、`k` 保真（同形状在不同 zoom 下重生成结果一致）；
- 未知部件容错、老工程字节不变（golden 字节比对）。

### 4.4 用户可见行为变化（产品视角）

- ✅ 工程文件新增 `.lmshapes` 部件：形状随工程保存 / 重开还原（空形状时不写，老工程不受影响）；
- ✅ 形状参数变更可撤销，且与音符**同一撤销单元**；
- ⚠️ 协作房间内**只有音符同步**，形状对象仅本地可见（已确认口径，写入文档）；
- ⛔ S0 结束后用户**看不到任何新面板或新工具**——这是地基，验收靠测试与工程文件检查。

### 4.5 部件格式纪律（写进实现注释，避免未来踩坑）

bincode 是位置编码，**给 `ShapeModel` / `ShapeOp` 加字段会让旧文件解码失败**。
规则：任何字段增删必须同时提升 `.lmshapes` 自带 version，并保留旧版本读取路径（或另起部件名），
不得静默改结构——同 `data_formats.rs:112` 已记录的教训。

## 6. 风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 老工程保存后字节被改（golden 测试炸） | 非空才写部件 + 字节比对用例 |
| R2 | 撤销错位：音符回退、形状没回退 | 形状前像按 group_id 回放；专门用例覆盖「改参数→undo→两者同时回退」 |
| R3 | `k`（beats per key）丢失导致形状跨 zoom 走形 | `k` 存进 `ShapeModel`；断言不同 zoom 下重生成结果一致 |
| R4 | 未来给形状加字段破坏旧工程 | §4.5 部件 version 纪律 + 旧版本读取路径 |
| R5 | 协作端不知形状存在 → 行为不一致被当 bug | 文档 + 协作状态提示（S0 只写文档，提示归 T1） |
| R6 | 再生成在 UI 线程卡顿 | S0 无 UI 拖动，先在 `shape_ops` 留脏标记 + 缓存键接口，性能预算在 T1 兑现 |
