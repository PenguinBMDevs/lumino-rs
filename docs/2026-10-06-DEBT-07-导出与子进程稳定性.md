## 背景

导出链路（音/视频、ffmpeg 子进程）存在可重入、永久挂起与管道死锁：
用户二点导出可能丢首次任务；长导出可能因 stderr 堵死；取消可能打不断阻塞 recv。

## 证据（file:line）

| 项 | 位置 | 说明 |
|---|---|---|
| **FfmpegSink stderr 不排空 → 死锁** | `crates/tools/export/src/audio/stream.rs:221-223,241-269`；args 无 `-nostats`（`:199-219`） | 对照 `video/ffmpeg.rs:71-99` 有专门排空线程——同仓两种口径 |
| 导出可重入 | `src/runner/menu/window/audio_export.rs:105-110,179-181`；`video_export_handler.rs:116-122,156-157` | 进度通道/取消标志被覆盖；两线程并发写盘 |
| 视频流水线永久挂起 | `src/runner/menu/window/video_export_handler/memory_task/task.rs:86`；`pipeline.rs:80-89` | 自持发送端使 `recv()` 不 Err；取消只在循环顶检查 |
| GPU 导出忽略限幅/NaN | `crates/tools/export/src/audio/gpu_backend/render.rs:123,219` | 与 CPU 路径口径分叉 |
| 死代码地雷 | `crates/tools/export/src/audio/renderer.rs:106-123`（BatchRenderer/render_tail） | 无界/NaN 死循环（未接线但保留危险） |

## 修复方案

1. 加线程实时排空 stderr（复用视频侧）或 `-nostats -loglevel error`；
2. 导出入口守卫：已有任务则拒绝或先取消；
3. `recv_timeout(100ms)` 循环校验取消；取消时 drop 发送端/发哨兵；
4. GPU 导出接限幅/净化，或显式声明差异并在 UI 标注；
5. 删除或隔离死代码地雷（并入 DEBT-09）。
